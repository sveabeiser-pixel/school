Lehrer-HowTo

Interaktive Lernseiten mit diesem Repo bauen

Diese Seite erklärt, wie du aus einem Thema, einem Arbeitsblatt, einer PDF oder einer Unterrichtsidee eine lauffähige HTML-Lernseite erstellst. Sie ist bewusst als Arbeitsanleitung für Lehrkräfte gestaltet und nicht als Schüler:innen-Material.

Zur Einrichtung README öffnen Musterseite ansehen

Grundidee

Das Repo trennt Inhalt und Technik. Deine einzelne Unterrichtsseite bleibt eine normale, gut lesbare HTML-Datei. Die Navigation, das Layout, die Quiz-Logik, Drag-and-Drop-Aufgaben und die Ergebnissicherung kommen aus dem gemeinsamen Ordner assets/.

1. Inhalt

Du formulierst Lernroute, Erklärungen, Aufgaben und Sicherungen passend zu deiner Lerngruppe.

2. Bausteine

Der KI-Agent setzt daraus HTML-Seiten mit vorhandenen Interaktionsblöcken zusammen.

3. Veröffentlichung

Die Seite läuft lokal, auf GitHub Pages oder als SCORM-Paket in Moodle.

Merksatz: Du musst nicht programmieren lernen. Du musst aber präzise beschreiben, was die Lernenden verstehen, üben und abgeben sollen.

Programme einrichten

Für die Arbeit mit diesem Repo brauchst du nur wenige Programme. Die folgende Einrichtung ist für Lehrkräfte gedacht, die Lernseiten selbst erstellen, mit KI überarbeiten und anschließend veröffentlichen möchten.

Welche Programme und Pakete du brauchst

Programm oder Konto Wofür? Pflicht?

GitHub-Konto erstellen

  1. GitHub öffnen. Gehe auf github.com und klicke auf Sign up.
  2. Konto anlegen. Nutze am besten deine dienstliche Mailadresse oder eine Adresse, die du langfristig für Unterrichtsmaterialien verwenden darfst.
  3. E-Mail bestätigen. GitHub schickt dir einen Bestätigungslink. Ohne Bestätigung kannst du viele Funktionen nicht nutzen.
  4. Repo übernehmen. Öffne das Schul-Webpages-Repo und klicke auf Fork. Dadurch entsteht deine eigene bearbeitbare Kopie.
  5. GitHub Pages aktivieren. Gehe in deinem Fork auf Settings → Pages, wähle den Branch main und speichere. Nach einigen Minuten erhältst du eine öffentliche URL.

Git installieren

  1. Installer herunterladen. Öffne git-scm.com/downloads und lade Git für dein Betriebssystem herunter.
  2. Installation starten. Unter Windows kannst du die vorgeschlagenen Standardoptionen in der Regel übernehmen. Wichtig ist, dass Git später in VS Code verfügbar ist.
  3. Installation prüfen. Öffne in VS Code später ein Terminal und tippe:
Git prüfen 
git --version

Visual Studio Code installieren

  1. VS Code herunterladen. Öffne code.visualstudio.com und lade Visual Studio Code herunter.
  2. Installieren und starten. Melde dich in VS Code mit GitHub an, wenn du danach gefragt wirst. Das vereinfacht später das Klonen und Hochladen.
  3. Projekt klonen. Drücke Ctrl + Shift + P, suche Git: Clone, füge die URL deines Forks ein und wähle einen Speicherort auf deinem Computer.
  4. Ordner öffnen. Öffne den geklonten Projektordner in VS Code. Ab jetzt arbeitet der KI-Agent direkt in diesem Ordner.

Pakete und Erweiterungen in VS Code installieren

Erweiterungen installierst du links über das Symbol Extensions oder mit Ctrl + Shift + X. Suche den Namen, klicke auf Install und lade VS Code bei Bedarf neu.

Erweiterung Empfehlung Warum?
Live Server Installieren. Öffnet HTML-Dateien lokal im Browser und aktualisiert die Vorschau beim Speichern.
KI-Coding-Assistent Eine Lösung auswählen, die deine Schule erlaubt. Zum Beispiel Codex, Claude oder ein anderer Assistent, der Dateien im Projekt lesen und bearbeiten kann.
GitHub Pull Requests and Issues Optional. Hilfreich, wenn mehrere Lehrkräfte gemeinsam an Material arbeiten und Änderungen besprechen.
German Language Pack Optional. Stellt die VS-Code-Oberfläche auf Deutsch um, falls gewünscht.

KI-Assistent verbinden

  1. Erweiterung installieren. Installiere in VS Code den KI-Assistenten, den deine Schule nutzen darf.
  2. Anmelden. Die Erweiterung fordert dich meist auf, dich mit deinem Konto anzumelden oder einen API-Schlüssel zu hinterlegen.
  3. Projektzugriff erlauben. Erlaube dem Assistenten den Zugriff auf den geöffneten Projektordner, damit er HTML-Dateien, Assets und README lesen kann.
  4. Ersten Testauftrag geben. Bitte den Assistenten: „Lies die README.md und erkläre mir kurz, wie dieses Repo aufgebaut ist.“

Datenschutz: Gib keine echten Schüler:innendaten, Notenlisten oder vertraulichen Elterninformationen an einen KI-Assistenten weiter. Nutze neutrale Beispieldaten oder anonymisierte Angaben.

Workflow

  1. Thema und Ziel klären. Schreibe zuerst auf, für welche Klasse, welches Fach, welche Dauer und welches Ergebnis die Seite gedacht ist.
  2. Material bereitstellen. Gib dem Agenten dein Arbeitsblatt, eine PDF, Stichpunkte, Bilder oder Links. Wenn du nichts hast, beauftrage ihn mit Recherche und Quellenliste.
  3. Lernroute verlangen. Eine gute Seite hat Einstieg, Erarbeitung, Sicherung, Anwendung, Transfer und Abschluss.
  4. Interaktionen gezielt einsetzen. Nutze nicht überall ein Quiz. Sinnvoll sind kurze Checks nach Erklärungen und offenere Aufgaben bei Transferstellen.
  5. HTML bauen lassen. Der Agent erstellt oder bearbeitet eine Datei im passenden Fachordner und bindet assets/allgemeines_format.css sowie assets/allgemeines_format.js ein.
  6. Testen und korrigieren. Öffne die Seite im Browser, prüfe Texte, Lösungen, Navigation, Abgabe und Darstellung auf Handybreite.
  7. Veröffentlichen oder exportieren. Stelle die Seite über GitHub Pages bereit oder baue bei Bedarf ein SCORM-ZIP.

Dateien und Ordner

Die wichtigsten Orte im Projekt sind schnell erklärt:

Ort Wofür? Typische Änderung
assets/ Gemeinsames Layout, Interaktionen, Icons und Hilfslogik. Nur ändern, wenn alle Seiten davon profitieren.
medien/, nwt/, felder/, wellen/, quanten/ Fach- und Themenordner für Unterrichtsseiten. Neue HTML-Seiten und dazugehörige Bilder ablegen.
index.html Übersicht über vorhandene Lernseiten. Neue fertige Seiten verlinken.
scripts/build-scorm.ps1 Erstellt ein SCORM-Paket aus einer einzelnen HTML-Datei. Beim Export ausführen, nicht manuell bearbeiten.
README.md Kurze Projektbeschreibung und Einstieg. Grundlegende Hinweise für Mitwirkende ergänzen.

Wichtig: Lege Bilder möglichst im Themenordner ab, also zum Beispiel wellen/pdf-bilder/. Dann bleiben Seiten auch beim Export oder Umzug nachvollziehbar.

Mit dem KI-Agenten arbeiten

Gute Prompts beschreiben nicht nur das Thema, sondern auch Zielgruppe, Niveau, Material, gewünschte Interaktionen und Prüfauftrag. Je genauer du das Unterrichtsziel formulierst, desto weniger musst du später nachkorrigieren.

Prompt: Neue Lernseite aus Material 
Erstelle eine interaktive HTML-Lernseite für [Fach, Klasse/Kursstufe] zum Thema [Thema].
Nutze mein Material als Hauptquelle: [Material/Dateiname/Link].
Die Seite soll eine klare Lernroute haben: Einstieg, Erarbeitung, Sicherung, Anwendung, Transfer, Zusammenfassung und Quellen.
Baue mindestens diese Interaktionen ein: mcq, verify, cloze, categorize, p2, reveal, essay und order.
Sprich die Schüler:innen mit "du" an.
Nutze das vorhandene Book-Layout mit assets/allgemeines_format.css und assets/allgemeines_format.js.
Lege die Datei unter [Ordner/dateiname.html] ab und verlinke sie anschließend in index.html.
Prüfe am Ende HTML, JSON-Konfigurationen, Umlaute, Navigation, mobile Darstellung und fachliche Korrektheit.
Prompt: Vorhandene Seite verbessern 
Überarbeite [Pfad/zur/seite.html].
Ziel: [konkretes Ziel, z. B. fachlich schärfer, kürzer, mehr Transfer, bessere Aufgaben].
Behalte die bestehende Struktur und die vorhandenen Assets bei.
Füge nur Änderungen ein, die den Unterrichtswert verbessern.
Prüfe danach alle Interaktionen, JSON-Blöcke, Links und die Darstellung im Browser.
Gute Aufträge
  • „Erkläre in kleinen Schritten.“
  • „Baue typische Fehlvorstellungen ein.“
  • „Lass Schüler:innen begründen, nicht nur anklicken.“
  • „Nenne Quellen am Ende.“
Aufträge, die du vermeiden solltest
  • „Mach mal eine Seite zu Magnetismus.“
  • „Mach es schöner.“
  • „Füge viele Aufgaben ein.“
  • „Übernimm einfach den ganzen Text.“

Interaktionsblöcke

Die Schüler:innen-Seiten nutzen feste Bausteine. Du musst die Bausteine nicht selbst programmieren, aber du solltest wissen, wofür sie didaktisch sinnvoll sind.

Block Didaktischer Einsatz Typische Prompt-Formulierung
mcq Schnelle Diagnose mit plausiblen Fehlvorstellungen. „Erstelle eine MCQ-Frage mit drei plausiblen Distraktoren und kurzer Erklärung.“
verify Wahr/Falsch-Aussagen prüfen und begründen. „Baue eine Aussage ein, die eine typische Fehlannahme sichtbar macht.“
cloze Begriffe sichern, wenn Definitionen schon erarbeitet wurden. „Erstelle einen Lückentext mit Wortbank zu den Fachbegriffen.“
categorize Begriffe, Beispiele oder Aussagen nach Kategorien ordnen. „Lass Beispiele in zwei Kategorien einsortieren und erkläre die Grenzfälle.“
p2 Paare bilden: Begriff und Definition, Darstellung und Bedeutung, Formel und Einheit. „Erstelle eine Zuordnungsübung mit vier Paaren.“
order Abläufe, Versuchsprotokolle, Lösungswege oder Argumentationen sortieren. „Lass die Schritte eines Versuchs in die richtige Reihenfolge bringen.“
reveal Selbstkontrolle, Auflösung, Denkimpuls oder gestufte Hilfe. „Baue eine einklappbare Erklärung als Hilfe nach der Aufgabe ein.“
essay Begründung, Reflexion, Transfer und Abgabe freier Antworten. „Lass die Lernenden in 5 bis 8 Sätzen begründen und zwei Fachwörter verwenden.“
Minimaler Aufbau einer Schüler:innen-Seite 
<!doctype html>
<html lang="de">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Titel der Lernseite</title>
  <link rel="stylesheet" href="../assets/allgemeines_format.css">
</head>
<body>
  <div data-wb-book>
    <script type="application/json" class="wb-book-config">
    {
      "bookTitle":"Fach",
      "sectionTitle":"Thema",
      "startPage":1,
      "submitLabel":"Ergebnisse anzeigen",
      "onSubmit":"alert",
      "autoNav":true
    }
    </script>

    <section data-wb-page="1" data-wb-page-title="Start">
      <h1>Leitfrage</h1>
      <p>Kurzer Einstieg in das Thema.</p>
    </section>
  </div>

  <script src="../assets/wb-webhook-loader.js"></script>
  <script src="../assets/allgemeines_format.js"></script>
  <script>
    SBBook.autoMount();
    SBBlocks.autoMount();
    SBLibrary.autoMountAll();
  </script>
</body>
</html>

Abgabe und SCORM

Es gibt drei praktische Wege, Ergebnisse einzusammeln.

Download

Einfachste Variante. Lernende laden ihre Ergebnisse herunter und geben sie per Moodle, Mail oder Cloud-Abgabe ab.

Webhook

Für automatisierte Abgaben an Teams, Slack oder eigene Dienste. Dafür brauchst du eine passende Webhook-URL.

SCORM

Geeignet für Moodle und LMS-Systeme, wenn die Seite als Paket importiert werden soll.

SCORM-Paket erstellen 
./scripts/build-scorm.ps1 -InputHtml pfad\zur\seite.html

Prüfe nach dem Export das ZIP in einer Testumgebung. Besonders wichtig sind Bilder, relative Pfade, Videos und eingebundene Simulationen.

Veröffentlichen

Für GitHub Pages reicht meistens dieser Ablauf:

  1. Datei im passenden Ordner erstellen, zum Beispiel wellen/interferenz.html.
  2. Die Seite in index.html verlinken.
  3. Änderungen lokal testen.
  4. Änderungen in Git speichern und zu GitHub hochladen.
  5. Die veröffentlichte URL öffnen und noch einmal prüfen.
Typische Git-Befehle 
git status
git add pfad/zur/seite.html index.html
git commit -m "Neue Lernseite zu [Thema]"
git push

Wenn mehrere Personen gleichzeitig am Repo arbeiten, vor dem Bearbeiten immer die aktuelle Version holen und bei Konflikten nicht blind überschreiben.

Qualitätscheck

Diese Prüfliste eignet sich als letzter Auftrag an den Agenten und als eigene Kontrolle im Browser.

  • Die Leitfrage ist auf der Startseite klar.
  • Die Seite hat eine erkennbare Lernroute.
  • Begriffe werden eingeführt, geübt und angewandt.
  • Jede Interaktion hat eine eindeutige Lösung oder einen klaren Erwartungshorizont.
  • MCQ-Antworten enthalten plausible, aber fachlich falsche Distraktoren.
  • Offene Aufgaben verlangen Begründungen, Transfer oder Vergleich.
  • Alle JSON-Blöcke sind gültig.
  • Alle Bilder laden und haben sinnvolle Alternativtexte.
  • Umlaute werden korrekt angezeigt.
  • Die Seite funktioniert auf Desktop und Handybreite.
  • Die Abgabe oder Ergebnisansicht ist getestet.
  • Quellen und Weiterforschen stehen am Ende.

Vorlagen

Diese kurzen Bausteine kannst du direkt in Agenten-Aufträge übernehmen.

Didaktischer Auftrag

Didaktik-Baustein 
Baue die Seite so, dass Lernende selbstständig arbeiten können.
Jedes Kapitel soll einen kurzen Einstieg, eine Erklärung, eine Sicherung, eine Anwendung und eine Reflexionsfrage enthalten.
Nutze regelmäßig "Jetzt hast du das gelernt:" als Sicherung.
Die Aufgaben sollen nicht nur Fakten abfragen, sondern Begründen, Vergleichen, Fehlerfinden und Transfer verlangen.

Technischer Auftrag

Technik-Baustein 
Nutze die vorhandenen Dateien assets/allgemeines_format.css und assets/allgemeines_format.js.
Verwende das Book-Layout mit data-wb-book und autoNav.
Baue Interaktionen ausschließlich mit den vorhandenen data-wb-type-Blöcken.
Lege nach Absätzen und vor Interaktionen einen <div class="wb-section-break"></div> ein.
Prüfe am Ende im Browser, ob alle Interaktionen ohne JavaScript-Fehler mounten.

Review-Auftrag

Review-Baustein 
Prüfe diese Lernseite kritisch:
1. fachliche Korrektheit,
2. roter Faden,
3. Aufgabenqualität,
4. gültiges HTML und gültiges JSON,
5. funktionierende Navigation,
6. mobile Darstellung,
7. Quellen und Urheberrecht.
Korrigiere gefundene Probleme direkt.
