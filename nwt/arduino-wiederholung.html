Vom Quelltext zur wiederholten Ausführung

Beim Start oder Reset führt der Arduino zuerst setup() genau einmal aus. Danach wird loop() immer wieder von oben nach unten durchlaufen. Vor dem Übertragen prüft der Compiler die Schreibweise und übersetzt den Quelltext; anschließend wird das Programm über den gewählten Port auf das richtige Board geladen.

1. PlanenEingaben, Verarbeitung und Ausgaben festlegen.
2. SchreibenBezeichner, Klammern und Semikola korrekt setzen.
3. KompilierenSyntax prüfen und übersetzen.
4. ÜbertragenBoard und Port auswählen, dann hochladen.
5. TestenWirkung beobachten und Soll-Ist vergleichen.
const int LED = 13; void setup() { pinMode(LED, OUTPUT); } void loop() { digitalWrite(LED, HIGH); delay(500); digitalWrite(LED, LOW); delay(500); }

Werte speichern und Verhalten sichtbar machen

Variablen halten Zustände fest, etwa einen Messwert, eine Punktzahl oder eine Motorgeschwindigkeit. Ein Datentyp legt fest, welche Art von Wert gespeichert werden kann. Funktionen bündeln wiederkehrende Anweisungen unter einem Namen. Die serielle Ausgabe macht innere Zustände sichtbar und ist deshalb ein zentrales Diagnosewerkzeug.

Variable

int wert = 3;

Ein benannter Speicherplatz mit aktuellem Wert.

Funktion

signal(440);

Ein verständlicher Name ruft einen wiederverwendbaren Ablauf auf.

Serieller Monitor

Serial.println(wert);

Der aktuelle Zustand wird zur Beobachtung ausgegeben.

int punkte = 2; void verdoppleUndZeige() { punkte = punkte * 2; Serial.println(punkte); } void setup() { Serial.begin(9600); verdoppleUndZeige(); punkte = punkte + 3; verdoppleUndZeige(); }

Wiederholen, zählen und Helligkeit steuern

Eine for-Schleife passt, wenn die Anzahl der Durchläufe feststeht. Initialisierung, Bedingung und Änderung der Zählvariablen legen gemeinsam fest, welche Werte auftreten. Bei analogWrite() steuert ein PWM-Wert typischerweise das Verhältnis von Ein- und Ausschaltzeit; beim Arduino Uno reichen die Werte von 0 bis 255.

for (int hell = 0; hell <= 255; hell = hell + 85) { analogWrite(3, hell); delay(400); }

Taster lesen und Bedingungen präzise formulieren

Ein digitaler Eingang braucht einen eindeutigen Grundzustand. Mit INPUT_PULLUP nutzt der Arduino einen internen Widerstand: Nicht gedrückt ergibt meist HIGH, gedrückt verbindet den Eingang mit GND und ergibt LOW. Diese umgekehrte Logik muss die Bedingung korrekt berücksichtigen.

const int TASTER = 2; const int LED = 13; void setup() { pinMode(TASTER, INPUT_PULLUP); pinMode(LED, OUTPUT); } void loop() { int zustand = digitalRead(TASTER); if (zustand == LOW) { digitalWrite(LED, HIGH); } else { digitalWrite(LED, LOW); } }

Viele Werte ordnen, kurze Ereignisse bemerken

Ein Array speichert mehrere Werte desselben Typs in einer geordneten Liste. Der erste Platz hat den Index 0. Eine Schleife kann die Einträge nacheinander bearbeiten. Ein Interrupt unterbricht den normalen Ablauf bei einem Ereignis kurz; die Interrupt-Service-Routine, kurz ISR, sollte deshalb nur das Nötigste tun.

int melodie[] = {262, 330, 392, 523}; for (int i = 0; i < 4; i++) { tone(8, melodie[i]); delay(200); } noTone(8);

Polling

loop() fragt einen Eingang wiederholt ab. Übersichtlich, aber kurze Ereignisse können während langer Blockaden verpasst werden.

Interrupt

Ein festgelegtes Signal löst sofort eine ISR aus. Sie setzt meist nur eine Merker-Variable.

volatile

Kennzeichnet einen Wert, der sich außerhalb des normalen Programmflusses durch eine ISR ändern kann.

Die passende Ausgabe für die Aufgabe wählen

Eine LED zeigt einen einfachen Zustand, ein Lautsprecher erzeugt Töne, ein LCD stellt Text oder Messwerte dar. Bei Bewegung entscheidet die Aufgabe über den Motortyp. Ein DC-Motor dreht kontinuierlich, ein Servo fährt Winkelpositionen an, ein Schrittmotor bewegt sich in reproduzierbaren Einzelschritten.

DC-Motor

Geeignet für kontinuierliche Drehung und Drehzahlsteuerung. Richtung und Leistung werden über eine Treiberstufe, etwa eine H-Brücke, gesteuert.

Servomotor

Geeignet für definierte Winkel, Klappen und Hebel. Die Bibliothek erzeugt das benötigte Steuersignal.

Schrittmotor

Geeignet für schrittweise, reproduzierbare Drehbewegungen. Eine Treiberplatine versorgt die Wicklungen in der richtigen Folge.

Jetzt hast du gelernt: Die technische Aufgabe bestimmt den Aktor. Bibliotheken vereinfachen die Ansteuerung, lösen aber weder falsche Verdrahtung noch eine ungeeignete Stromversorgung.

Debugging beginnt bei der ersten Abweichung

Trenne Syntaxfehler, Übertragungsprobleme, Logikfehler und Hardwarefehler. Prüfe zuerst, ob das Programm kompiliert und übertragen wird. Danach testest du die kleinste mögliche Wirkungskette und machst Zustände mit der seriellen Ausgabe sichtbar.

Fehlerlabor: Klicke auf die erste problematische Zeile

Die LED soll leuchten, wenn der Sensorwert größer als 500 ist. Das Programm kompiliert, aber die LED ist unabhängig vom Messwert immer an.

Wähle die erste Zeile, an der das beobachtete Verhalten falsch abbiegt.
Fehlermuster: Das Semikolon direkt hinter der if-Bedingung beendet die bedingte Anweisung. Korrigiere zu if (sensorWert > 500) { ... }. Unterscheide außerdem Zuweisung = und Vergleich ==.

Das Arduino-System als Ganzes beherrschen

Der entscheidende Schritt ist nicht das Erinnern einzelner Befehle. Du musst begründen können, wie ein Signal durch Hardware und Programm läuft, welche Zustände sich ändern und wie du eine Abweichung sichtbar machst.

Hardware: Stromweg, Polung, Widerstand, Versorgung und gemeinsame Masse prüfen.
Struktur: Einmalige Initialisierung von der wiederholten Verarbeitung trennen.
Daten: Variablen, Datentypen, Arrays und Indizes schrittweise verfolgen.
Logik: Randwerte, Bedingungen, Zweige und Schleifenende testen.
Ausgaben: Digital, PWM, Ton, Display und Motor passend zur Aufgabe wählen.
Diagnose: Die erste Abweichung mit kleinen Tests und serieller Ausgabe finden.
