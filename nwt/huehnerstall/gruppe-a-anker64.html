Musterprojekt: beide Sensoren und lokales HTTP

Verdrahtung: KY-015 S→GPIO4, +→3V3, −→GND; KY-018 analoger Mittelabgriff→GPIO34/ADC1, Versorgung und Schaltung nach der tatsächlichen Modulbeschriftung, gemeinsame GND-Verbindung. Beide Signalpegel bleiben innerhalb der 3,3-V-Grenzen. Adafruit-DHT-Bibliothek erforderlich. Das folgende Kernprogramm liest alle 2 s, mittelt 16 LDR-Werte und stellt lokale Messdaten unter /api bereit.

#include <WiFi.h>
#include <WebServer.h>
#include <DHT.h>
#include <math.h>

// Beispielkonfiguration; im Schulnetz gelten die freigegebenen Zugangsdaten.
const char* ssid = "Schul-Labornetz";
const char* password = "BeispielzugangNurLokal";
constexpr int LDRPIN = 34;
DHT dht(4, DHT11);
WebServer server(80);
float temperatur = NAN, feuchte = NAN;
int licht = 0;
bool gueltig = false, gemessen = false, wlanWarVerbunden = false;
unsigned long letzteMessung = 0, letzterVersuch = 0;

String datensatz() {
  String s = "{\"temp\":";
  s += gueltig ? String(temperatur, 1) : "null";
  s += ",\"humidity\":";
  s += gueltig ? String(feuchte, 1) : "null";
  s += ",\"light_raw\":";
  s += gemessen ? String(licht) : "null";
  s += ",\"sample_uptime_ms\":";
  s += gemessen ? String(letzteMessung) : "null";
  s += ",\"age_ms\":";
  s += gemessen ? String(millis() - letzteMessung) : "null";
  s += ",\"interval_ms\":2000,\"status\":\"";
  s += !gemessen ? "pending" : (gueltig ? "ok" : "dht_error");
  s += "\"}";
  return s;
}

void setup() {
  Serial.begin(115200);
  dht.begin();
  analogReadResolution(12);
  pinMode(LDRPIN, INPUT);
  WiFi.mode(WIFI_STA);
  WiFi.begin(ssid, password);
  server.on("/", []() {
    server.send(200, "text/html; charset=utf-8",
      "<!doctype html><html lang='de'><meta charset='utf-8'>"
      "<title>Stallmessung</title><h1>Stallmessung</h1>"
      "<p>Temperatur in C, Feuchte in %RH, Licht als ADC-Rohwert.</p>"
      "<a href='/api'>Aktueller Datensatz</a></html>");
  });
  server.on("/api", []() {
    server.sendHeader("Cache-Control", "no-store");
    server.send(200, "application/json", datensatz());
  });
  server.begin();
}

void loop() {
  unsigned long jetzt = millis();
  if (jetzt - letzteMessung >= 2000) {
    temperatur = dht.readTemperature();
    feuchte = dht.readHumidity();
    gueltig = !isnan(temperatur) && !isnan(feuchte);
    long summe = 0;
    for (int i = 0; i < 16; ++i) summe += analogRead(LDRPIN);
    licht = summe / 16;
    letzteMessung = millis();
    gemessen = true;
    Serial.println(datensatz());
  }
  if (WiFi.status() != WL_CONNECTED && jetzt - letzterVersuch >= 10000) {
    letzterVersuch = jetzt;
    WiFi.reconnect();
  }
  bool wlanVerbunden = WiFi.status() == WL_CONNECTED;
  if (wlanVerbunden && !wlanWarVerbunden) {
    Serial.print("HTTP-Adresse: http://");
    Serial.println(WiFi.localIP());
  }
  wlanWarVerbunden = wlanVerbunden;
  if (wlanVerbunden) server.handleClient();
}

Die WLAN-Werte sind eine gekennzeichnete Beispielkonfiguration. sample_uptime_ms ist Laufzeit seit Reset, kein Kalenderdatum; age_ms zeigt das Messalter. Die Anzeige wartet nach dem Start auf den ersten Datensatz. Die Richtung der Lichtänderung und die Kategoriegrenzen werden am konkreten Spannungsteiler bestimmt.

Nachweise für die Übergabe

Sicherung: Fachbegriffe einsetzen

Der ADC wandelt eine elektrische Spannung in einen digitalen Rohwert um. Für die Übertragung nutzt der ESP32 WLAN.

Technische Notiz an Gruppe B

Eine mögliche Antwort

Schnittstelle: lokales HTTP, GET /api am im seriellen Monitor dokumentierten ESP32-Host; Beispieladresse 192.168.1.50. Datenformat: temp in °C, humidity in %RH, light_raw als 12-Bit-Rohwert; Intervall 2000 ms; Messzeit als Laufzeit plus age_ms. Bei DHT-Lesefehler sind Temperatur und Feuchte null und status=dht_error. Bekannte Grenzen: DHT-Genauigkeit nach Datenblatt, LDR ohne Lux-Kalibrierung und mögliche ADC-Sättigung. Letzter Meilenstein des Musters ist eine gültige HTTP-200-Antwort mit aktuellem Datensatz; im echten Protokoll steht die tatsächlich getestete IP. Als Fehlerfall testen wir gelöste Signalleitung und kurz getrenntes WLAN; ein Fehler darf niemals durch erfundene Nullwerte verdeckt werden.

Beispiel für Mess- und Fehlersuchnachweis: Fiktive Rohwerte 1420/1430/1440 ergeben Mittelwert 1430. Bei dht_error werden vor dem nächsten Test Versorgung, Masse, GPIO4 und DHTPIN geprüft. Ein Screenshot oder Log muss Datum und tatsächliche Ausgabe des eigenen Tests enthalten; die Musterlösung ersetzt keinen Messnachweis.
