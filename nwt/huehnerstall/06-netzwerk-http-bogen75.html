6. WLAN, IP-Adresse und HTTP

HTTP-Ablauf ordnen

  1. Browser sendet Anfrage an IP-Adresse
  2. ESP32 empfängt und verarbeitet die Anfrage
  3. ESP32 sendet eine Antwort
  4. Browser zeigt die Webseite an

Diagnose einer nicht erreichbaren Webseite

Zuerst zeigt der serielle Startlog, dass der ESP32 läuft. Dann muss WiFi.status() == WL_CONNECTED gelten und WiFi.localIP() die aktuelle Adresse liefern. Im freigegebenen LAN wird genau diese Adresse angefragt, etwa http://192.168.1.50/api; die Adresse ist ein Beispiel. Eine HTTP-404-Antwort beweist Erreichbarkeit des Servers, weist aber auf eine falsche Route hin. Eine Zeitüberschreitung führt zurück zu Adresse, WLAN, Client-Isolation oder Serverlauf. Erst nach erfolgreichem HTTP-200-Test werden JSON und Darstellung geprüft. Ein erfolgloser Ping allein beweist keinen ausgefallenen HTTP-Server, da ICMP blockiert sein kann.
