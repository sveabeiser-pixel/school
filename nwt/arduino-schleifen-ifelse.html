Vom Ablaufplan zum ersten Programmcode

Wo steckt dein Programm gerade: in der Bedingung, im Zweig oder in der Schleife?

In dieser Lernstrecke verfolgst du Programme Schritt für Schritt. Du liest Flussdiagramme, Pseudocode und immer häufiger echte Programmier-Schreibweisen wie if(Bedingung){Aktion}else{Aktion} und while(Bedingung){Aktion}.

Bedingung prüfenDu entscheidest, ob eine Aussage gerade wahr oder falsch ist.
Zweig auswählenDu begründest, ob der if-Block oder der else-Block läuft.
Schleife verfolgenDu notierst Durchlauf, Zustand und Rücksprung zur nächsten Prüfung.

Bekannte Abläufe bekommen neue Namen

Im Einstieg hast du Verzweigungen als WENN-DANN-SONST und Schleifen als WIEDERHOLE oder SOLANGE geschrieben. Die Idee bleibt jetzt genau gleich. Neu sind nur die englischen Schlüsselwörter, Klammern und geschweiften Blöcke der Programmiersprache.

Aus WENN-DANN-SONST wird if/else

if bedeutet WENN. Der erste Block enthält das frühere DANN. else bedeutet SONST.

WENN Taste gedrückt ist DANN schalte LED an SONST schalte LED aus ENDE WENN
if(tasteGedrueckt == true){ ledAn(); }else{ ledAus(); }

Aus WIEDERHOLE, SOLANGE wird while

while bedeutet SOLANGE. Der Block wird wiederholt, solange die Bedingung in den runden Klammern wahr ist.

Bedingungen müssen eindeutig prüfbar sein

Arduino-Programme arbeiten mit Messwerten, Tasterzuständen und gespeicherten Variablen. Damit eine Verzweigung zuverlässig läuft, muss die Bedingung eindeutig wahr oder falsch werden können.

while: prüfen, ausführen, zurückspringen

Eine Schleife braucht eine Veränderung

Eine while-Schleife endet nur, wenn sich ein Zustand so verändert, dass die Bedingung irgendwann falsch wird. Fehlt diese Veränderung, bleibt das Programm in der Schleife stecken.

abstand = 20; while(abstand > 10){ piep(); // Fehler: abstand wird hier nicht neu gemessen } motorStopp();
Debugging-Frage: Welche Anweisung müsste im Schleifenrumpf stehen, damit die Bedingung später falsch werden kann?

while und if/else arbeiten oft zusammen

In Arduino-Projekten wird häufig wiederholt gemessen. Innerhalb jedes Durchlaufs entscheidet eine Verzweigung, welche Aktion ausgeführt wird. Genau dann musst du zwei Fragen trennen: Bleibe ich noch in der Schleife? Und welcher Zweig läuft in diesem Durchlauf?

zeit = 0; while(zeit < 4){ helligkeit = messung[zeit]; if(helligkeit < 400){ led = AN; }else{ led = AUS; } zeit = zeit + 1; } summer = AUS;

Für die vier Messungen gelten diese Werte: messung[0] = 320, messung[1] = 500, messung[2] = 390, messung[3] = 410.

Transfer: Einen Arduino-Ablauf selbst erklären

Jetzt formulierst du selbst. Wichtig ist nicht, dass dein Code perfekt wie in der Arduino-IDE aussieht. Wichtig ist, dass du Bedingungen, Blöcke und Rücksprünge sauber erklärst.

while(temperatur < 30){ temperatur = liesSensor(); if(temperatur >= 26){ luefter = AN; }else{ luefter = AUS; } } alarm = AN;
Impuls: Die Schleife endet erst, wenn die gemessene Temperatur nicht mehr kleiner als 30 ist. Der Lüfter kann aber schon vorher je nach Messwert an oder aus gehen.

Werkzeugkasten für Schleifen und Verzweigungen

Du kannst jetzt einen Ablauf nicht nur lesen, sondern mit Zuständen belegen. Genau das brauchst du später beim echten Arduino-Code: Werte messen, Bedingungen prüfen, Blöcke unterscheiden und Schleifen sicher verlassen.

Debugging-Routine

  • Notiere die Startwerte vor der ersten Bedingung.
  • Prüfe jede Bedingung ausdrücklich als wahr oder falsch.
  • Markiere, ob du im if-Block, else-Block oder while-Block bist.
  • Ändere nach jeder Aktion nur die Werte, die wirklich betroffen sind.
  • Springe bei while nach dem Rumpf zur Bedingung zurück.
  • Prüfe Grenzwerte wie 400, 28, 30 oder 0 besonders genau.
Jetzt hast du das gelernt: Du kannst Bedingungen auswerten, Zweige unterscheiden, Schleifendurchläufe zählen und erklären, warum ein Programm hinter der Schleife weiterläuft oder in ihr stecken bleibt.
