Tonaufbau an D11

Für die Tonaufgaben gilt nach Prüfung des konkreten Bauteils: D11 → 330-Ω-Serienwiderstand → kleiner passiver Lautsprecher oder passiver Piezo; zweiter Anschluss → GND. Bei gepoltem Piezo liegt + auf der Pinseite. Ein 1-kΩ-Widerstand kann für leisere Ausgabe verwendet werden. Eine unbekannte Last wird nicht direkt an den Pin angeschlossen; ein aktiver Summer eignet sich nicht für gezielt veränderliche Tonhöhen. Alle folgenden Frequenz- und Zeitangaben setzen diesen geprüften Tonaufbau voraus.

6.1 Variablenwerte und Tonausgabe

Die globalen Variablen sind vor setup() mit 0 initialisiert. Nach a = 10 gilt (a,n,m) = (10,0,0); nach n = 100 − 8: (10,92,0); nach m = 2*a + 15 − 3: (10,92,32); nach a = 200 + 20: (220,92,32). Die spätere Änderung von a berechnet m nicht neu.

Jeder loop()-Durchlauf erzeugt einen Ton mit 220 Hz für 92 ms und anschließend 32 ms Pause. Die reine Wartezeit beträgt 124 ms. Wird n auf 184 verdoppelt, verlängert sich nur die Tonphase; Frequenz und 32-ms-Pause bleiben gleich. Die reine Periodendauer wird 216 ms und verdoppelt sich daher nicht. Die korrigierte Vorlage verwendet noTone(11).

6.2 Notenlängen mit Variablen

int a = 125;
int v = 250;
int h = 500;
void note(int f, int dauer) {
  tone(11, f);
  delay(dauer);
  noTone(11);
  delay(30);
}
void setup() {}
void loop() {
  note(262, v); note(262, v);
  note(294, v); note(330, v);
  note(330, v); note(294, v);
  note(262, h);
  note(330, a); note(349, a); note(392, h);
  delay(1000);
}

Eine mögliche Tonfolge an D11. Mit a = 250, v = 500 und h = 1000 dauern die Noten doppelt so lange; ihre Verhältnisse und die Frequenzen bleiben gleich. Weil die 30-ms-Trennpausen und die 1000-ms-Schlusspause unverändert sind, verdoppelt sich die gesamte Stückdauer nicht exakt. Für eine insgesamt halbierte Geschwindigkeit müssen auch diese Pausen verdoppelt werden. Beim Ersatzbeispiel sind die Tonphasen 125, 250 und 500 ms lang und werden zu 250, 500 und 1000 ms.

6.3 Steigende Frequenz

Die ersten fünf Frequenzen sind 100, 101, 102, 103 und 104 Hz. Nach jeweils 100 ms erhöht f = f + 1 die Frequenz für den nächsten Durchlauf. Weil noTone(11) fehlt, erklingt ein durchgehender, schrittweise ansteigender Ton. Das ist eine erwartete Beobachtung; ein individueller Hörbericht kann abweichen. Für dauerhaften Betrieb begrenze ich nach der Erhöhung:

int f = 100;
void setup() {}
void loop() {
  tone(11, f);
  delay(100);
  f = f + 1;
  if (f > 1000) { f = 100; }
}

So bleiben Frequenzen und int-Werte im vorgegebenen Bereich.

Sicherung: for-Schleife

In einer for-Schleife legt der Startwert fest, wo gezählt wird. Die Bedingung entscheidet vor jedem Durchgang, ob der Block ausgeführt wird. Der Schritt verändert danach die Zählvariable.

Verständnisfragen – for-Schleifen

Eine mögliche Antwort
  1. Eine for-Schleife fasst einen wiederkehrenden Ablauf zusammen. Änderungen müssen nur im Schleifenrumpf vorgenommen werden, statt in fünf Kopien.
  2. i ist die Zählvariable. Sie wird initialisiert, in der Bedingung geprüft und nach jedem Durchlauf verändert; sie kann auch Werte für den jeweiligen Durchlauf liefern.
  3. Bei i = 0; i < 3; i++ läuft der Rumpf dreimal, für i = 0, 1 und 2. Bei i = 3 ist die Bedingung falsch.

8.1 Schleifengrenzen verändern

  • n = 0; n < 30; n++: 30 Durchläufe, n = 0 bis 29.
  • Startwert 5 bei Grenze 30: 25 Durchläufe, n = 5 bis 29.
  • Startwert 5 bei Grenze 50: 45 Durchläufe, n = 5 bis 49.
  • Startwert 5, Grenze 50 und n = n + 3: 15 Durchläufe, n = 5, 8, 11, …, 47.

Bei jedem Durchlauf werden Hallo und der aktuelle Zähler auf getrennten Zeilen ausgegeben. Die Grenze selbst gehört bei < nicht dazu. In der letzten Variante folgt nach 47 bereits 50; deshalb ist 47 der letzte ausgegebene Wert. Die Folge startet nur bei Reset erneut, weil sie in setup() steht.

8.2 Tonfolge einer for-Schleife

Die Frequenzen sind 100, 103, 106, …, 1000 Hz, mit Schrittweite 3 Hz. Das sind (1000 − 100) / 3 + 1 = 301 Durchläufe. Die Wartezeiten ergeben insgesamt 301 · 60 ms = 18,06 s; Befehlslaufzeiten kommen hinzu. Ohne noTone(11) bleibt der letzte Ton nach der Schleife eingeschaltet, auch bei leerem loop(). Wird noTone(11) unmittelbar nach der Schleife in setup() ergänzt, verstummt der Ton nach den 301 Stufen.

8.3 Auf- und abschwellende Sirene

void setup() {}
void loop() {
  for (int f = 100; f <= 1000; f += 3) {
    tone(11, f);
    delay(5);
  }
  for (int f = 1000; f >= 100; f -= 3) {
    tone(11, f);
    delay(5);
  }
}

Die erste Schleife erhöht, die zweite senkt die Tonhöhe. Ein Auf-und-Ab-Zyklus hat 602 Stufen und 3,01 s reine Wartezeit. Mit 10 statt 5 ms werden daraus 6,02 s; die Grenzen 100 und 1000 Hz bleiben gleich. Beide Endwerte werden an den Übergängen jeweils zweimal ausgegeben. Der Ton bleibt zwischen den Stufen eingeschaltet.

8.4 Lauflicht

void setup() {
  for (int pin = 9; pin <= 13; pin++) {
    pinMode(pin, OUTPUT);
  }
}
void loop() {
  for (int pin = 9; pin <= 13; pin++) {
    digitalWrite(pin, HIGH);
    delay(200);
    digitalWrite(pin, LOW);
  }
}

Für jeden Pin D9 bis D13: Pin → eigener 330-Ω-Widerstand → LED-Anode, LED-Kathode → gemeinsame, mit GND verbundene Schiene. Der Tonaufbau ist entfernt. Jeweils eine externe LED leuchtet für etwa 200 ms, danach die nächste. LED L kann bei Pin 13 mit leuchten. Für die Gegenrichtung wird ausschließlich der Kopf der Schleife in loop() zu for (int pin = 13; pin >= 9; pin--) geändert; der Rumpf bleibt gleich. Die Reihenfolge ist dann 13, 12, 11, 10, 9.

Fünfmal blinken und Reset

LED L blinkt nach Upload beziehungsweise Reset genau fünfmal: i = 0, 1, 2, 3, 4. Danach ist sie aus. Die reine Wartezeit ist 5 · (300 + 300) ms = 3 s. Steht dieselbe Schleife in loop(), werden Fünfergruppen dauerhaft wiederholt.

9. LEDs dimmen – Helligkeit in feinen Stufen steuern

Wahr oder falsch?

Falsch. analogWrite(3, 127) erzeugt beim Arduino Uno eine echte, dauerhaft halbe Spannung am Pin.

Falsch. Beim Uno R3 schaltet PWM zwischen LOW und HIGH. 127 bedeutet ungefähr halbe Einschaltdauer; daraus folgt keine konstante halbe Spannung und auch nicht zwingend subjektiv halbe Helligkeit.

Verständnisfragen – LEDs dimmen

Eine mögliche Antwort
  1. Digitales Schalten setzt einen Ausgang auf HIGH oder LOW. Beim Dimmen verändert PWM den zeitlichen Anteil der HIGH-Phasen, sodass sich die mittlere Helligkeit der LED ändert.
  2. Der zweite Wert von analogWrite(pin, wert) bestimmt beim Uno das Tastverhältnis mit Werten von 0 bis 255: 0 ist aus, 255 dauerhaft an, 128 ungefähr die Hälfte der Zeit an.
  3. Die Schaltfolge ist schnell, sodass ihre Einzelphasen unter üblichen Beobachtungsbedingungen verschmelzen. Ein größeres Tastverhältnis liefert der LED im Mittel mehr Strom und lässt sie heller erscheinen.

9.1 Drei Helligkeitszustände

Die LED an Pin 3 ist eine Sekunde voll an, eine Sekunde aus und eine Sekunde per PWM gedimmt. Danach beginnt die Folge erneut. analogWrite(3, 127) entspricht ungefähr 49,8 % Tastverhältnis, nicht einer konstanten halben Ausgangsspannung. In der Skizze ist LOW eine dauerhaft niedrige und HIGH eine dauerhaft hohe Linie. Bei PWM 64 sind etwa 25 %, bei 128 etwa 50 % jeder Periode HIGH, der Rest LOW. Bei 255 bleibt der Ausgang HIGH. Die HIGH-Pegel sind jeweils gleich hoch; verändert wird die Pulsbreite.

9.2 Sanftes Auf- und Abblenden

void setup() { pinMode(3, OUTPUT); }
void loop() {
  for (int hell = 0; hell <= 255; hell++) {
    analogWrite(3, hell);
    delay(10);
  }
  for (int hell = 255; hell >= 0; hell--) {
    analogWrite(3, hell);
    delay(10);
  }
}

Die LED wird heller und wieder dunkler. Die Wartezeiten eines gesamten Zyklus betragen 512 · 10 ms = 5,12 s. Werden beide Pausen auf 20 ms gesetzt, verdoppelt sich die reine Wartezeit auf 10,24 s; die Helligkeitsgrenzen bleiben gleich. Die Extremwerte werden jeweils zweimal ausgegeben.

9.3 Wahrgenommene halbe Helligkeit

Für die wahrgenommene halbe Helligkeit gibt es keinen universellen PWM-Wert. 128 bedeutet etwa halbe Einschaltdauer, nicht zwangsläufig halbe subjektive Helligkeit. Der eigene Vergleichswert muss mit derselben LED, demselben Widerstand, gleichen Lichtbedingungen und gleichem Blickwinkel gegenüber 255 bestimmt werden. Typischerweise erscheint die Einstellung 128 noch heller als subjektiv halb hell; das ist eine qualitative Erwartung, kein vorgegebener Messwert. Unterschiede zwischen Personen sind zulässig. Ein vollständiges Protokoll enthält den wirklich erprobten Wert und die tatsächlichen Bedingungen.

9.4 Flackernde Kerze

void setup() {
  pinMode(3, OUTPUT);
  Serial.begin(9600);
  randomSeed(analogRead(A1));
}
void loop() {
  int s = random(40, 220);
  Serial.println(s);
  analogWrite(3, s);
  delay(random(30, 150));
}

Die ursprüngliche Zahlenwahl random(1,7) liefert 1 bis 6. Im Kerzencode werden PWM-Werte 40 bis 219 und Pausen von 30 bis 149 ms verwendet. Die Obergrenzen sind ausgeschlossen. Gegenüber gleichmäßigem Blinken ändern sich Helligkeit und Haltedauer unregelmäßig; beide Variationen vermeiden einen festen Rhythmus. A1 bleibt unbeschaltet. Der Startwert kann variieren, ist aber kein Garant für unabhängige Zufallswerte.

Mini-Challenge – Helligkeit steuern

Bei gleicher LED, gleichem Aufbau und PWM-Werten im Bereich 0 bis 255 bedeutet ein größerer Wert im Allgemeinen einen größeren mittleren Strom und mehr Licht. hell = 0 schaltet aus, 255 dauerhaft ein. 50 ist eine geringe Einschaltdauer; eine Verdopplung des Zahlenwerts verdoppelt nicht zwingend den subjektiven Helligkeitseindruck.

10. RGB-LEDs – Farben mischen mit Licht

Verständnisfragen – RGB-LEDs

Eine mögliche Antwort
  1. Eine RGB-LED enthält drei getrennt steuerbare Farbanteile: Rot, Grün und Blau. Dafür werden drei Steueranschlüsse und ein gemeinsamer Anschluss benötigt; je Farbzweig gehört ein Vorwiderstand dazu.
  2. Gelb entsteht durch additive Mischung von rotem und grünem Licht. Blau bleibt dabei aus.
  3. analogWrite() verändert auf PWM-Pins die Helligkeit jedes Farbanteils. Bei einer gemeinsamen Anode muss die Ansteuerlogik gegenüber einer gemeinsamen Kathode passend invertiert werden.

9.5 RGB-Farbmischungen

Beim hier verwendeten Kathoden-Aufbau gilt: D3 → 330 Ω → Rot, D5 → 330 Ω → Grün, D6 → 330 Ω → Blau und gemeinsame Kathode → GND. Die genaue Beinbelegung wird aus dem Datenblatt des konkreten Bauteils entnommen; sie lässt sich nicht universell aus der Beinlänge ableiten. Die Einzeltests (255,0,0), (0,255,0), (0,0,255) sollen entsprechend Rot, Grün und Blau ergeben.

Erwartete Mischfarben: (255,255,0) Gelb, (255,0,255) Magenta, (0,255,255) Cyan, (255,255,255) näherungsweise Weiß. Reales Weiß erfordert gegebenenfalls einen Abgleich unterschiedlich heller Farbzweige. Ein gemeinsamer Widerstand würde den Gesamtstrom begrenzen und die Farbströme gegenseitig beeinflussen; deshalb hat jeder Zweig einen eigenen. Bei gemeinsamer Anode kommt der gemeinsame Anschluss an 5 V und jeder PWM-Wert wird zu 255 − farbwert invertiert.

  pinMode(6, OUTPUT);
}
void loop() {
  for (int r = 0; r <= 255; r++) {
    for (int g = 0; g <= 255; g++) {
      for (int b = 0; b <= 255; b++) {
        analogWrite(3, r);
        analogWrite(5, g);
        analogWrite(6, b);
        delay(1);
      }
    }
  }
}

Die innere Schleife verändert Blau am schnellsten; bei jeder neuen Grünstufe beginnt Blau wieder bei 0. Für den Kurztest werden in allen drei Schleifenköpfen r++, g++, b++ durch r += 85, g += 85, b += 85 ersetzt und delay(1) durch delay(100). Die Kanalwerte sind dann jeweils 0, 85, 170, 255: 4³ = 64 Kombinationen mit 64 · 100 ms = 6,4 s reiner Wartezeit.

Die vollständige Fassung erzeugt 256³ = 16.777.216 PWM-Einstellungen. Allein die Pausen betragen 16.777.216 ms = 16.777,216 s, ungefähr 4,66 Stunden; die Befehlsausführung kommt hinzu. Unterschiedliche elektrische Einstellungen müssen keine für das Auge unterscheidbaren Farben ergeben; außerdem begrenzen die LED-Farbanteile den darstellbaren Farbbereich.

Mini-Challenge – Farbe einstellen

r = 255, g = 0, b = 0 ergibt beim Kathoden-Aufbau Rot. r = 200, g = 0, b = 200 mischt Rot und Blau, idealisiert Magenta. Für einen eher violetten Farbeindruck kann beispielsweise ein kleinerer Rotanteil gegenüber Blau erprobt werden. Der genaue Eindruck hängt von der konkreten LED ab; ein universell richtiger Violettwert wird deshalb nicht vorgegeben.

Verständnisfragen – if / else

Eine mögliche Antwort
  1. Bedingungen erlauben ein Verhalten abhängig von Messwerten oder Zuständen, zum Beispiel Licht einschalten, wenn es dunkel ist.
  2. Ist die if-Bedingung falsch, wird der if-Rumpf übersprungen. Gibt es einen else-Zweig, wird dieser ausgeführt; danach geht es hinter der Entscheidung weiter.
  3. = ist eine Zuweisung, zum Beispiel x = 5. == ist ein Vergleich, zum Beispiel x == 5, der wahr oder falsch ergibt.

10.1 Schere, Stein oder Papier

void setup() {
  Serial.begin(9600);
  randomSeed(analogRead(A1));
  int wahl = random(1, 4);
  if (wahl == 1) Serial.println("Schere");
  else if (wahl == 2) Serial.println("Stein");
  else Serial.println("Papier");
}
void loop() {}

A1 bleibt unbeschaltet. Bei jedem Reset erscheint einmal eines der drei Wörter; random(1,4) liefert 1, 2 oder 3. Es ist keine bestimmte Reihenfolge und kein Wechsel bei jedem Reset vorgeschrieben. Ein unbeschalteter Analogeingang garantiert keinen neuen Startwert. Für reproduzierbare Zweigtests wird int wahl = random(1,4) nacheinander durch int wahl = 1, = 2 und = 3 ersetzt; erwartet werden Schere, Stein und Papier.

10.2 Helligkeitswechsel nach Zählschritten

Bei i = 1 und 99999 gilt PWM 100, bei i = 100000 PWM 255. Die ersten 99.999 Durchläufe sind gedimmt. i zählt Durchläufe, keine Millisekunden; ohne delay() hängt die Dauer von Board und Befehlslaufzeiten ab. Die vollständige Kurztestfassung hält den Zähler an der Grenze an:

long i = 1;
void setup() { pinMode(9, OUTPUT); }
void loop() {
  if (i < 10) {
    analogWrite(9, 100);
  } else {
    analogWrite(9, 255);
  }
  if (i < 10) { i = i + 1; }
  delay(500);
}

Die Werte 1 bis 9 ergeben neun gedimmte Durchläufe mit 9 · 500 ms = 4,5 s reiner Wartezeit. Beim nächsten Durchlauf wird der Ausgang dauerhaft voll eingeschaltet. i bleibt bei 10 und kann daher später nicht überlaufen. Aufbau: D9 → 330 Ω → Anode, Kathode → GND.

Zusatzaufgabe – Ampelschaltung

int zeit = 2000;
void farbe(int r, int g, int b) {
  analogWrite(3, r);
  analogWrite(5, g);
  analogWrite(6, b);
  delay(zeit);
}
void setup() {
  pinMode(3, OUTPUT);
  pinMode(5, OUTPUT);
  pinMode(6, OUTPUT);
}
void loop() {
  farbe(255, 0, 0);
  farbe(255, 255, 0);
  farbe(0, 255, 0);
  farbe(255, 255, 0);
}

Am Kathoden-Aufbau mit D3/D5/D6 und je 330 Ω ist die erwartete Folge Rot, Gelb, Grün, Gelb und wieder Rot. Jede Phase dauert ungefähr zwei Sekunden, ein Zyklus etwa acht Sekunden. Beim Übergang Gelb → Grün wird Rot ausdrücklich auf 0 gesetzt; sonst könnte Gelb stehen bleiben. Das ist eine vereinfachte Übungsfolge, nicht die vollständige deutsche Fahrzeugampel mit Rot-Gelb vor Grün.

Zusatzaufgabe – Eigenes Projekt

Eine mögliche Antwort: Ich plane eine Statusleuchte mit dem geprüften Kathoden-Aufbau, D3 für Rot, D5 für Grün, D6 für Blau und je 330 Ω. Sie blinkt zunächst zweimal grün und meldet die dritte Runde rot. Die Rundenzahl ist eine Variable; for begrenzt die Wiederholung und if wählt die Farbe.

int runden = 3;
void setup() {
  pinMode(3, OUTPUT);
  pinMode(5, OUTPUT);
  pinMode(6, OUTPUT);
  Serial.begin(9600);
}
void loop() {
  for (int i = 1; i <= runden; i++) {
    Serial.println(i);
    if (i < runden) {
      analogWrite(3, 0);
      analogWrite(5, 128);
    } else {
      analogWrite(3, 128);
      analogWrite(5, 0);
    }
    analogWrite(6, 0);
    delay(500);
    analogWrite(3, 0);
    analogWrite(5, 0);
    delay(500);
  }
  delay(1500);
}

Testfall 1 mit runden = 3: erwartet werden Grün, Grün, Rot und die seriellen Werte 1, 2, 3. Testfall 2 mit runden = 1: erwartet wird sofort ein roter Blinkimpuls und die Ausgabe 1. Eigene tatsächliche Beobachtungen müssen nach dem Hardwaretest ergänzt werden; diese Erwartungen sind keine gemessenen Ergebnisse. Alle Farbkanäle werden bewusst gesetzt, damit kein vorheriger Anteil eingeschaltet bleibt.

Weiterforschen: Während delay() läuft, erreicht der normale Programmablauf keine neue Tasterabfrage. Eine Vermutung für den Umbau ist daher, Zeitpunkte mit millis() zu vergleichen und die Abfrage bei jedem loop()-Durchlauf auszuführen.
