6.1 Variablenwerte und Tonausgabe

Nach setup(): a = 220, n = 92, m = 32. Bei der Berechnung von m gilt noch a = 10; die spätere Änderung von a verändert m nicht rückwirkend. Die Schleife erzeugt jeweils 92 ms lang einen Ton mit 220 Hz, anschließend folgen 32 ms Pause. Die im Bild gezeigte Zeile noTone() muss noTone(11) heißen.

6.2 Notenlängen mit Variablen

const int a = 125; // Achtelnote
const int v = 250; // Viertelnote
const int h = 500; // Halbe Note

void note(int f, int dauer) {
  tone(11, f);
  delay(dauer);
  noTone(11);
  delay(30);
}
void setup() {}
void loop() {
  note(262, v); note(262, v);
  note(294, v); note(330, v);
  note(330, v); note(294, v);
  note(262, h);
  note(330, a); note(349, a); note(392, h);
  delay(1000);
}

Eine mögliche Tonfolge. Durch Ändern der drei Längenvariablen ändert sich das Tempo, während das Verhältnis der Notenlängen erhalten bleibt.

6.3 Steigende Frequenz

f beginnt bei 100. Die ausgegebenen Frequenzen sind 100, 101, 102, … Hz. Nach jeweils 100 ms wird f um 1 erhöht; der Ton steigt also schrittweise an. Das Programm läuft nicht unbegrenzt mit immer höheren gültigen Frequenzen: Ein int auf dem üblichen Uno hat nur einen begrenzten Wertebereich. Eine robuste Variante setzt f bei einer oberen Grenze wieder auf 100.

7. Serielle Ausgabe – Mit dem Arduino kommunizieren

Verständnisfragen – Serielle Ausgabe

Eine mögliche Antwort
  1. Mit der seriellen Ausgabe sehe ich Werte und erreichte Programmschritte. So kann ich prüfen, ob die Berechnung oder die Entscheidung zum erwarteten Ergebnis führt.
  2. Ohne Serial.begin() wird die serielle Schnittstelle beim üblichen Arduino Uno nicht passend initialisiert; die erwartete Ausgabe funktioniert dann nicht zuverlässig.
  3. Ich kann eine Variable bei jedem Durchlauf ausgeben und ihre Änderungen verfolgen, auch wenn diese an der LED nicht sichtbar sind.
  4. Sender und Empfänger müssen dieselbe Übertragungsgeschwindigkeit benutzen. Andernfalls werden Zeichen falsch interpretiert oder unlesbar ausgegeben.

7.1 Ausgabe im seriellen Monitor

Die ersten beiden Zeilen kommen einmal aus setup(). Die Zeile nicht wird in loop() immer wieder ausgegeben. Der Monitor muss auf dieselbe Baudrate eingestellt sein wie Serial.begin(9600).

7.2 Gesichter und Unterprogramme

void traurig() {
  Serial.println("  o   o");
  Serial.println("    |");
  Serial.println("  /---/");
  Serial.println("   :(");
}
void lachend() {
  Serial.println("  o   o");
  Serial.println("    |");
  Serial.println("  (___)");
  Serial.println("   :)");
}
void setup() {
  Serial.begin(9600);
  traurig();
  Serial.println();
  lachend();
}
void loop() {}

Eine mögliche Gestaltung. Die Funktionen fassen jeweils die Ausgabe eines Gesichtes zusammen und können erneut aufgerufen werden.

7.3 Zahlenfolge im seriellen Monitor

Die Folge beginnt mit 0, 5, 10, 15, 20, …, weil zuerst x ausgegeben und dann um 5 erhöht wird. Beim üblichen Uno ist int 16 Bit groß; 32765 ist der letzte noch darstellbare Wert dieser positiven Folge. Ein Überlauf ist keine verlässliche Fortsetzung der Zahlenfolge. Mit long lässt sich der Bereich vergrößern; eine Grenzprüfung vermeidet den Überlauf.

Debugging – Wenn das Programm nicht so läuft wie gedacht

Reflexion

Eine mögliche Antwort

Ein Programm kann kompilieren und dennoch etwas anderes tun als geplant. Beim Debugging vergleiche ich Soll- und Istverhalten, beobachte Zwischenwerte und grenze die Ursache ein. Ich ändere jeweils nur eine Sache und teste erneut. So lerne ich, ob ein Fehler in der Hardware, im Ablauf oder in einer Berechnung liegt.

Sicherung: for-Schleife

In einer for-Schleife legt der Startwert fest, wo gezählt wird. Die Bedingung entscheidet vor jedem Durchgang, ob der Block ausgeführt wird. Der Schritt verändert danach die Zählvariable.

Verständnisfragen – for-Schleifen

Eine mögliche Antwort
  1. Eine for-Schleife fasst einen wiederkehrenden Ablauf zusammen. Änderungen müssen nur im Schleifenrumpf vorgenommen werden, statt in fünf Kopien.
  2. i ist die Zählvariable. Sie wird initialisiert, in der Bedingung geprüft und nach jedem Durchlauf verändert; sie kann auch Werte für den jeweiligen Durchlauf liefern.
  3. Bei i = 0; i < 3; i++ läuft der Rumpf dreimal, für i = 0, 1 und 2. Bei i = 3 ist die Bedingung falsch.

8.1 Schleifengrenzen verändern

  • n = 0; n < 30; n++: 30 Durchläufe, n = 0 bis 29.
  • Startwert 5 bei Grenze 30: 25 Durchläufe, n = 5 bis 29.
  • Startwert 5 bei Grenze 50: 45 Durchläufe, n = 5 bis 49.
  • Startwert 5, Grenze 50 und n = n + 3: 15 Durchläufe, n = 5, 8, 11, …, 47.

Bei jedem Durchlauf werden Hallo und der aktuelle Zähler ausgegeben. Die Grenze selbst gehört bei < nicht dazu.

8.2 Tonfolge einer for-Schleife

Die Frequenzen sind 100, 103, 106, …, 1000 Hz. Das sind (1000 − 100) / 3 + 1 = 301 Durchläufe. Die Wartezeiten ergeben insgesamt 301 · 60 ms = 18,06 s; Befehlslaufzeiten kommen hinzu. Ohne noTone(11) bleibt der letzte Ton nach der Schleife eingeschaltet.

8.3 Auf- und abschwellende Sirene

void setup() {}
void loop() {
  for (int f = 100; f <= 1000; f += 3) {
    tone(11, f);
    delay(5);
  }
  for (int f = 1000; f >= 100; f -= 3) {
    tone(11, f);
    delay(5);
  }
}

Die erste Schleife erhöht, die zweite senkt die Tonhöhe. Größere Wartezeiten machen die Änderung langsamer.

8.4 Lauflicht

void setup() {
  for (int pin = 9; pin <= 13; pin++) {
    pinMode(pin, OUTPUT);
  }
}
void loop() {
  for (int pin = 9; pin <= 13; pin++) {
    digitalWrite(pin, HIGH);
    delay(200);
    digitalWrite(pin, LOW);
  }
}

Jede LED bekommt einen eigenen Vorwiderstand. Immer nur eine LED leuchtet; die Pinreihenfolge legt die Laufrichtung fest.

Wahr oder falsch?

Falsch. Bei außen 3 Durchgängen und innen 5 Durchgängen läuft der innere Code insgesamt 8-mal.

Falsch. Die Durchgänge werden multipliziert: 3 mal 5 ergibt 15.

Verständnisfragen – geschachtelte Schleifen

Eine mögliche Antwort
  1. Bei einer geschachtelten Schleife wird die innere Schleife innerhalb des Rumpfes der äußeren Schleife ausgeführt. Sie startet normalerweise bei jedem äußeren Durchlauf neu.
  2. Der innere Code läuft 2 · 5 = 10-mal.
  3. Mit der äußeren Schleife kann ich Zeilen oder Runden durchlaufen, mit der inneren Spalten oder Einzelschritte. So lassen sich regelmäßige Muster mit wenig Code beschreiben.

9. LEDs dimmen – Helligkeit stufenlos steuern

Wahr oder falsch?

Falsch. analogWrite(3, 127) erzeugt beim Arduino Uno eine echte, dauerhaft halbe Spannung am Pin.

Falsch. Der Arduino nutzt PWM: Der Pin wird sehr schnell ein- und ausgeschaltet. Für das Auge wirkt die LED dadurch ungefähr halb hell.

Verständnisfragen – LEDs dimmen

Eine mögliche Antwort
  1. Digitales Schalten setzt einen Ausgang auf HIGH oder LOW. Beim Dimmen verändert PWM den zeitlichen Anteil der HIGH-Phasen, sodass sich die mittlere Helligkeit der LED ändert.
  2. Der zweite Wert von analogWrite(pin, wert) bestimmt beim Uno das Tastverhältnis mit Werten von 0 bis 255: 0 ist aus, 255 dauerhaft an, 128 ungefähr die Hälfte der Zeit an.
  3. Die Schaltfolge ist schnell, sodass ihre Einzelphasen unter üblichen Beobachtungsbedingungen verschmelzen. Ein größeres Tastverhältnis liefert der LED im Mittel mehr Strom und lässt sie heller erscheinen.

9.1 Drei Helligkeitszustände

Die LED an Pin 3 ist eine Sekunde voll an, eine Sekunde aus und eine Sekunde per PWM gedimmt. Danach beginnt die Folge erneut. analogWrite(3, 127) entspricht ungefähr 49,8 % Tastverhältnis, nicht einer konstanten halben Ausgangsspannung.

9.2 Sanftes Auf- und Abblenden

void setup() { pinMode(3, OUTPUT); }
void loop() {
  for (int hell = 0; hell <= 255; hell++) {
    analogWrite(3, hell);
    delay(10);
  }
  for (int hell = 255; hell >= 0; hell--) {
    analogWrite(3, hell);
    delay(10);
  }
}

Die Wartezeiten eines gesamten Zyklus betragen 512 · 10 ms = 5,12 s. Die Extremwerte werden bei dieser Variante jeweils zweimal ausgegeben.

9.3 Wahrgenommene halbe Helligkeit

Für die wahrgenommene halbe Helligkeit gibt es keinen universellen PWM-Wert. 128 bedeutet etwa halbe Einschaltdauer, nicht zwangsläufig halbe subjektive Helligkeit. Die gesuchte Einstellung wird durch Vergleich mit 255 unter gleichen Lichtbedingungen bestimmt. Als reine Modellrechnung: Bei angenommener Wahrnehmung L = (PWM / 255)1/2,2 ergibt L = 0,5 etwa PWM = 55. Das ist kein gemessener Wert dieser LED.

9.4 Flackernde Kerze

void setup() {
  pinMode(3, OUTPUT);
  randomSeed(analogRead(A1));
}
void loop() {
  analogWrite(3, random(40, 220));
  delay(random(30, 150));
}

A1 bleibt für diesen Zufallsstart unbeschaltet. Die Obergrenzen von random() sind ausgeschlossen. Helligkeit und Dauer ändern sich unregelmäßig.

10. RGB-LEDs – Farben mischen mit Licht

Verständnisfragen – RGB-LEDs

Eine mögliche Antwort
  1. Eine RGB-LED enthält drei getrennt steuerbare Farbanteile: Rot, Grün und Blau. Dafür werden drei Steueranschlüsse und ein gemeinsamer Anschluss benötigt; je Farbzweig gehört ein Vorwiderstand dazu.
  2. Gelb entsteht durch additive Mischung von rotem und grünem Licht. Blau bleibt dabei aus.
  3. analogWrite() verändert auf PWM-Pins die Helligkeit jedes Farbanteils. Bei einer gemeinsamen Anode muss die Ansteuerlogik gegenüber einer gemeinsamen Kathode passend invertiert werden.

9.5 RGB-Farbmischungen

Bei einer RGB-LED mit gemeinsamer Kathode: Rot + Grün ergibt Gelb, Rot + Blau Magenta, Grün + Blau Cyan. Alle drei Farbanteile zusammen können Weiß ergeben, müssen dafür aber passend ausbalanciert sein. Jeder Farbzweig benötigt einen eigenen Vorwiderstand. Bei gemeinsamer Anode wird die Ansteuerung invertiert.

9.6 Fehler im Sketch korrigieren

void setup() {
  Serial.begin(9600);
}
void loop() {
  for (int i = 0; i < 10; i = i + 1) {
    Serial.print("Huhu");
    for (int u = 0; u < 100; u = u + 1) {
      Serial.print(i);
      Serial.print(",");
      Serial.println(u);
    }
  }
}

Korrigiert sind das Semikolon hinter setup(), der Name Serial.begin, die Klammern hinter loop, Serial.print statt pint sowie Deklaration und Semikolons der inneren for-Schleife. Die Baudrate von Sketch und Monitor muss übereinstimmen. Pro loop()-Durchlauf entstehen 10 · 100 = 1000 Zahlenpaar-Zeilen. Vor dem ersten Zahlenpaar jeder äußeren Runde steht Huhu.

9.7 Alle RGB-Einstellungen durchlaufen

void setup() {
  pinMode(9, OUTPUT);
  pinMode(10, OUTPUT);
  pinMode(11, OUTPUT);
}
void loop() {
  for (int r = 0; r <= 255; r++) {
    for (int g = 0; g <= 255; g++) {
      for (int b = 0; b <= 255; b++) {
        analogWrite(9, r);
        analogWrite(10, g);
        analogWrite(11, b);
        delay(1);
      }
    }
  }
}

Mit gemeinsamer Kathode und je einem Vorwiderstand sind das 256³ = 16.777.216 PWM-Kombinationen. Allein die Wartezeiten dauern ungefähr 4,66 Stunden. Die Kombinationen sind nicht sämtlich als unterschiedliche Farben wahrnehmbar.

Verständnisfragen – if / else

Eine mögliche Antwort
  1. Bedingungen erlauben ein Verhalten abhängig von Messwerten oder Zuständen, zum Beispiel Licht einschalten, wenn es dunkel ist.
  2. Ist die if-Bedingung falsch, wird der if-Rumpf übersprungen. Gibt es einen else-Zweig, wird dieser ausgeführt; danach geht es hinter der Entscheidung weiter.
  3. = ist eine Zuweisung, zum Beispiel x = 5. == ist ein Vergleich, zum Beispiel x == 5, der wahr oder falsch ergibt.

10.1 Schere, Stein oder Papier

void setup() {
  Serial.begin(9600);
  randomSeed(analogRead(A1));
  int wahl = random(1, 4);
  if (wahl == 1) Serial.println("Schere");
  else if (wahl == 2) Serial.println("Stein");
  else Serial.println("Papier");
}
void loop() {}

A1 ist unbeschaltet. Bei jedem Reset wird einmal eine der drei Möglichkeiten ausgegeben; random(1, 4) kann 1, 2 oder 3 liefern.

10.2 Helligkeitswechsel nach Zählschritten

Für i = 1 bis 99999 wird PWM-Wert 100 ausgegeben. Ab i = 100000 wird PWM-Wert 255 ausgegeben. Die ersten 99.999 Durchläufe sind also gedimmt, danach leuchtet die LED voll. Die Zahl zählt Schleifendurchläufe, keine Millisekunden; ohne delay() hängt die Zeit von der Laufgeschwindigkeit ab. Für dauerhaften Betrieb sollte der Zähler nach Erreichen der Grenze nicht weiter erhöht werden, damit kein Überlauf entsteht.
