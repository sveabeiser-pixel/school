Papieraufgabe: Erkläre die LED-Schaltung

Eine mögliche Antwort

Eine LED leuchtet, wenn Strom in Durchlassrichtung von der Anode zur Kathode fließt. Der Arduino-Pin wird mit pinMode() als Ausgang eingestellt und kann danach mit digitalWrite() auf HIGH oder LOW gesetzt werden. Die LED ist in Reihe mit einem passenden Widerstand verbunden, der ihren Strom begrenzt. Über GND führt der Stromweg zurück zum gemeinsamen Bezugspunkt. Bei HIGH kann die richtig gepolte LED leuchten, bei LOW ist sie in der gezeigten Schaltung aus.

Selbstkontrolle

Wichtig sind diese Punkte: Der Arduino steuert einen Ausgangspin, der Strom fließt durch LED und Widerstand zu GND, der Widerstand begrenzt den Strom und schützt die LED, und der Stromkreis muss geschlossen sein. Eine gute Antwort nennt außerdem die Richtung des Stromflusses und die Funktion von HIGH oder LOW.

Schleifen und Bedingungen

Sicherung: Schleifen und Bedingungen

Eine for-Schleife nutzt du meist, wenn die Anzahl der Wiederholungen vorher bekannt ist. Eine while-Schleife läuft, solange eine Bedingung wahr bleibt. Mit if / else trifft das Programm eine Entscheidung zwischen verschiedenen Wegen.

Sortiere die Aussagen

KategorieBegriff
passt zu forDie Anzahl der Wiederholungen ist vorher bekannt.
passt zu whileDer Code läuft, solange eine Bedingung wahr bleibt.
passt zu if / elseDas Programm entscheidet zwischen zwei Wegen.
passt zu forTypisch für 5-mal blinken.
passt zu whileTypisch für warten, bis ein Taster gedrückt wird.
passt zu if / elseTypisch für LED an oder aus je nach Messwert.

Warum braucht man Schleifen?

Welche Vorteile haben Schleifen im Programm?

Wiederholungen müssen nicht mehrfach ausgeschrieben werden.; Programme werden oft kürzer und übersichtlicher.; Man kann Abläufe gezielt mehrfach ausführen.

Schleifen strukturieren Wiederholungen. Sie ersetzen natürlich keine elektrischen Bauteile.

Weil sie zu einer Endlosschleife werden kann, wenn sich die Bedingung nie ändert.

Wenn die Bedingung immer wahr bleibt, läuft die while-Schleife endlos weiter.

Was ist der wichtige Unterschied zwischen = und == in einer Bedingung?

= weist einen Wert zu, == vergleicht zwei Werte.

Das ist ein sehr typischer Fehler: = ist Zuweisung, == ist Vergleich.

Fehler finden: semantischer Fehler

Eine mögliche Antwort

Mit INPUT_PULLUP ist der Taster im Ruhezustand HIGH und bei Druck LOW. Die while-Schleife läuft also gerade während des Wartens auf den Tastendruck und erhöht zaehler extrem schnell. Sie zählt keine einzelnen Tastendrücke. Solange sie läuft, sind die LED-Entscheidung und die serielle Ausgabe dahinter nicht erreichbar. Beim Drücken endet die Schleife; der inzwischen große Zähler ist normalerweise nicht gleich 1, sodass die LED ausgeschaltet wird. Ein unbegrenzt wachsender int kann zudem überlaufen. Für das Zählen von Tastendrücken muss ich einen Wechsel von HIGH nach LOW erkennen, den Taster entprellen und pro gültigem Wechsel nur einmal erhöhen. Soll die LED nur den Tasterzustand zeigen, ist statt der Zählschleife digitalWrite(LED, digitalRead(BTN) == LOW ? HIGH : LOW) passend.

Die while-Schleife zählt extrem schnell hoch, solange der Taster nicht gedrückt ist. Dadurch wird zaehler sehr groß, noch bevor überhaupt eine sinnvolle Aktion passiert. Außerdem wird die LED praktisch nie dauerhaft wegen zaehler == 1 eingeschaltet, weil dieser Zustand kaum getroffen wird. Transferfrage

Eine mögliche Antwort

Ein Motor benötigt gewöhnlich mehr Strom, als ein Arduino-Ausgang liefern darf. Besonders der Anlauf- oder Blockierstrom kann groß sein. Deshalb liefert der Pin nur das Steuersignal an einen passenden Transistor oder Motortreiber. Der Laststrom kommt aus einer ausreichend dimensionierten Versorgung. Arduino und Treiber benötigen einen passenden gemeinsamen Bezugspunkt, normalerweise GND. Beim Ausschalten versucht die Motorinduktivität den Strom aufrechtzuerhalten und kann eine hohe Spannungsspitze erzeugen. Eine Freilaufdiode beziehungsweise die geeignete Schutzbeschaltung des Treibers bietet dem Strom einen Pfad und schützt die Schaltung. Bei einer H-Brücke ist deren vorgesehene Schutzbeschaltung zu verwenden, nicht einfach irgendeine Diode quer zum Motor.

Selbstkontrolle

Ein Motor braucht meist mehr Strom als ein Arduino-Pin liefern kann. Deshalb steuert der Arduino den Motor indirekt über Transistor oder Motortreiber. Oft braucht der Motor eine eigene Stromversorgung. Außerdem können beim Abschalten Spannungsspitzen entstehen, gegen die eine Freilaufdiode schützt. Eine gute Antwort verbindet also Strombedarf, Schutz und Steuerprinzip.

Weiterdenken

Eine LED braucht deutlich weniger Strom und kann deshalb oft direkt über einen Ausgangspin mit Schutzwiderstand betrieben werden. Ein Motor ist dagegen ein stärkerer Verbraucher und erzeugt zusätzlich störende Spannungsspitzen. Deshalb braucht er eine aufwendigere Ansteuerung.

Mini-Check zur Probeklausur

Welche Aussage zu analogWrite() passt am besten?

Der zweite Wert steuert bei PWM die Stärke zwischen 0 und 255.

Im Lernbaustein wird analogWrite() mit einem Wertebereich von 0 bis 255 genutzt, zum Beispiel für LED-Helligkeit oder Motorsteuerung.

Warum sind Unterprogramme in einer Klausur wichtig?

Weil sie zeigen, wie man wiederkehrende Abläufe übersichtlich organisiert.

Unterprogramme strukturieren wiederkehrende Abläufe und machen Programme kürzer und klarer.

Deine Musterlösung

Eine mögliche Antwort

Beispielantwort zu Aufgabe A: digitalWrite() setzt einen als Ausgang konfigurierten Pin auf HIGH oder LOW. Bei einem üblichen Uno entspricht dies ungefähr 5 V oder 0 V gegenüber GND. Eine angeschlossene LED wird dadurch ein- oder ausgeschaltet. analogWrite() erzeugt an einem dafür geeigneten Uno-Pin normalerweise PWM. Es schaltet ebenfalls zwischen HIGH und LOW, verändert aber das Verhältnis der Zeitanteile. Der typische Wertebereich ist 0 bis 255. Bei 0 bleibt der Ausgang LOW, bei 255 HIGH. Ein Wert von etwa 128 liefert ungefähr 50 % Tastverhältnis. Eine LED wirkt dadurch unter üblichen Beobachtungsbedingungen etwa in einer mittleren Helligkeit, wobei die wahrgenommene Helligkeit nicht exakt linear zum Zahlenwert ist. PWM ist bei diesem Board kein echter stufenloser Gleichspannungsausgang.

Erwartungshorizont

Aufgabe A: digitalWrite schaltet nur an oder aus, analogWrite nutzt PWM mit Werten etwa von 0 bis 255. Aufgabe B: Bei INPUT_PULLUP ist gedrückt gleich LOW und nicht gedrückt gleich HIGH. Aufgabe C: = weist zu, == vergleicht. Aufgabe D: Unterprogramme und Schleifen machen Code kürzer, klarer und leichter änderbar. Aufgabe E: Erwartet werden while oder if für den Taster, eine for-Schleife für die fünf Wiederholungen, tone oder noTone für den Ton und Serial.println für die Meldung.

Aufgabe A

digitalWrite() schaltet einen Ausgang auf HIGH oder LOW. analogWrite() verwendet beim Uno an PWM-Pins einen Wert von 0 bis 255, um das Tastverhältnis zu verändern. Dadurch lässt sich beispielsweise eine LED dimmen, obwohl der Pin elektrisch weiter zwischen den beiden Pegeln schaltet.

Aufgabe B

Gedrückt liest der Arduino LOW, weil der Taster den Eingang mit GND verbindet. Im Ruhezustand sorgt der interne Pullup für HIGH. Die intuitive Vorstellung 'gedrückt = HIGH' passt deshalb nicht zu dieser Verdrahtung.

Aufgabe C

if (x = 5) weist x den Wert 5 zu. Der Zuweisungsausdruck liefert 5 und gilt als wahr; der if-Block wird deshalb ausgeführt, ohne den vorherigen x-Wert zu vergleichen. Für den Vergleich lautet der Ausdruck if (x == 5).

Aufgabe D

Ein Unterprogramm kapselt den wiederkehrenden Ablauf unter einem verständlichen Namen. Eine Schleife wiederholt den Aufruf oder den Ablauf mit einer festgelegten Anzahl beziehungsweise Bedingung. Änderungen erfolgen einmal in der Definition statt in jeder Kopie. Dadurch werden Code und Fehlersuche übersichtlicher.

Aufgabe E

Eine while-Schleife wartet bei INPUT_PULLUP, solange der Taster HIGH ist. Danach führt eine for-Schleife fünf Ton-Pause-Paare aus. tone() beginnt den Ton, noTone() beendet ihn; delay() legt die Dauer und Pause fest. Abschließend gibt Serial.println() eine Meldung aus.

void setup() {
  pinMode(2, INPUT_PULLUP); Serial.begin(9600);
  while (digitalRead(2) == HIGH) { delay(5); }
  for (int i = 0; i < 5; i++) {
    tone(11, 440); delay(100);
    noTone(11); delay(100);
  }
  Serial.println("Fertig");
}
void loop() {}

Dieses Beispiel führt den Ablauf einmal nach dem Start aus.
