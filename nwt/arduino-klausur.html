Arduino-Klausurtraining für die Papierklausur

Über die Internetseiten zu Arduino soll eine Klausur geschrieben werden. Diese Seite hilft dir dabei, die Inhalte ohne Computer und ohne echten Arduino zu wiederholen. Du trainierst also genau das, was du auf Papier können musst: Begriffe erklären, Code lesen, Abläufe begründen, Fehler erkennen und kleine Lösungen planen.

So benutzt du diese Seite
Lies die Aufgaben wie eine Probeklausur. Antworte erst im Kopf oder auf Papier und prüfe dich dann mit den Interaktionen. Nutze die Freitextfelder für Begründungen, nicht nur für Ein-Wort-Antworten.
Was du danach können solltest
Du kannst die wichtigsten Arduino-Begriffe sauber erklären, typische Code-Strukturen lesen und passende Lösungen oder Korrekturen aufschreiben, auch wenn kein Board vor dir liegt.

Grundlagen: Mikrocontroller, Pins, Stromkreis

Jetzt hast du das gelernt: Ein Arduino ist eine Mikrocontroller-Platine. Er verarbeitet Programme, liest Eingaben und steuert Ausgänge. Zu den Grundlagen gehören außerdem HIGH und LOW, geschlossene Stromkreise, LEDs, Widerstände, GND und die Idee, dass Bauteile richtig verbunden sein müssen.

Merke
HIGH bedeutet vereinfacht: An einem Pin liegt Spannung an. LOW bedeutet: Es liegt keine Ausgangsspannung an oder ein Eingang wird auf das niedrige Signalniveau gezogen.
Typischer Klausurpunkt
Du musst erklären können, warum eine LED einen Widerstand braucht und warum ein Stromkreis nur funktioniert, wenn er geschlossen ist.

Programmaufbau: setup(), loop(), IDE und Upload

Jetzt hast du das gelernt: Die Arduino-IDE dient zum Schreiben, Prüfen und Übertragen von Programmen. Ein Arduino-Programm hat meist die Bereiche setup() und loop(). In Klausuren wird oft gefragt, was welcher Teil macht und warum die Reihenfolge beim Übertragen wichtig ist.

Klausurformat
Formuliere Antworten so, als würdest du sie einer Person erklären, die das Programm vor sich sieht. Ein Satz wie „setup ist einmal, loop ist immer“ reicht meistens nicht. Du musst den Zweck nennen.

Code lesen: Variablen, Ausgabe und Fehlersuche

In der Klausur wirst du wahrscheinlich Codeausschnitte lesen und erklären müssen. Dazu gehören Variablen, Blinkprogramme, serielle Ausgabe und typische Fehlermeldungen. Entscheidend ist: Du musst nicht alles auswendig schreiben, sondern verstehen, was der Code bewirkt.

Jetzt hast du das gelernt
Variablen speichern veränderbare Werte. Serial.begin(9600); startet die serielle Verbindung. Serial.println(...); gibt Werte aus. Fehlermeldungen weisen oft auf fehlende Zeichen, falsche Namen oder falsche Klammern hin.
Verbinde jeweils den Befehl mit seiner Funktion.
Befehl
pinMode(13, OUTPUT);
delay(500);
Serial.begin(9600);
x = x + 1;
Funktion
legt fest, dass ein Pin als Ausgang arbeitet
erzeugt eine Wartezeit von 500 Millisekunden
startet die serielle Kommunikation
erhöht den Wert einer Variable um 1
Gelöst
Code zur Aufgabe 
int wert = 4;
int faktor = 2;

void loop() {
  Serial.println(wert);
  if (wert < 20) {
    wert = wert * faktor;
  } else {
    wert = wert - 6;
  }
}
Code zur Aufgabe 
int ton = 262;
int pause = 180;
int wiederholungen = 0;
int sprung = 35;

void setup() {
  Serial.begin(9600);
}

void loop() {
  if (wiederholungen < 4) {
    tone(11, ton);
    delay(pause);
    noTone(11);
    delay(120);
    Serial.println(ton);
    ton = ton + sprung;
    wiederholungen = wiederholungen + 1;
  } else {
    Serial.println(pause);
    pause = pause + 100;
    ton = 262;
    wiederholungen = 0;
  }
}

Schleifen und Bedingungen

Jetzt hast du das gelernt: for-Schleifen nutzt du meist für feste Wiederholungen, while-Schleifen für Wiederholungen mit einer Bedingung, und if / else für Entscheidungen. Genau diese Unterschiede werden gern abgefragt.

Code zur Aufgabe 
int grundton = 330;

for (int runde = 0; runde < 2; runde++) {
  for (int i = 0; i < 3; i++) {
    tone(11, grundton + i * 40);
    delay(120);
    noTone(11);
    delay(80);
  }
  grundton = grundton + 100;
}

Programmieren üben: Codebausteine, Syntax und Semantik

Jetzt geht es um typische Klausuraufgaben direkt zum Programmieren. Du sollst Reihenfolgen herstellen, Fehlerarten unterscheiden und begründen, was der Unterschied zwischen einem Syntaxfehler und einem semantischen Fehler ist.

Merke
Ein Syntaxfehler bedeutet: Der Code ist formal falsch und lässt sich oft nicht kompilieren. Ein semantischer Fehler bedeutet: Der Code ist formal erlaubt, macht aber nicht das, was beabsichtigt war.
Code zur Aufgabe 
int basis = 200;
int schritt = 50;

void setup( {
  Serial.begin(9600)
}

void loop() {
  for (int i = 0; i < 3; i++ {
    Serial.println(basis + i * schritt);
  
  if (basis < 500) {
    basis = basis + schritt
  }
}
Code zur Aufgabe 
const int BTN = 2;
const int LED = 13;
int zaehler = 0;

void setup() {
  pinMode(LED, OUTPUT);
  pinMode(BTN, INPUT_PULLUP);
  Serial.begin(9600);
}

void loop() {
  while (digitalRead(BTN) == HIGH) {
    zaehler = zaehler + 1;
  }

  if (zaehler == 1) {
    digitalWrite(LED, HIGH);
  } else {
    digitalWrite(LED, LOW);
  }

  Serial.println(zaehler);
}

Anwendung: PWM, Taster, Unterprogramme, Motoren und Displays

Auf den späteren Seiten tauchen Anwendungen auf, bei denen du Begriffe übertragen musst: PWM für Helligkeit oder Geschwindigkeit, Taster mit INPUT_PULLUP, Unterprogramme für wiederkehrende Abläufe, Displays zur Ausgabe von Texten und Motoren mit Transistor oder Motortreiber.

PWM und analogWrite()
Eine LED kann nicht nur an oder aus sein. Mit PWM wirkt sie heller oder dunkler. Bei Motoren kann PWM auch die Geschwindigkeit beeinflussen.
INPUT_PULLUP
Typischer Stolperstein: nicht gedrückt = HIGH, gedrückt = LOW. Wenn du das vergisst, drehst du die Logik im Code aus Versehen um.
Verbinde den Begriff mit der passenden Erklärung.
Begriff
analogWrite(..., 127)
INPUT_PULLUP
Unterprogramm / Funktion
Transistor oder Motortreiber
lcd.print(...)
Erklärung
setzt eine mittlere PWM-Stärke und wirkt zum Beispiel wie halbe Helligkeit
legt für einen Eingang einen definierten Grundzustand fest
fasst wiederkehrende Abläufe an einer Stelle zusammen
schaltet größere Ströme, die ein Arduino-Pin nicht direkt liefern soll
gibt Text auf einem Display aus
Gelöst

Probeklausur auf Papier

Hier trainierst du typische Aufgabentypen, die in einer Papierklausur gut vorkommen können: erklären, vergleichen, korrigieren und begründen. Schreibe deine Antworten möglichst vollständig und in Fachsprache.

Aufgabe A
Erkläre den Unterschied zwischen digitalem Schalten mit digitalWrite() und dem Dimmen mit analogWrite(). Nenne auch einen typischen Wertebereich.
Aufgabe B
Ein Taster ist mit INPUT_PULLUP angeschlossen. Beschreibe, welchen Wert der Arduino liest, wenn der Taster gedrückt ist, und warum viele Schülerinnen und Schüler hier zuerst falsch denken.
Aufgabe C
Eine Schülerin schreibt: if (x = 5). Erkläre, warum das problematisch ist und welche Schreibweise sie für einen Vergleich normalerweise braucht.
Aufgabe D
Erkläre, warum man für einen wiederkehrenden Ablauf eher ein Unterprogramm und eine Schleife benutzt als denselben Codeblock immer wieder neu hinzuschreiben. Gehe dabei auf Übersichtlichkeit und Änderbarkeit ein.
Aufgabe E
Beschreibe in Worten, was dieser Ablauf macht: Zuerst wird auf einen Tastendruck gewartet, danach erklingt ein Ton fünfmal kurz hintereinander, und zum Schluss wird eine Meldung im seriellen Monitor ausgegeben. Welche Programmbausteine erwartest du dafür?

Zusammenfassung, Weiterforschen und Abgabe

Jetzt hast du das gelernt: Du solltest nicht nur einzelne Befehle nennen können, sondern ihren Zweck, ihre Wirkung und typische Fehler erklären. Genau das ist die Grundlage für eine gute Papierklausur.
