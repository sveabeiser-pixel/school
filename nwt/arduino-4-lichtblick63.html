11. Eingaben mit Tastern - Der Arduino reagiert

Ablaufspur: INPUT_PULLUP richtig herum denken

TasterVerbindungdigitalRead(BTN)== LOW
nicht gedrücktintern mit HIGH verbundenHIGHfalsch
gedrücktmit GND verbundenLOWwahr

Wahr oder falsch?

Wahr. Bei unserem Taster zwischen Eingang und GND bedeutet gedrückt mit INPUT_PULLUP LOW.

Richtig. Der Taster verbindet den Eingang beim Drücken mit GND. Deshalb liest der Arduino LOW.

Verständnisfragen - Taster

Eine mögliche Antwort
  1. Der Schließertaster schließt nur während des Drückens und öffnet beim Loslassen. Ein rastender Schalter bleibt in seiner gewählten Stellung.
  2. Ein offener Eingang wäre ohne definierenden Widerstand störanfällig. Der Pullup zieht ihn zur Versorgung, ein Pulldown nach GND. Ein Widerstand begrenzt dabei den Strom, wenn der Taster den anderen Pegel verbindet.
  3. Mit INPUT_PULLUP liest D4 beim freien Taster HIGH, beim Drücken verbindet der Taster D4 mit GND und die Abfrage ergibt LOW. LOW/HIGH bezeichnet den Spannungspegel, nicht allgemein den Zustand gedrückt/frei.

Multiple Choice - Eingaben (mehrere Antworten möglich)

1) Was trifft auf digitale Eingänge zu?

Sie kennen nur LOW oder HIGH; Man liest sie mit digitalRead()

Digitale Eingänge kennen LOW/HIGH und werden mit digitalRead() gelesen.

2) Wozu dient INPUT_PULLUP?

Der Eingang bekommt einen definierten Grundzustand; Man spart oft einen externen Widerstand

INPUT_PULLUP setzt einen Grundzustand und spart oft den externen Widerstand.

3) Welche Aussage ist bei INPUT_PULLUP richtig?

Nicht gedrückt = HIGH; Gedrückt = LOW

Bei INPUT_PULLUP ist nicht gedrückt = HIGH und gedrückt = LOW.

Versuchsprotokoll 11.1–11.5

Eine mögliche Antwort

Als erwartetes Ergebnis des beschriebenen Aufbaus: 11.1 frei → 1, gedrückt → 0, wieder frei → 1; auch ein abgetrennter Eingang bleibt durch INPUT_PULLUP HIGH. 11.2 frei → LED aus, gedrückt → an, losgelassen → aus. Nach Vertauschen der beiden LED-Ausgabepegel ist die LED frei an und gedrückt aus.

11.3 ergibt ohne Taste Stille, bei D4 220 Hz, bei D5 880 Hz und bei beiden zunächst 220 Hz. Nach Vertauschen der Abfragereihenfolge hat D5 Vorrang. Der einfache Zähler zählt Schleifendurchläufe bei LOW; langes Halten erzeugt deshalb viele Zählungen. Die stabile Ereignislösung unter 11.4 zählt einen bestätigten Druck und wartet auf stabiles Loslassen. Prellen ist davon unabhängig ein mehrfacher mechanischer Kontaktwechsel.

Für 11.5 sind 1,042 ms pro 8N1-Zeichen bei 9600 Baud und 0,521 ms bei 19200 Baud berechnete Sollwerte. Die Folge von millis-Ausgaben kann wiederholte und unterschiedlich weit auseinanderliegende Werte enthalten. Zahlendarstellung, Zeilenenden und Sendepuffer beeinflussen sie. Ohne eigenen Hardwaretest werden keine Zeitstempel-Differenzen oder Messwerte behauptet; diese sind im tatsächlichen Protokoll einzutragen.

11.1 Tasterwerte

void setup() {
  pinMode(4, INPUT_PULLUP);
  Serial.begin(9600);
}
void loop() {
  int zustand = digitalRead(4);
  Serial.println(zustand);
  delay(100);
}

Mit INPUT_PULLUP liefert D4 frei 1/HIGH, gedrückt 0/LOW und wieder frei 1. Auch ohne Tasterleitung zieht der interne Widerstand den Eingang auf HIGH. Die Materialaussage gilt genau für den Taster nach GND. Ein dauerhaftes LOW kann durch einen falschen Kontaktanschluss entstehen.

11.2 LED mit Taster schalten

void setup() {
  pinMode(4, INPUT_PULLUP);
  pinMode(9, OUTPUT);
}
void loop() {
  if (digitalRead(4) == LOW) digitalWrite(9, HIGH);
  else digitalWrite(9, LOW);
}

Taster D4/GND; D9→330 Ω→LED-Anode, Kathode→GND. Frei ist die LED aus, gedrückt an, danach wieder aus. Vertauschte Ausgabepegel kehren nur das LED-Verhalten um: frei an, gedrückt aus. Der Tasterpegel selbst bleibt unverändert.

11.3 Zwei Taster für zwei Tonhöhen

void setup() {
  pinMode(4, INPUT_PULLUP);
  pinMode(5, INPUT_PULLUP);
}
void loop() {
  if (digitalRead(4) == LOW) {
    tone(11, 220);
  } else if (digitalRead(5) == LOW) {
    tone(11, 880);
  } else {
    noTone(11);
  }
}

Beide Taster liegen nach GND; am Uno R3 ist D11 über 330 Ω oder 1 kΩ mit einem geprüften kleinen passiven Lautsprecher und dessen zweiter Anschluss mit GND verbunden. Zuerst wird 1 kΩ verwendet; der Serienwiderstand bleibt immer eingebaut. Ein unbeschriftetes Bauteil wird vor dem Anschluss als passiver Lautsprecher geprüft. Ein passiver Piezo mit Serienwiderstand ist eine Alternative. Keine Taste: stumm; D4: 220 Hz; D5: 880 Hz; beide: 220 Hz, weil der erste if-Zweig Vorrang hat. Wird zuerst D5 und dann D4 geprüft, erklingt bei beiden 880 Hz. Für höhere Lautstärke ist eine geeignete Treiberstufe nötig. Ein aktiver Summer erzeugt seine Tonhöhe selbst und ist für diesen Versuch ungeeignet.

11.4 Tastendrücke zählen

Der einfache Ausgangssketch erhöht anzahl bei jedem loop-Durchlauf mit LOW. Ein langes Halten zählt deshalb sehr oft; auch kurzes Drücken kann mehr als einmal zählen. Nur auf das Loslassen zu warten verhindert das Wiederholen beim Halten, aber noch nicht jedes Prellen. Eine blockierende Ereignislösung mit hier angenommener Entprellzeit von 20 ms ist:

unsigned long anzahl = 0;
void warteStabil(int pin, int pegel) {
  unsigned long seit = millis();
  while (millis() - seit < 20) {
    if (digitalRead(pin) != pegel) seit = millis();
  }
}
void setup() {
  pinMode(4, INPUT_PULLUP);
  Serial.begin(9600);
}
void loop() {
  if (digitalRead(4) == LOW) {
    warteStabil(4, LOW);
    anzahl++;
    Serial.println(anzahl);
    warteStabil(4, HIGH);
  }
}

Jeder Pegel muss durchgehend 20 ms anliegen. Nach bestätigtem LOW wird einmal gezählt, dann auf stabiles HIGH gewartet. Bei fünf ausreichend langen getrennten Betätigungen ab Reset erwartet man die Folge 1 bis 5; ein langer zusätzlicher Druck erhöht genau einmal auf 6. Die Funktion blockiert andere Aufgaben, sehr kurze Impulse werden nicht als bestätigte Betätigung gewertet.

11.5 Übertragungszeit serieller Zeichen

Der erste Versuch lautet:

void setup() {
  Serial.begin(9600);
}
void loop() {
  unsigned long m = millis();
  Serial.println(m);
}

millis wird als mehrstellige Dezimalzahl ausgegeben; println sendet zusätzlich zwei Zeilenendezeichen. Die Millisekundenauflösung und der Sendepuffer erlauben aus den Differenzen aufeinanderfolgender Zeitstempel keine genaue Dauer pro Zeichen.

void setup() {
  Serial.begin(9600);
  delay(1000);
  Serial.flush();
  unsigned long start = micros();
  for (int i = 0; i < 100; i++) {
    Serial.write('A');
  }
  Serial.flush();
  unsigned long dauer = micros() - start;
  Serial.println();
  Serial.print("Mikrosekunden pro Zeichen: ");
  Serial.println(dauer / 100.0);
}
void loop() {}

Bei 9600 Baud/8N1 werden pro Zeichen 10 Bits übertragen: 10/9600 s = 1,0417 ms = 1041,7 µs. 100 Zeichen benötigen theoretisch etwa 104,17 ms. Bei 19200 Baud halbiert sich der Sollwert auf 520,8 µs pro Zeichen. Das sind berechnete Werte, keine realen Messwerte. Der Kontrollversuch wartet mit flush auf den Abschluss der Übertragung; Programmaufwand und Zeitauflösung können Abweichungen bewirken. Er misst nicht die Darstellungsgeschwindigkeit des seriellen Monitorfensters und setzt den UART des Uno R3 voraus.

Mini-Challenge: Taster als Farbwechsel

const int BTN = 4;
const int ROT = 9, GRUEN = 10, BLAU = 6;
void setup() {
  pinMode(BTN, INPUT_PULLUP);
  pinMode(ROT, OUTPUT);
  pinMode(GRUEN, OUTPUT);
  pinMode(BLAU, OUTPUT);
}
void loop() {
  bool gedrueckt = digitalRead(BTN) == LOW;
  analogWrite(ROT, gedrueckt ? 0 : 255);
  analogWrite(GRUEN, gedrueckt ? 255 : 0);
  analogWrite(BLAU, 0);
}

Gemeinsame Kathode an GND; R/G/B jeweils über 330 Ω an D9/D10/D6; Taster D4/GND. Frei leuchtet Rot, gedrückt Grün und danach wieder Rot. Blau bleibt aus. Die Abfrage speichert keinen Modus, sondern reagiert direkt auf den aktuellen Pegel. Eine RGB-LED mit gemeinsamer Anode benötigt angepasste Verdrahtung und umgekehrte Ansteuerung.

12. Wiederholungen mit while: solange eine Bedingung wahr ist

Ablaufspur: while prüft vor jedem Durchgang

Sicherung: while

Eine while-Schleife läuft, solange ihre Bedingung wahr ist. Damit eine anfangs wahre Bedingung später falsch wird, muss sich eine für sie relevante Größe ändern, sodass die Bedingung irgendwann falsch wird.

Verständnisfragen - while

Eine mögliche Antwort
  1. for bündelt Initialisierung, Bedingung und Zählschritt im Schleifenkopf; while enthält dort nur die Bedingung. Beide können feste Wiederholungszahlen umsetzen. for ist dafür oft übersichtlicher.
  2. while passt zum Warten auf einen Tastendruck mit unbekannter Wartezeit: while (digitalRead(4) == HIGH) {} endet, sobald der Eingang beim Drücken LOW liest. Die Abfrage liest den Taster bei jeder Prüfung erneut.
  3. Eine Endlosschleife verlässt ihren Block nicht. Die konstante Bedingung 2 < 5 bleibt immer wahr. Ein fehlender Zählschritt kann denselben Effekt haben. Ein erneut gelesener Tasterwert kann sich durch Betätigung ändern; bleibt die Taste frei, wartet diese Schleife weiter. Nach dem globalen Zählbeispiel gilt x = 20: loop läuft weiter, aber der while-Rumpf wird nicht erneut betreten.

Multiple Choice - while (mehrere Antworten möglich)

1) Eine while-Schleife läuft ...

so lange, wie die Bedingung wahr ist; bis die Bedingung falsch wird

while läuft, solange die Bedingung wahr ist, und endet, wenn sie falsch wird.

2) Welche Situationen passen gut zu while?

Warten, bis ein Taster gedrückt wird; Wiederholen, bis ein Grenzwert erreicht ist

while nutzt man, wenn nicht vorher feststeht, wie oft etwas passiert.

3) Wie vermeidet man Endlosschleifen?

Die Bedingung muss irgendwann falsch werden können; Eine geprüfte Größe muss sich ändern können, etwa ein erneut gelesener Tasterzustand; Man sollte prüfen, ob die Ausstiegsbedingung erreichbar ist

Für einen regulären Ausstieg muss die Bedingung falsch werden können. Das kann durch Zählen oder einen neu eingelesenen äußeren Zustand geschehen.

Versuchsprotokoll 12.1–12.3

Eine mögliche Antwort

12.1: Erwartet werden 1 bis 99, anschließend fortlaufend !. setup endet nicht, die LED wird in loop nicht eingeschaltet. Nach Ersetzen des zweiten while-Blocks durch Serial.println("fertig") wird fertig ausgegeben und loop setzt die LED auf HIGH. Ein Reset allein wiederholt lediglich denselben ursprünglichen Fehler.

12.2: Vor dem Drücken keine Ausgabe; beim Drücken von jetzt; beim Halten kein weiteres Textstück; nach Loslassen bis jetzt. Der nächste Tastendruck setzt die Folge fort. print hängt alles direkt zusammen, println erzeugt Zeilenumbrüche. Ohne gespeicherte Start-/Endzeit und Differenz wird noch keine Dauer gemessen.

12.3: Für drei getrennte D4-Betätigungen ausgehend von 440 Hz sind 441, 442, 443 Hz zu erwarten; ein weiterer langer Druck liefert einmal 444 Hz. Nach Loslassen senkt ein D5-Druck auf 443 Hz. An den Grenzen bleibt der Wert zwischen 100 und 2000. Die Pegelprüfung muss 20 ms ohne Gegenzustand erfüllen; das stabile Loslassen gibt den nächsten Druck frei. D4 hat beim Wählen Vorrang; D5 kann danach folgen, wenn er noch gehalten wird. Während des Wartens wird die andere Taste nicht parallel bearbeitet.

Mit || ist die Bereichsbedingung unter 100 ODER über 2000 erfüllbar. Mit && müsste derselbe Wert gleichzeitig unter 100 UND über 2000 sein; das ist unmöglich. Die Frequenzen hier sind Codevorhersagen, keine behaupteten Messungen.

12.1 Zwei while-Schleifen

Erwartete Folge: 1, 2, …, 99; danach x = 100. Die konstante Bedingung 2 < 5 bleibt wahr und erzeugt fortlaufend !. setup endet nicht; loop und dessen LED-Anweisung werden nicht erreicht. Reset startet die gleiche Schleife wieder. Die Reparatur ersetzt den zweiten while-Block durch eine einmalige Ausgabe:

int x = 1;
void setup() {
  Serial.begin(9600);
  pinMode(LED_BUILTIN, OUTPUT);
  digitalWrite(LED_BUILTIN, LOW);
  while (x < 100) {
    Serial.println(x);
    x++;
  }
  Serial.println("fertig");
}
void loop() {
  digitalWrite(LED_BUILTIN, HIGH);
}

Nach fertig endet setup; loop schaltet die eingebaute LED an. Der Monitor wird auf 9600 Baud eingestellt.

12.2 Gedrückt und losgelassen

void setup() {
  pinMode(4, INPUT_PULLUP);
  Serial.begin(9600);
}
void loop() {
  while (digitalRead(4) == HIGH) {}
  Serial.print("von jetzt");
  while (digitalRead(4) == LOW) {}
  Serial.print("bis jetzt");
}

Die erste leere while-Schleife liest D4 wiederholt, solange die Taste frei ist. Beim Drücken erscheint von jetzt. Die zweite wartet solange die Taste LOW ist; erst beim Loslassen erscheint bis jetzt. Danach beginnt loop neu. Ohne Druck wird zunächst nichts geschrieben. print liefert von jetztbis jetztvon jetzt… ohne Zeilenumbruch. Mit println stehen die Textteile in separaten Zeilen. Eine Zeitdauer wird weder gespeichert noch berechnet. Ohne Entprellung kann ein realer Taster zusätzliche Übergänge auslösen.

12.3 Tonhöhe schrittweise verändern

int frequenz = 440;

void warteStabil(int pin, int pegel) {
  unsigned long seit = millis();
  while (millis() - seit < 20) {
    if (digitalRead(pin) != pegel) seit = millis();
  }
}

void setup() {
  pinMode(4, INPUT_PULLUP);
  pinMode(5, INPUT_PULLUP);
  Serial.begin(9600);
  tone(11, frequenz);
}
void loop() {
  int taste = 0;
  if (digitalRead(4) == LOW) taste = 4;
  else if (digitalRead(5) == LOW) taste = 5;
  if (taste == 0) return;
  warteStabil(taste, LOW);
  if (taste == 4 && frequenz < 2000) frequenz++;
  if (taste == 5 && frequenz > 100) frequenz--;
  tone(11, frequenz);
  Serial.println(frequenz);
  warteStabil(taste, HIGH);
}

D4 erhöht um 1 Hz, D5 senkt um 1 Hz. Der Monitor bei 9600 Baud macht die kleine Änderung eindeutig sichtbar. Ausgehend von 440 liefern drei getrennte D4-Drücke 441, 442, 443; ein zusätzlicher langer Druck einmal 444. Die Grenzprüfungen halten den Wert zwischen 100 und 2000. warteStabil wartet durchgehend 20 ms auf den gewählten Pegel. Das stabile Loslassen verhindert wiederholtes Auslösen durch Halten.

Bei zwei gleichzeitig erkannten Tasten wird D4 ausgewählt. Nach seinem Loslassen kann der noch gehaltene D5 im nächsten loop-Durchlauf folgen. Während der blockierenden Wartefunktion wird der andere Eingang nicht ausgewertet; der erzeugte Ton läuft weiter. frequenz < 100 || frequenz > 2000 bezeichnet Werte außerhalb des Bereichs. Beide Teilbedingungen gleichzeitig mit && sind unmöglich.

Aufbau wie in 11.3: Uno R3 D11 → 330 Ω oder 1 kΩ → geprüfter kleiner passiver Lautsprecher → GND; alternativ ein passiver Piezo mit Serienwiderstand. Der Widerstand wird nicht weggelassen.

Mini-Challenge: Blinken beim Drücken anhalten

const int BTN = 4;
void setup() {
  pinMode(BTN, INPUT_PULLUP);
  pinMode(LED_BUILTIN, OUTPUT);
}
void loop() {
  while (digitalRead(BTN) == HIGH) {
    digitalWrite(LED_BUILTIN, HIGH);
    delay(200);
    digitalWrite(LED_BUILTIN, LOW);
    delay(200);
  }
  digitalWrite(LED_BUILTIN, LOW);
}

Frei blinkt die eingebaute LED mit 200 ms an und 200 ms aus. Bei anhaltendem LOW verlässt der Sketch die Schleife und setzt die LED auf LOW. Nach Loslassen beginnt der nächste loop-Durchlauf erneut mit Blinken. Der Tastenzustand wird nur einmal je Blinkperiode geprüft; eine Reaktion kann fast 400 ms dauern, ein kurzer Druck vollständig übersehen werden. Während delay wird dieser Eingang nicht neu abgefragt.

13.3/12.2 enthält statt der Zeitstempelausgabe die Ausgabe von jetzt vor dem Warten auf Loslassen und bis jetzt danach. In den RGB-Schleifen entstehen zuerst (0,0,0), (0,0,1), (0,0,2). Auf (0,0,255) folgt (0,1,0). Beim Ende der inneren Schleife wird g erhöht und b für den neuen Durchlauf auf 0 gesetzt; nach allen g-Werten wird r erhöht und g neu initialisiert.

Das Pudding-Modell beginnt mit Mischen, Anrühren, Milch aufkochen und einmaliger Pulverzugabe. Danach wird geprüft, ob der Pudding kocht: Nein → rühren und weiter erhitzen → erneut prüfen; Ja → abfüllen/kalt stellen → Ende. Eine Pulverzugabe innerhalb des Rücksprungs würde die Zutatenmenge jedes Mal verändern.

  7. In die Glasschale füllen, kalt stellen.
  8. Ende.

Nur Rühren, Erhitzen und erneutes Prüfen gehören in die Wiederholung. Wiederholte Pulverzugabe würde die Rezeptmenge verändern. Dies ist ein vereinfachtes Ablaufmodell; ein tatsächliches Kochrezept enthält genauere Zeit- und Sicherheitsschritte.

Einstiegsplan und Spickzettel

Start (Oval) → LED einschalten (Rechteck) → 300 ms warten (Rechteck) → LED ausschalten (Rechteck) → Ende (Oval). Eine vorgeschaltete Raute „Taster gedrückt?“ führt auf dem Ja-Weg zur Einschaltfolge; der Nein-Weg kann direkt zu „LED aus“ und Ende führen. Bei einem wiederholten Test wird ein Rücksprung vor die Tasterprüfung eingezeichnet. Eine Ein-/Ausgabe kann als Parallelogramm dargestellt werden. Wichtig sind eindeutige Zweigbeschriftungen und Pfeile.

Übung: Vom Plan zum ausführbaren Sketch

const int BTN = 4;
void setup() {
  pinMode(BTN, INPUT_PULLUP);
  pinMode(LED_BUILTIN, OUTPUT);
  digitalWrite(LED_BUILTIN, LOW);
  while (digitalRead(BTN) == HIGH) {}
  for (int i = 0; i < 5; i++) {
    digitalWrite(LED_BUILTIN, HIGH);
    delay(300);
    digitalWrite(LED_BUILTIN, LOW);
    delay(300);
  }
}
void loop() {}

Taster D4/GND, eingebaute LED. Nach einem Druck werden genau fünf Impulse à 300 ms an/300 ms aus erzeugt. Danach bleibt die LED aus; ein weiterer oder langer Druck startet die Folge nicht erneut, weil alles einmal in setup steht. Reset beginnt wieder beim Warten. Für den Transfer wird i < 5 in i < 3 geändert, sodass genau drei Impulse entstehen.

Inbetriebnahmeprotokoll 14.1–14.3

Eine mögliche Antwort

Eine mögliche, ausdrücklich angenommene Konfiguration ist ein 5-V-16×2-LCD mit zum verlinkten LiquidCrystal_I2C-Quellcode passender Bibliothek und einem Scannerfund 0x27. Am Uno R3: GND→GND, VCC→5 V, SDA→A4/SDA, SCL→A5/SCL. Bibliotheksautor und installierte Version sowie ein realer Scannerfund müssen an der tatsächlich vorhandenen Installation abgelesen werden; hier wird keine Installation oder Messung behauptet.

setCursor(3,0) beginnt an der vierten Stelle der ersten Zeile, setCursor(0,1) links in der zweiten. millis liefert Millisekunden. noBacklight schaltet das Licht aus, löscht aber den Zeicheninhalt nicht; backlight schaltet es wieder ein. Häufiges clear kann flackern. Wird LANGER TEXT ohne Löschen durch KURZ ersetzt, bleibt KURZER TEXT stehen; die kürzere Ausgabe überschreibt nur vier Zeichen. Auffüllen bis zur Zeilenbreite entfernt den Rest.

Die Fehlersuche prüft Versorgung, gemeinsame Masse, SDA/SCL und Kontrast, danach Scanneradresse und passende Bibliotheks-API samt Beispiel. Ein leuchtendes Display bestätigt weder richtige Adresse noch korrekte Initialisierung.

Verständnisfragen - Displays

Eine mögliche Antwort
  1. Ein Zeichen-LCD zeigt Zeichen in festen Positionen; ein Grafik-OLED kann einzelne Bildpunkte und Grafiken darstellen. Die konkreten Möglichkeiten hängen vom Modell ab.
  2. 16×2 bedeutet zwei Zeilen mit je 16 Zeichenpositionen. Links in der zweiten Zeile ist setCursor(0, 1), weil beide Koordinaten mit 0 beginnen.
  3. Ein falsch eingestellter Kontrast kann Text unsichtbar machen: Ich drehe den Kontrastregler vorsichtig. Eine falsche Adresse verhindert die Kommunikation: Ich vergleiche Scannerfund und Sketchadresse. Auch eine zur Adapterbelegung unpassende Bibliothek ist möglich; dann teste ich deren mitgeliefertes Beispiel.

14.1–14.2 LCD-Bibliothek und Anschlüsse

Voraussetzung: 5-V-I²C-LCD am Uno R3, vier Anschlüsse GND→GND, VCC→5 V, SDA→SDA/A4, SCL→SCL/A5. Die Bibliothek muss den dreiteiligen Konstruktor und init/backlight/noBacklight unterstützen; Namen allein reichen zur Auswahl nicht. Die API ist im verlinkten LiquidCrystal_I2C-Projekt dokumentiert; Autor und tatsächlich installierte Version werden lokal geprüft.

#include <Wire.h>
void setup() {
  Serial.begin(9600);
  Wire.begin();
  Serial.println("I2C-Scan");
  int gefunden = 0;
  for (int adresse = 1; adresse < 127; adresse++) {
    Wire.beginTransmission(adresse);
    if (Wire.endTransmission() == 0) {
      Serial.print("Gefunden: 0x");
      if (adresse < 16) Serial.print('0');
      Serial.println(adresse, HEX);
      gefunden++;
    }
  }
  if (gefunden == 0) Serial.println("Kein I2C-Geraet gefunden");
}
void loop() {}

Ein angenommener Scannerfund 0x27 verlangt dieselbe Adresse im Sketch; andere Funde werden entsprechend eingesetzt. Der Fund beweist nur die Erreichbarkeit am I²C-Bus, nicht automatisch eine passende Adapterbelegung. Ein vollständiger LCD-Test für die Annahme 0x27 lautet:

#include <Wire.h>
#include <LiquidCrystal_I2C.h>
LiquidCrystal_I2C lcd(0x27, 16, 2);
void setup() {
  lcd.init();
  lcd.backlight();
  lcd.setCursor(0, 0);
  lcd.print("I2C LCD ready");
}
void loop() {}

Erwartet ist I2C LCD ready in der ersten Zeile. Kompilierfehler bei init deuten auf eine andere Bibliotheks-API. Bei erfolgreichem Upload, aber fehlendem Text prüft man Kontrast, Versorgung, Datenleitungen und Adresse. Für Parallel-LCDs gilt die eigene Anschlussliste der Lernseite; sie werden mit LiquidCrystal und begin statt dem I²C-Beispiel betrieben.

14.3 LCD-Ausgabe und Hintergrundlicht

#include <Wire.h>
#include <LiquidCrystal_I2C.h>
LiquidCrystal_I2C lcd(0x27, 16, 2);
void setup() {
  lcd.init();
  lcd.backlight();
}
void loop() {
  lcd.clear();
  lcd.setCursor(3, 0);
  lcd.print("Zeit:");
  lcd.print(millis());
  delay(100);
}

Die erste Zeile beginnt an der vierten Zeichenposition mit Zeit: und einer zunehmenden Millisekundenzahl. Aktualisierung: mindestens etwa 100 ms plus Übertragungsaufwand. setCursor(0,1) verschiebt die Ausgabe links in die zweite Zeile. Der Lichttest nach init lautet beispielsweise:

lcd.backlight();
lcd.print("Lichttest");
delay(1000);
lcd.noBacklight();
delay(1000);
lcd.backlight();
delay(1000);

Dies ist ein in setup einzufügender Abschnitt, kein eigener Sketch. Er schaltet nur das Hintergrundlicht; der Text bleibt gespeichert. Häufiges clear kann sichtbares Flackern verursachen. Ohne clear erzeugt LANGER TEXT, gefolgt von KURZ an derselben Position, KURZER TEXT. Mit Leerzeichen bis zur Zeilenbreite werden Restzeichen überschrieben. millis misst keine Sekunden; für Sekunden wäre beispielsweise millis()/1000 nötig.

Mini-Challenge: Statusanzeige

#include <Wire.h>
#include <LiquidCrystal_I2C.h>
LiquidCrystal_I2C lcd(0x27, 16, 2);
void setup() {
  pinMode(4, INPUT_PULLUP);
  lcd.init();
  lcd.backlight();
}
void loop() {
  bool gedrueckt = digitalRead(4) == LOW;
  lcd.setCursor(0, 0);
  lcd.print(gedrueckt ? "Ampel: GRUEN    " : "Ampel: ROT      ");

  lcd.print(gedrueckt ? "Taster:GEDRUECKT" : "Taster:FREI     ");

Für eine tatsächlich bestätigte Adresse wird 0x27 entsprechend ersetzt. Ohne Tastendruck: Ampel: ROT und Taster:FREI. Gedrückt: Ampel: GRUEN und Taster:GEDRUECKT. Danach wieder ROT/FREI, ohne alte Restzeichen. GELB wird durch Austausch des festen 16-Zeichen-Texts zu Ampel: GELB mit fünf folgenden Leerzeichen getestet. Die erste Zeile ist 16 Zeichen lang, die zweite wird mindestens bis zur vorherigen Textlänge überschrieben. Die 50-ms-Pause begrenzt die Aktualisierungsrate, bestätigt aber keinen über eine Zeit stabilen Kontaktzustand und genügt nicht zur sicheren Ereigniszählung. Die Anzeige ist keine vollständige Ampelsteuerung.

15. Motoren steuern

Motorprotokoll 15.1–15.2

Eine mögliche Antwort

Codeanalyse unter der Annahme einer geeigneten L298N-Platine mit Schutzdioden und dazu passenden Motoren: D3/D4→IN1/IN2 für Motor links A; D7/D8→IN3/IN4 für rechts B; D5→ENA und D6→ENB bei entfernten Enable-Jumpern. Uno-GND, Treiber-GND und Minus der externen Motorversorgung sind verbunden. GPIOs speisen keinen Motor. Die tatsächliche zulässige Motor-/Modulspannung, der Anlaufstrom und die Reglerjumperstellung sind aus den Unterlagen der vorhandenen Bauteile zu bestimmen; ohne benannten Modultyp ist keine universelle 5V-EN-Stellung korrekt.

15.1: HIGH/LOW bei aktivem ENA treibt an, HIGH/HIGH bremst zwei Sekunden. ENA = 0 deaktiviert die Brücke, sodass der Motor auslaufen kann. Der sichtbare Unterschied hängt von Trägheit und Last ab und wird ohne Hardware nicht als Beobachtung behauptet.

15.2: vorwaerts fährt beide vorwärts, rueckwaerts beide rückwärts. linksVor treibt nur links vorwärts und bremst rechts, rechtsVor treibt nur rechts und bremst links, stopp bremst hier ausdrücklich beide bei aktivierten Enable-Eingängen. Der auslaufende stopp im Motorenmodul schaltet dagegen die Enable-Eingänge ab. Bei einem Fahrzeug bedeutet linkes Rad vorwärts und rechtes Rad gebremst typischerweise eine Rechtskurve. Eine Polungskorrektur dreht genau den falsch laufenden Motor um, bei abgezogener Versorgung; alternativ wird seine Logik überall konsequent angepasst.

Verständnisfragen - Motoren

Eine mögliche Antwort
  1. Ein Motor kann besonders beim Anlaufen oder Blockieren mehr Strom benötigen, als ein GPIO liefern darf. Induktive Wicklungen erzeugen beim Schalten Spannungsspitzen. Deshalb steuern GPIOs nur eine geeignete Treiberstufe; der Motorstrom stammt aus einer separaten passenden Versorgung.
  2. Ein DC-Motor dreht kontinuierlich; ein üblicher Positionsservo fährt einen Sollwinkel an. Ein Schrittmotor bewegt sich in diskreten Schritten.
  3. Freilaufpfade führen den Wicklungsstrom beim Schalten weiter und begrenzen Spannungsspitzen. Bei einer umpolbaren Brücke muss dies für beide Stromrichtungen funktionieren. Eine einzelne Diode quer zum Motor würde bei einer der Polaritäten leitend; sie ist dafür ungeeignet. Die L298N-Platine muss die zur Brücke passenden Schutzdioden enthalten.

Multiple Choice - Motoren (mehrere Antworten möglich)

1) Welche Aussagen zu Motoren sind richtig?

Motoren erzeugen Bewegung; Motoren benötigen oft mehr Strom; Motoren brauchen Schutzbeschaltung

Motoren erzeugen Bewegung, brauchen Strom und Schutzbeschaltung.

2) Wozu dient PWM bei Motoren?

Steuerung der Geschwindigkeit

PWM verändert das Tastverhältnis und kann damit die Drehzahl beeinflussen. Eine verlässliche Strombegrenzung benötigt zusätzliche Messung und Regelung; PWM allein bietet sie nicht.

3) Welche Bauteile werden häufig zur Motorsteuerung genutzt?

Transistor; Motortreiber-Modul; Freilaufdiode

Transistor, Motortreiber und Freilaufdiode sind typische Bauteile.

15.1 Motor einschalten und bremsen

const int IN1 = 3, IN2 = 4, ENA = 5;
void setup() {
  pinMode(ENA, OUTPUT);
  digitalWrite(ENA, LOW);
  pinMode(IN1, OUTPUT);
  pinMode(IN2, OUTPUT);
}
void loop() {
  digitalWrite(IN1, HIGH);
  digitalWrite(IN2, LOW);
  analogWrite(ENA, 255);
  delay(2000);
  digitalWrite(IN1, HIGH);
  digitalWrite(IN2, HIGH);
  delay(2000);
}

Motor A (links) liegt an OUT1/OUT2, D3/D4 an IN1/IN2, D5 an ENA bei entferntem ENA-Jumper. Externe passende Motorversorgung und gemeinsame Masse sind erforderlich; die Modul-Logikversorgung folgt der konkreten Herstelleranleitung. Motorstrom fließt nicht aus GPIOs.

ENA = 255 und HIGH/LOW treibt zwei Sekunden in einer Richtung an. HIGH/HIGH bei weiter aktivem ENA bremst danach zwei Sekunden. Beim Vergleich wird in der zweiten Phase zusätzlich analogWrite(ENA, 0) ausgeführt: Dann deaktiviert die Brücke und der Motor kann auslaufen. Im nächsten loop-Durchlauf setzt der vorhandene erste Abschnitt ENA wieder auf 255. Ob Auslaufen sichtbar länger dauert, hängt von der tatsächlichen Mechanik ab.

15.2 Zwei Motoren und Bewegungsfunktionen

const int ENA = 5, ENB = 6;
void setzen(int a, int b, int c, int d) {
  digitalWrite(3, a); digitalWrite(4, b);
  digitalWrite(7, c); digitalWrite(8, d);
}
void vorwaerts() { setzen(HIGH, LOW, HIGH, LOW); }
void rueckwaerts() { setzen(LOW, HIGH, LOW, HIGH); }
void linksVor() { setzen(HIGH, LOW, HIGH, HIGH); }
void rechtsVor() { setzen(HIGH, HIGH, HIGH, LOW); }
void stopp() { setzen(HIGH, HIGH, HIGH, HIGH); }
void setup() {
  pinMode(ENA, OUTPUT); pinMode(ENB, OUTPUT);
  digitalWrite(ENA, LOW); digitalWrite(ENB, LOW);
  pinMode(3, OUTPUT); pinMode(4, OUTPUT);
  pinMode(7, OUTPUT); pinMode(8, OUTPUT);
  stopp();
  analogWrite(ENA, 255); analogWrite(ENB, 255);
}
void loop() {
  vorwaerts(); delay(2000);
  stopp(); delay(1000);
  rueckwaerts(); delay(2000);
  stopp(); delay(1000);
  linksVor(); delay(1000);
  stopp(); delay(1000);
  rechtsVor(); delay(1000);
  stopp(); delay(1000);
}

Zuordnung: links A an D3/D4 und ENA D5; rechts B an D7/D8 und ENB D6. Beide Enable-Jumper werden entfernt. Annahme: HIGH/LOW bedeutet am jeweiligen eingebauten Motor vorwärts; bei falscher Richtung werden spannungslos dessen Leitungen getauscht oder alle zugehörigen Logikzustände angepasst.

linksVor bezeichnet das linke Rad, nicht eine Linkskurve: Bei üblichem Differentialantrieb entsteht daraus eine Rechtskurve. stopp bremst in diesem Versuch bei aktivierten Enable-Eingängen beide Motoren; die Zwischenstopps bremsen vor dem Richtungswechsel. Mini-Challenge: Motor nur beim Halten mit PWM-Rampe

const int BTN = 2, IN1 = 3, IN2 = 4, ENA = 5;
int pwm = 0;
unsigned long zuletzt = 0;
void setup() {
  pinMode(BTN, INPUT_PULLUP);
  pinMode(ENA, OUTPUT);
  digitalWrite(ENA, LOW);
  pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);
}
void loop() {
  if (digitalRead(BTN) == LOW) {
    if (millis() - zuletzt >= 20) {
      zuletzt = millis();
      if (pwm < 255) pwm += 5;
    }
  } else {
    pwm = 0;
    zuletzt = millis();
  }
  analogWrite(ENA, pwm);
}

Taster D2/GND, Motor ausschließlich über L298N-Brücke A mit IN1 D3, IN2 D4 und ENA D5, ENA-Jumper entfernt. Der zweite Motor ist für diesen Versuch nicht versorgt. Ohne Druck bleibt ENA bei 0. Beim Halten wächst pwm in 5er-Schritten pro mindestens 20 ms bis 255; nach ungefähr 1,02 s ist der Maximalwert erreicht. Beim Loslassen werden pwm und ENA sofort auf 0 gesetzt: Die Brücke wird deaktiviert, der Motor kann mechanisch nachlaufen. Er kann wegen Haftreibung erst ab einem Mindestwert anlaufen; eine gleichmäßige Drehzahlrampe wird nicht garantiert. PWM liefert keine eigenständige Strombegrenzung. Ein rastender Ein-/Aus-Modus würde eine gespeicherte Zustandsvariable und entprellte Ereignisse benötigen.
