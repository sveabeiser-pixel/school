11. Eingaben mit Tastern - Der Arduino reagiert

Ablaufspur: INPUT_PULLUP richtig herum denken

TasterVerbindungdigitalRead(BTN)== LOW
nicht gedrücktintern mit HIGH verbundenHIGHfalsch
gedrücktmit GND verbundenLOWwahr

Wahr oder falsch?

Wahr. Bei INPUT_PULLUP bedeutet gedrückt meistens LOW.

Richtig. Der Taster verbindet den Eingang beim Drücken mit GND. Deshalb liest der Arduino LOW.

Verständnisfragen - Taster

Eine mögliche Antwort
  1. Ein Taster kehrt beim Loslassen in seine Ausgangsstellung zurück. Ein Schalter bleibt normalerweise in seiner gewählten Stellung.
  2. Ein offener Eingang braucht einen definierten Ruhepegel. Ein Pullup verbindet ihn über einen Widerstand mit der Versorgung, ein Pulldown mit GND. Dadurch wird ein undefinierter, störanfälliger Eingang verhindert.
  3. Bei INPUT_PULLUP liest der Arduino ohne Druck HIGH. Ein gedrückter Taster verbindet den Eingang mit GND: Er wird als LOW gelesen.

Multiple Choice - Eingaben (mehrere Antworten möglich)

1) Was trifft auf digitale Eingänge zu?

Sie kennen nur LOW oder HIGH; Man liest sie mit digitalRead()

Digitale Eingänge kennen LOW/HIGH und werden mit digitalRead() gelesen.

2) Wozu dient INPUT_PULLUP?

Der Eingang bekommt einen definierten Grundzustand; Man spart oft einen externen Widerstand

INPUT_PULLUP setzt einen Grundzustand und spart oft den externen Widerstand.

3) Welche Aussage ist bei INPUT_PULLUP richtig?

Nicht gedrückt = HIGH; Gedrückt = LOW

Bei INPUT_PULLUP ist nicht gedrückt = HIGH und gedrückt = LOW.

11.1 Tasterwerte

Mit INPUT_PULLUP liegt der freie Eingang auf HIGH; digitalRead(4) liefert 1. Verbindet der gedrückte Taster Pin 4 mit GND, liefert die Abfrage LOW beziehungsweise 0. Die Schaltung arbeitet damit aktiv-low.

11.2 LED mit Taster schalten

void setup() {
  pinMode(4, INPUT_PULLUP);
  pinMode(9, OUTPUT);
}
void loop() {
  if (digitalRead(4) == LOW) {
    digitalWrite(9, HIGH);
  } else {
    digitalWrite(9, LOW);
  }
}

Der Taster liegt zwischen Pin 4 und GND; die LED an Pin 9 besitzt einen Vorwiderstand.

11.3 Zwei Taster für zwei Tonhöhen

void setup() {
  pinMode(4, INPUT_PULLUP);
  pinMode(5, INPUT_PULLUP);
}
void loop() {
  if (digitalRead(4) == LOW) {
    tone(11, 220);
  } else if (digitalRead(5) == LOW) {
    tone(11, 880);
  } else {
    noTone(11);
  }
}

Beide Taster verbinden ihren Eingang mit GND. Sind beide gedrückt, hat in dieser Lösung Taster 4 Vorrang. Ohne Tastendruck ist der Piezo stumm.

11.4 Tastendrücke zählen

unsigned long anzahl = 0;
void setup() {
  pinMode(4, INPUT_PULLUP);
  Serial.begin(9600);
}
void loop() {
  if (digitalRead(4) == LOW) {
    delay(20);
    if (digitalRead(4) == LOW) {
      anzahl++;
      Serial.println(anzahl);
      while (digitalRead(4) == LOW) {}
      delay(20);
    }
  }
}

Eine einfache, blockierende Lösung: Ein bestätigter Druck erhöht den Zähler einmal. Danach wartet das Programm auf das Loslassen. Die Wartezeiten mindern Kontaktprellen. Ein bloßes if (Taste gedrückt) mit anzahl++ würde bei gehaltenem Taster viele Durchläufe zählen. Für besonders stark prellende Taster ist eine Prüfung durchgehend stabiler Zustände zuverlässiger.

11.5 Übertragungszeit serieller Zeichen

Bei 9600 Baud und dem üblichen Format 8N1 werden pro Zeichen 10 Bits übertragen: 10 / 9600 s ≈ 1,04 ms. Eine mehrstellige Zahl sowie die beiden Zeilenendezeichen brauchen entsprechend länger. Wiederholte Ausgaben von millis() messen nicht direkt die Zeit eines einzelnen Zeichens: millis() hat Millisekundenauflösung und Serial puffert Ausgaben. Für eine Messung vieler Zeichen wird der Puffer vorher geleert, vor der Ausgabe micros() erfasst und nach Serial.flush() erneut gemessen. Die Gesamtzeit geteilt durch die Zeichenanzahl nähert die Zeit pro Zeichen an.

Sicherung: while

Eine while-Schleife läuft, solange ihre Bedingung wahr ist. Damit sie enden kann, muss sich etwas im Ablauf verändert, sodass die Bedingung irgendwann falsch wird.

Verständnisfragen - while

Eine mögliche Antwort
  1. for bündelt Initialisierung, Bedingung und Zählschritt in einer Schleifenkopfzeile. while prüft eine Bedingung; eine nötige Zustandsänderung oder neue Messung steht ausdrücklich im Rumpf.
  2. while eignet sich, wenn die Wiederholungszahl von einer Bedingung abhängt, etwa solange ein Taster nicht gedrückt ist. Während der Schleife muss der Zustand neu geprüft werden.
  3. Eine Endlosschleife endet nicht, weil ihre Bedingung dauerhaft wahr bleibt. Sie entsteht zum Beispiel, wenn der Zähler nicht erhöht oder der Sensorwert im Rumpf nicht neu gelesen wird.

Multiple Choice - while (mehrere Antworten möglich)

1) Eine while-Schleife läuft ...

so lange, wie die Bedingung wahr ist; bis die Bedingung falsch wird

while läuft, solange die Bedingung wahr ist, und endet, wenn sie falsch wird.

2) Welche Situationen passen gut zu while?

Warten, bis ein Taster gedrückt wird; Wiederholen, bis ein Grenzwert erreicht ist

while nutzt man, wenn nicht vorher feststeht, wie oft etwas passiert.

3) Wie vermeidet man Endlosschleifen?

Die Bedingung muss irgendwann falsch werden können; In der Schleife muss sich etwas ändern (z. B. Variable); Man sollte prüfen, ob die Bedingung erreichbar ist

Die Bedingung muss erreichbar sein und sich in der Schleife ändern können.

12.1 Zwei while-Schleifen

Die erste Schleife gibt 1, 2, 3, …, 99 aus; danach gilt x = 100. Die Bedingung 2 < 5 der zweiten Schleife ist immer wahr. Deshalb werden ständig Ausrufezeichen ausgegeben und setup() endet nie; loop() wird nicht erreicht. Für eine tatsächliche lesbare Ausgabe muss zusätzlich Serial.begin(9600) in setup() stehen und der Monitor dieselbe Baudrate verwenden.

12.2 Gedrückt und losgelassen

Bei INPUT_PULLUP wartet while (digitalRead(4) == HIGH) {} auf das Drücken. Dann erscheint von jetzt. Die nächste Schleife wartet bei LOW auf das Loslassen; danach erscheint bis jetzt. Dieser Ablauf wiederholt sich. Serial.print() fügt keinen Zeilenumbruch an; die Texte stehen ohne zusätzliche Formatierung direkt hintereinander. Eine Zeitdauer wird noch nicht berechnet.

12.3 Tonhöhe schrittweise verändern

int frequenz = 440;
void setup() {
  pinMode(4, INPUT_PULLUP);
  pinMode(5, INPUT_PULLUP);
}
void loop() {
  if (digitalRead(4) == LOW) {
    delay(20);
    if (digitalRead(4) == LOW) {
      if (frequenz < 2000) frequenz++;
      while (digitalRead(4) == LOW) {}
      delay(20);
    }
  } else if (digitalRead(5) == LOW) {
    delay(20);
    if (digitalRead(5) == LOW) {
      if (frequenz > 100) frequenz--;
      while (digitalRead(5) == LOW) {}
      delay(20);
    }
  }
  tone(11, frequenz);
}

Pro bestätigtem Druck steigt oder sinkt die Frequenz um 1 Hz. Die Grenzprüfungen verhindern unzulässige Werte; das Warten auf das Loslassen verhindert mehrfaches Zählen eines gehaltenen Tasters.

13.1 Flussdiagramm als Sketch

void setup() {
  Serial.begin(9600);
  int x = 10;
  while (x < 100) {
    Serial.println(x);
    x = x + 2;
  }
}
void loop() {}

Die Ausgabe lautet 10, 12, 14, …, 98: insgesamt 45 Zahlen. Anschließend ist x = 100, die Bedingung ist falsch und die Schleife endet.

13.2 Tastendruck und Zeitstempel

void setup() {
  pinMode(4, INPUT_PULLUP);
  Serial.begin(9600);
}
void loop() {
  while (digitalRead(4) == HIGH) {}
  Serial.println(millis());
  while (digitalRead(4) == LOW) {}
}

Das Programm wartet auf einen Tastendruck, gibt einmal die seit dem Start verstrichenen Millisekunden aus und wartet auf das Loslassen. Dann beginnt der nächste Durchlauf. Das bildet das gezeigte Diagramm ab; für reale Taster sollte zusätzlich entprellt werden.

14. LCD-Displays - Texte anzeigen

Verständnisfragen - Displays

Eine mögliche Antwort
  1. Ein Zeichen-LCD zeigt Zeichen in festen Positionen; ein Grafik-OLED kann einzelne Bildpunkte und damit auch Grafiken darstellen. Die konkreten Möglichkeiten hängen vom Modell ab.
  2. 16×2 bedeutet zwei Zeilen mit jeweils 16 Zeichenpositionen.
  3. Der Kontrast kann falsch eingestellt sein. Außerdem können Initialisierung, Versorgung oder Anschlussbelegung unpassend sein; bei I²C ist auch eine falsche Adresse möglich. Ich prüfe zuerst ein bekanntes Testprogramm und die passenden Einstellungen.

Multiple Choice - LCD (mehrere Antworten möglich)

1) Welche Display-Typen gibt es häufig?

Zeichen-LCD (16x2 / 20x4); OLED; TFT

Zeichen-LCD, OLED und TFT sind typische Display-Typen.

2) Was stimmt zu I2C-LCDs?

Man braucht meist weniger Kabel als bei Parallel; Typisch sind SDA und SCL; Die I2C-Adresse kann je nach Modul unterschiedlich sein

I2C nutzt SDA/SCL, braucht weniger Kabel und die Adresse kann variieren.

3) Warum sieht man manchmal nichts auf dem LCD?

Kontrast ist falsch eingestellt; Hintergrundbeleuchtung/Power fehlt; falsche I2C-Adresse / falsche Pins

Kontrast, Backlight/Power oder die Adresse/Pins sind häufige Ursachen.

14.1–14.2 LCD-Bibliothek und Anschlüsse

Eine zum Beispielcode passende LiquidCrystal_I2C-Bibliothek stellt das Objekt sowie init(), setCursor() und print() bereit. Bei einem üblichen 5-V-I²C-LCD am Uno: GND an GND, VCC an 5 V, SDA an SDA beziehungsweise A4 und SCL an SCL beziehungsweise A5. Andere Boards und Module können andere Pins oder Versorgungsspannungen benötigen. Die I²C-Adresse muss zur tatsächlichen Hardware passen; 0x27 ist die Annahme des Beispiels.

14.3 LCD-Ausgabe und Hintergrundlicht

#include <Wire.h>
#include <LiquidCrystal_I2C.h>
LiquidCrystal_I2C lcd(0x27, 16, 2);

void setup() {
  lcd.init();
  lcd.backlight();
}
void loop() {
  lcd.clear();
  lcd.setCursor(3, 0);
  lcd.print("Zeit: ");
  lcd.print(millis());
  delay(100);
}

Für eine Bibliothek mit dieser API: Die erste Zeile beginnt ab der vierten Spalte mit Zeit: und der Zahl der Millisekunden seit dem Programmstart. Die Ausgabe wird ungefähr alle 100 ms erneuert; clear() kann sichtbares Flackern erzeugen. backlight() schaltet das Hintergrundlicht an, noBacklight() aus. Der gespeicherte Text wird dadurch nicht gelöscht. Eine geänderte Position lässt sich etwa durch setCursor(0, 1) auf den Anfang der zweiten Zeile setzen.

15. Motoren steuern

Verständnisfragen - Motoren

Eine mögliche Antwort
  1. Der Motor benötigt mehr Strom, als ein Arduino-Pin liefern darf, und kann induktive Spannungsspitzen erzeugen. Er wird deshalb über einen geeigneten Treiber angeschlossen.
  2. Ein Gleichstrommotor dreht kontinuierlich, ein Servo fährt typischerweise einen vorgegebenen Winkel an. Ein Schrittmotor bewegt sich dagegen in diskreten Schritten.
  3. Beim Abschalten eines induktiven Verbrauchers bietet die Freilaufdiode einen Pfad für den weiterfließenden Strom und begrenzt die Spannungsspitze. Bei Motorbrücken muss die Schutzbeschaltung zur Treiberschaltung passen.

Multiple Choice - Motoren (mehrere Antworten möglich)

1) Welche Aussagen zu Motoren sind richtig?

Motoren erzeugen Bewegung; Motoren benötigen oft mehr Strom; Motoren brauchen Schutzbeschaltung

Motoren erzeugen Bewegung, brauchen Strom und Schutzbeschaltung.

2) Wozu dient PWM bei Motoren?

Steuerung der Geschwindigkeit; Strombegrenzung

PWM steuert die Geschwindigkeit und kann den effektiven Strom beeinflussen.

3) Welche Bauteile werden häufig zur Motorsteuerung genutzt?

Transistor; Motortreiber-Modul; Freilaufdiode

Transistor, Motortreiber und Freilaufdiode sind typische Bauteile.

15.1 Motor einschalten und bremsen

void setup() {
  pinMode(3, OUTPUT);
  pinMode(4, OUTPUT);
}
void loop() {
  digitalWrite(3, HIGH);
  digitalWrite(4, LOW);
  delay(2000);
  digitalWrite(3, HIGH);
  digitalWrite(4, HIGH);
  delay(2000);
}

Bei der gezeigten H-Brücke mit aktiviertem Enable-Eingang dreht der Motor zunächst zwei Sekunden in einer Richtung. Beide Steuereingänge auf HIGH bremsen anschließend zwei Sekunden; das ist kein Freilauf. Motoren werden über den Treiber und eine geeignete Motorversorgung betrieben, nicht direkt aus GPIOs. Arduino und Treiber benötigen eine gemeinsame Masse.

15.2 Zwei Motoren und Bewegungsfunktionen

// Rechter Motor: 3/4; linker Motor: 5/6
void setzen(int a, int b, int c, int d) {
  digitalWrite(3, a); digitalWrite(4, b);
  digitalWrite(5, c); digitalWrite(6, d);
}
void vor() { setzen(HIGH, LOW, HIGH, LOW); }
void rueck() { setzen(LOW, HIGH, LOW, HIGH); }
void links() { setzen(HIGH, LOW, HIGH, HIGH); }
void rechts() { setzen(HIGH, HIGH, HIGH, LOW); }
void stopp() { setzen(HIGH, HIGH, HIGH, HIGH); }
void setup() {
  for (int pin = 3; pin <= 6; pin++) {
    pinMode(pin, OUTPUT);
  }
}
void loop() {
  vor(); delay(2000);
  stopp(); delay(500);
  rueck(); delay(2000);
  stopp(); delay(500);
  links(); delay(1000);
  stopp(); delay(500);
  rechts(); delay(1000);
  stopp(); delay(1000);
}

Annahme: HIGH/LOW entspricht bei beiden eingebauten Motoren der Fahrtrichtung vorwärts und die Enable-Eingänge sind aktiviert. Falls ein Motor andersherum eingebaut oder angeschlossen ist, muss dessen Zuordnung umgekehrt werden. links() treibt nur rechts vorwärts und bremst links; rechts() macht es umgekehrt. stopp() bremst beide Motoren.
