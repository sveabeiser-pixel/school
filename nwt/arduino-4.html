11. Eingaben mit Tastern - Der Arduino reagiert

Ein technisches System wird interessant, sobald es seine Umgebung wahrnimmt. Du liest Tasterzustände ein, triffst Entscheidungen und planst komplexere Abläufe erst als Modell und dann als Code.

EntscheidungDie Bedingung als wahr oder falsch auswerten.
AusgabeNur den gewählten Programmzweig verfolgen.

Dein Arbeitsplatz: aufbauen, hochladen, prüfen

Du arbeitest hier mit einem Arduino Uno R3 (5 V), Steckbrett und USB-Datenkabel. Für die Versuche brauchst du zwei Taster, eine LED mit 330-Ω-Vorwiderstand, eine RGB-LED mit gemeinsamer Kathode und drei Vorwiderständen, einen geprüften kleinen passiven Lautsprecher mit 330-Ω- oder 1-kΩ-Serienwiderstand (alternativ einen passiven Piezo) sowie später ein 5-V-I²C-LCD (16×2) und eine zum Motor passende L298N-Treiberplatine. Führe die Aufbauten nacheinander aus: Pins werden in späteren Versuchen neu belegt.

  1. Ziehe vor jedem Umbau USB und die externe Versorgung ab. Kontrolliere am vierbeinigen Taster mit Durchgangsprüfung bei abgezogener Versorgung, welche zwei Kontakte erst beim Drücken verbunden werden. Zwei bereits intern verbundene Beine würden den Eingang dauerhaft auf LOW legen.
  2. Öffne die Arduino IDE. Lege für jeden Versuch mit Datei → Neu einen eigenen Sketch an und speichere ihn beispielsweise als Aufgabe_11_1. Ersetze den gesamten Vorgabetext durch den jeweiligen vollständigen Sketch; füge nicht mehrere setup()- oder loop()-Funktionen zusammen.
  3. Verbinde den Uno per USB. Wähle im Boardwähler beziehungsweise unter Werkzeuge → Board den Arduino Uno und unter Werkzeuge → Port seinen Anschluss. Wenn der Port unklar ist, vergleiche die Liste vor und nach dem Anstecken. Fehlt er, prüfe Datenkabel und USB-Anschluss.
  4. Klicke Überprüfen, behebe die erste gemeldete Fehlerstelle und klicke danach Hochladen. Erst die Erfolgsmeldung beim Hochladen bestätigt, dass das neue Programm auf dem Board läuft.
  5. Öffne für Serial-Versuche den seriellen Monitor und stelle 9600 Baud ein. Ein Reset startet den Versuch erneut; beim Öffnen des Monitors kann der Uno ebenfalls neu starten. Bei Uploadfehlern prüfst du Board, Port und Kabel, bei falschem Verhalten anschließend Code und Verdrahtung.

Notiere zu jedem Auftrag zuerst deine Erwartung, dann deinen tatsächlichen Test und deine Beobachtung. Bewahre den Sketch in der IDE auf und übernimm Code oder Dateiname mit der Auswertung in die vorgesehenen Antwortfelder. Am Ende öffnest du Ergebnisse & Abschluss, ergänzt deinen Namen und exportierst deine Antworten.

Was ist ein Taster?
Der hier verwendete Schließertaster verbindet seine beiden Kontaktseiten nur, solange du ihn gedrückt hältst. Nach dem Loslassen öffnet er wieder.
Damit kann der Arduino auf Eingaben reagieren - ähnlich wie bei einer Tastatur.
Digitale Eingänge
Ein digitaler Eingang kennt nur zwei Zustände:
  • LOW (0) - niedriger Spannungspegel, nahe GND
  • HIGH (1) - hoher Spannungspegel
Du liest das mit digitalRead(pin). Ob HIGH oder LOW „gedrückt“ bedeutet, legt die Schaltung fest, nicht der Zahlenwert allein.
So wird der Taster angeschlossen
Der Taster wird nicht zusammen mit der LED in denselben Stromkreis gesteckt. Er ist ein eigener Anschluss für einen Eingangspin.

Die LED gehört zum Ausgang: Der Arduino schickt dort Strom bzw. ein Signal zur Lampe.
Der Taster gehört zum Eingang: Er meldet dem Arduino nur, ob gedrückt wird oder nicht.

Bei INPUT_PULLUP steckst du den Taster meist so:
  • eine Seite des Tasters an Pin 4
  • die andere Seite an GND
Der Taster verbindet beim Drücken also Pin 4 mit GND. Die LED wird nicht direkt über den Taster geschaltet, sondern erst später im Code über ihren eigenen Ausgangspin.
Pullup / Pulldown - warum braucht man das?
Ein Eingang darf nicht "in der Luft hängen", sonst kann er zufällige Werte lesen. Darum nutzt man einen Widerstand, der den Eingang eindeutig auf LOW oder HIGH zieht.

Sehr praktisch ist der interne Pullup: 
pinMode(4, INPUT_PULLUP);
Für den hier zwischen Eingang und GND angeschlossenen Taster gilt:
  • Taster nicht gedrückt - HIGH
  • Taster gedrückt - LOW
Der Arduino liest diesen Zustand dann zum Beispiel mit digitalRead(4).
Typischer Stolperstein
Bei unserem Aufbau mit INPUT_PULLUP gilt: gedrückt = LOW, nicht gedrückt = HIGH.
Das ist kein Fehler - beim Drücken zieht der Taster den Eingang auf GND. Man muss es nur im if beachten.
Jetzt hast du das gelernt:

Der Taster liefert hier ein Eingangssignal. Mit INPUT_PULLUP und Taster nach GND bedeutet gedrückt LOW. Dein if prüft genau diese Verbindung.

Beispiel: Taster schaltet LED

Für diesen Sketch: Taster zwischen D4 und GND; D9 → 330 Ω → LED-Anode (langes Bein), LED-Kathode → GND.

const int BTN = 4;
const int LED = 9;

void setup() {
  pinMode(LED, OUTPUT);
  pinMode(BTN, INPUT_PULLUP);
}

void loop() {
  bool pressed = (digitalRead(BTN) == LOW);
  if (pressed) {
    digitalWrite(LED, HIGH);
  } else {
    digitalWrite(LED, LOW);
  }
}
Die LED leuchtet nur, wenn der Taster gedrückt wird.
Wichtig: Der Taster schaltet hier nicht direkt die LED. Er liefert nur die Information an den Arduino. Der Arduino schaltet danach die LED über den Ausgangspin ein oder aus.
Mini-Challenge - Taster als "Modus-Wechsel"
Challenge
Ziel: Wenn der Taster gedrückt ist, soll die RGB-LED z. B. grün leuchten, sonst rot.
Nutze if / else und digitalRead().

Aufbau: Trenne die Versorgung. Taster: D4 ↔ GND. Bei einer RGB-LED mit gemeinsamer Kathode kommt diese an GND. Verbinde die roten, grünen und blauen Anschlüsse jeweils über einen eigenen 330-Ω-Widerstand mit D9, D10 und D6. Bestimme die Anschlüsse mit dem Datenblatt deiner LED; die Beinlänge allein reicht nicht. Für eine gemeinsame Anode gilt dieser Sketch nicht.

IDE-Auftrag: Speichere den folgenden Sketch als RGB_Taster, lade ihn hoch und teste frei, gedrückt und wieder frei. Erkläre, warum das ein Farbwechsel während des Drückens und kein gespeicherter Umschaltmodus ist.

const int BTN = 4;
const int ROT = 9, GRUEN = 10, BLAU = 6;
void setup() {
  pinMode(BTN, INPUT_PULLUP);
  pinMode(ROT, OUTPUT);
  pinMode(GRUEN, OUTPUT);
  pinMode(BLAU, OUTPUT);
}
void loop() {
  bool gedrueckt = digitalRead(BTN) == LOW;
  analogWrite(ROT, gedrueckt ? 0 : 255);
  analogWrite(GRUEN, gedrueckt ? 255 : 0);
  analogWrite(BLAU, 0);
}

Dokumentation: Notiere Verdrahtung, Code und den Vergleich von Erwartung und Beobachtung für alle drei Testzustände. Erkläre die Abfrage des Tasters.

bedingung ? wertWennWahr : wertWennFalsch ist eine kurze Fallunterscheidung. Beispielsweise setzt die rote Ausgabe bei gedrücktem Taster 0, sonst 255.

Lösung anzeigen
Mit INPUT_PULLUP gilt: gedrückt = LOW.
Also: if (digitalRead(BTN) == LOW) { grün } else { rot }
Die Farben setzt du über analogWrite() auf die RGB-Pins.

11.1 Den Eingang im seriellen Monitor lesen

  1. Baue bei abgezogenem USB den Taster zwischen D4 und GND auf. Du benötigst mit INPUT_PULLUP keinen zusätzlichen Pullup-Widerstand.
  2. Überprüfe und lade den vollständigen Sketch hoch. Öffne den seriellen Monitor bei 9600 Baud.
  3. Sage für frei, gedrückt und wieder frei jeweils 0 oder 1 voraus. Halte den Taster zwei Sekunden gedrückt. Trenne danach bei abgezogenem USB eine Tasterleitung, verbinde USB erneut und vergleiche den offenen Eingang mit dem freien Taster.
void setup() {
  pinMode(4, INPUT_PULLUP);
  Serial.begin(9600);
}
void loop() {
  int zustand = digitalRead(4);
  Serial.println(zustand);
  delay(100);
}

Test und Reflexion: Prüfe die Materialaussage „geschlossen ergibt 0, offen ergibt 1“ mit deinem Aufbau. Erkläre den Ruhepegel durch den internen Widerstand. Ein dauerhaftes 0 deutet zum Beispiel auf zwei intern verbundene Tasterbeine hin.

11.3 Zwei Taster, zwei Tonhöhen

Aufbau: Je ein Schließertaster verbindet D4 beziehungsweise D5 mit GND. Für den leisen Tonversuch am Uno R3 verbindest du D11 → 330 Ω oder 1 kΩ → geprüfter kleiner passiver Lautsprecher → GND. Beginne mit 1 kΩ; der Serienwiderstand muss immer eingebaut bleiben. Lasse bei einem unbeschrifteten Bauteil zuerst prüfen, ob es ein passiver Lautsprecher ist. Schließe es nicht versuchsweise ohne Widerstand an. Für höhere Lautstärke brauchst du eine passende Treiberstufe. Ein passiver Piezo mit Serienwiderstand ist eine Alternative, aber keine Voraussetzung. Ein aktiver Summer erzeugt seine Tonhöhe selbst und passt nicht zu diesem Versuch.

void setup() {
  pinMode(4, INPUT_PULLUP);
  pinMode(5, INPUT_PULLUP);
}
void loop() {
  if (digitalRead(4) == LOW) {
    tone(11, 220);
  } else if (digitalRead(5) == LOW) {
    tone(11, 880);
  } else {
    noTone(11);
  }
}

IDE und Test: Lade Aufgabe_11_3 hoch. Teste keinen, nur D4, nur D5 und beide Taster. Ordne jedem Fall still/tief/hoch zu. Erkläre mit else if, welcher Taster bei gleichzeitigem Druck Vorrang hat. Tausche die Reihenfolge der Abfragen und teste deine Vorhersage.

11.4 Tastendrücke zählen: Zustand oder Ereignis?

Verwende nur den Taster D4/GND. Lade diesen absichtlich einfachen Zähler hoch und öffne den Monitor bei 9600 Baud. Vergleiche kurzes Drücken mit zwei Sekunden Halten. Zählt das Programm Tastendrücke oder Schleifendurchläufe mit gedrücktem Taster?

unsigned long anzahl = 0;
void setup() {
  pinMode(4, INPUT_PULLUP);
  Serial.begin(9600);
}
void loop() {
  if (digitalRead(4) == LOW) {
    anzahl++;
    Serial.println(anzahl);
  }
}

Verbessern nach Kapitel 12: Warte nach dem Zählen mit while (digitalRead(4) == LOW) {} auf das Loslassen. Teste fünf getrennte Betätigungen und einen langen Druck. Mechanische Kontakte können prellen: Ein Wechsel muss für eine verlässliche Zählung erst eine kurze Zeit stabil sein. Unterscheide Mehrfachzählen durch Halten von zusätzlichen Wechseln durch Prellen.

11.5 Wie lange dauert die serielle Übertragung?

Lade zuerst den Materialversuch hoch. Notiere aufeinanderfolgende Zeitstempel und ihre Differenzen. Begründe, weshalb eine ausgegebene Zahl aus mehreren Zeichen besteht und die Differenz noch keine genaue Übertragungszeit pro Zeichen ist.

void setup() {
  Serial.begin(9600);
}
void loop() {
  unsigned long m = millis();
  Serial.println(m);
}

Kontrollversuch am Uno R3: Lade nun den folgenden separaten Sketch hoch. Er misst die Übertragung von 100 gleichen Zeichen einschließlich des Leerens des Sendepuffers. Er gibt den Messwert einmal aus; Reset wiederholt die Messung. Serial.flush() wartet auf das Ende der Übertragung, nicht auf die Bildschirmdarstellung.

void setup() {
  Serial.begin(9600);
  delay(1000);
  Serial.flush();
  unsigned long start = micros();
  for (int i = 0; i < 100; i++) {
    Serial.write('A');
  }
  Serial.flush();
  unsigned long dauer = micros() - start;
  Serial.println();
  Serial.print("Mikrosekunden pro Zeichen: ");
  Serial.println(dauer / 100.0);
}
void loop() {}

Auswerten: Bei 9600 Baud und 8N1 benötigt ein Zeichen 1 Startbit + 8 Datenbits + 1 Stoppbit. Berechne 10 / 9600 Sekunden und vergleiche mit deinem Messwert. Wiederhole mit Serial.begin(19200) und 19200 Baud im Monitor. Welche Veränderung erwartest du? Dokumentiere echte Werte und mögliche Abweichungen. Dieses UART-Modell gilt hier für den Uno R3; native USB-Boards können sich anders verhalten.

12. Wiederholungen mit while: solange eine Bedingung wahr ist

Was ist eine while-Schleife?
Eine while-Schleife wiederholt einen Programmteil so lange, wie eine Bedingung wahr ist.

Merksatz: while = solange
Grundaufbau 
while (Bedingung) {
  // Code wird wiederholt
}
Wenn die Bedingung irgendwann false wird, endet die Schleife und das Programm läuft danach weiter.
Wann ist while sinnvoll?
Eine while-Schleife ist besonders sinnvoll, wenn man nicht vorher weiß, wie oft etwas wiederholt werden muss.

Beispiele:
  • Solange warten, bis ein Taster gedrückt wird
  • Solange blinken, bis eine Bedingung erfüllt ist
  • Solange Werte ausgeben, bis ein Grenzwert erreicht ist
Vergleich: for vs. while
for nutzt man meist, wenn die Anzahl der Wiederholungen fest ist (z. B. "5-mal blinken").

while nutzt man meist, wenn es heißt: „Solange eine Bedingung wahr ist“ (z. B. solange warten, wie der Taster frei ist).
Achtung: Endlosschleife
Wenn sich die Bedingung nie ändert, läuft die while-Schleife endlos. Das ist einer der häufigsten Fehler.

Prüfe immer:
  • Wird eine Variable in der Schleife verändert?
  • Kann die Bedingung überhaupt falsch werden?
Beispiel 1: Zählen bis ein Grenzwert erreicht ist

Ohne zusätzliche Bauteile: Lade diesen Sketch hoch, öffne den Monitor bei 9600 Baud und drücke Reset. Fülle zuerst die Ablaufspur aus und vergleiche danach mit der Ausgabe.

int x = 0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  while (x < 20) {
    Serial.println(x);
    x = x + 5;
  }
}
Die Schleife endet, sobald x mindestens 20 ist. Weil x global initialisiert wird, beginnt der nächste loop()-Durchlauf mit dem erreichten Wert. Es erscheint keine neue Zahlenfolge, bis du Reset drückst.
Jetzt hast du das gelernt:

while prüft vor jedem Durchgang. Ist die Bedingung schon anfangs falsch, läuft der Block kein einziges Mal. Zum späteren Verlassen muss sich eine geprüfte Größe ändern; das kann auch der erneut gelesene Tasterzustand sein.

Beispiel 2: Warten auf einen Tastendruck

Taster: D4/GND. Lade den Sketch hoch und teste Drücken, Halten und Loslassen mit dem Monitor bei 9600 Baud.

const int BTN = 4;

void setup() {
  pinMode(BTN, INPUT_PULLUP);
  Serial.begin(9600);
}

void loop() {
  while (digitalRead(BTN) == HIGH) {
    // solange nicht gedrückt (HIGH)
  }
  Serial.println("gedrueckt");
  while (digitalRead(BTN) == LOW) {
    // erst nach dem Loslassen den naechsten Druck zulassen
  }
}
Die zweite Schleife verhindert fortlaufende Ausgaben beim Halten. Prellen kann trotzdem zusätzliche Ausgaben verursachen; Aufgabe 12.3 zeigt eine Stabilitätsprüfung.
Mini-Challenge - Stoppe das Blinken mit einem Taster
Challenge
Ziel: Eine LED soll blinken, solange der Taster nicht gedrückt ist. Wenn du den Taster gedrückt hältst, soll das Blinken stoppen und die LED aus bleiben. Nach dem Loslassen beginnt es wieder. Ein kurzer Druck innerhalb einer Wartezeit kann übersehen werden.

Tipp: Nutze while und INPUT_PULLUP.

Aufbau und IDE: Nutze den Taster D4/GND und die eingebaute LED des Uno. Lade diesen vollständigen Sketch hoch. Halte den Taster länger als eine Blinkperiode gedrückt. Teste danach sehr kurze Drücke und erkläre die Verzögerung durch delay().

const int BTN = 4;
void setup() {
  pinMode(BTN, INPUT_PULLUP);
  pinMode(LED_BUILTIN, OUTPUT);
}
void loop() {
  while (digitalRead(BTN) == HIGH) {
    digitalWrite(LED_BUILTIN, HIGH);
    delay(200);
    digitalWrite(LED_BUILTIN, LOW);
    delay(200);
  }
  digitalWrite(LED_BUILTIN, LOW);
}

Notiere Code, Erwartung und Beobachtung für frei, dauerhaft gedrückt und wieder frei. Begründe, weshalb die Reaktion bis ungefähr 400 ms dauern kann und das Blinken nach dem Loslassen wieder beginnt.

Lösung anzeigen
Mit INPUT_PULLUP gilt: nicht gedrückt = HIGH, gedrückt = LOW.
Daher: while (digitalRead(BTN) == HIGH) { blinken }
Danach LED ausschalten.

Werkstatt 12: Bedingungen und Tastendruck-Ereignisse

12.1 Erreicht das Programm loop()?

Sage vor dem Hochladen voraus, welche Zahlen und Zeichen erscheinen und ob die eingebaute LED eingeschaltet wird. Dieser Sketch ergänzt das im Material fehlende Serial.begin(9600). Beobachte den Monitor kurz; lade danach einen anderen Sketch hoch, um die Endlosschleife zu ersetzen.

int x = 1;
void setup() {
  Serial.begin(9600);
  pinMode(LED_BUILTIN, OUTPUT);
  digitalWrite(LED_BUILTIN, LOW);
  while (x < 100) {
    Serial.println(x);
    x = x + 1;
  }
  while (2 < 5) {
    Serial.print("!");
  }
}
void loop() {
  digitalWrite(LED_BUILTIN, HIGH);
}

Fehler finden: Begründe, weshalb ein Reset die Endlosschleife nur neu startet. Ersetze den zweiten while-Block durch Serial.println("fertig");, lade erneut hoch und prüfe den Übergang zu loop().

12.2 Von jetzt bis jetzt

Nutze D4/GND und den seriellen Monitor bei 9600 Baud. Lies den Code vor dem Upload wie einen Ablaufplan. Sage voraus, was vor dem Drücken, beim Halten und nach dem Loslassen erscheint.

void setup() {
  pinMode(4, INPUT_PULLUP);
  Serial.begin(9600);
}
void loop() {
  while (digitalRead(4) == HIGH) {}
  Serial.print("von jetzt");
  while (digitalRead(4) == LOW) {}
  Serial.print("bis jetzt");
}

Test: Drücke, halte zwei Sekunden und lasse los. Wiederhole das. Erkläre die leeren Schleifen und die Ausgabe ohne Zeilenumbruch. Ersetze testweise beide print durch println. Misst das Programm bereits eine Zeitdauer? Begründe.

12.3 Feintuning: genau 1 Hz pro Betätigung

Aufbau: Taster D4/GND und D5/GND; D11 → 330 Ω oder 1 kΩ → geprüfter kleiner passiver Lautsprecher → GND wie in 11.3, alternativ ein passiver Piezo. Lade den Sketch als Aufgabe_12_3 hoch. Er startet bei 440 Hz; D4 erhöht, D5 senkt die Frequenz um 1 Hz innerhalb 100–2000 Hz.

int frequenz = 440;

void warteStabil(int pin, int pegel) {
  unsigned long seit = millis();
  while (millis() - seit < 20) {
    if (digitalRead(pin) != pegel) seit = millis();
  }
}

void setup() {
  pinMode(4, INPUT_PULLUP);
  pinMode(5, INPUT_PULLUP);
  Serial.begin(9600);
  tone(11, frequenz);
}
void loop() {
  int taste = 0;
  if (digitalRead(4) == LOW) taste = 4;
  else if (digitalRead(5) == LOW) taste = 5;
  if (taste == 0) return;
  warteStabil(taste, LOW);
  if (taste == 4 && frequenz < 2000) frequenz++;
  if (taste == 5 && frequenz > 100) frequenz--;
  tone(11, frequenz);
  Serial.println(frequenz);
  warteStabil(taste, HIGH);
}

Test: Drücke D4 einzeln dreimal, halte ihn danach zwei Sekunden und lasse los. Prüfe die Frequenz im Monitor, weil 1 Hz Unterschied kaum hörbar sein kann. Teste D5 entsprechend. Für Grenztests setzt du den Startwert testweise auf 100 beziehungsweise 2000; stelle danach 440 wieder her. Teste beide Taster zusammen: D4 wird zuerst gewählt, ein weiter gehaltener D5 kann nach D4 folgen.

Erklären: Die Funktion wartet auf 20 ms durchgehend denselben Pegel. Das unterdrückt das hier erwartete Kontaktprellen und erlaubt erst nach stabilem Loslassen eine neue Betätigung. Während des Wartens liest der Sketch die andere Taste nicht aus; der bereits gestartete Ton läuft weiter. && bedeutet „und“, || bedeutet „oder“: Vergleiche frequenz < 100 || frequenz > 2000 mit frequenz < 100 && frequenz > 2000. Warum kann die zweite Bedingung nie wahr sein?

13. Programme planen - Denken vor dem Programmieren

Warum Programme planen?
Gute Programme entstehen nicht durch Zufall.
Bevor man Code schreibt, sollte man sich überlegen:
  • Was soll das Programm tun?
  • In welcher Reihenfolge passieren die Schritte?
  • Wo gibt es Entscheidungen oder Wiederholungen?
Genau dabei helfen Flussdiagramme.
Starte mit einem bekannten Ablauf

Zeichne auf Papier „Start → LED an → 300 ms warten → LED aus → Ende“. Nutze für Start und Ende ein Oval und für die drei Schritte Rechtecke. Ergänze danach eine Raute „Taster gedrückt?“ vor dem Einschalten. Beschrifte beide Wege mit Ja und Nein: Was soll auf dem Nein-Weg geschehen? Vergleiche deinen Ablauf mit dem Taster-Sketch aus Kapitel 11.

Beispielbild: Flussdiagramm mit typischen Symbolen
Was ist ein Flussdiagramm?
Ein Flussdiagramm zeigt einen Ablauf so, dass man ihn schnell überblicken kann. Es macht sichtbar,
  • welche Schritte nacheinander passieren,
  • an welchen Stellen Entscheidungen getroffen werden,
  • welche Informationen oder Eingaben dafür gebraucht werden.
Ein Flussdiagramm kennzeichnet einen Start und gegebenenfalls ein Ende. Ein Arduino-Ablauf mit loop() führt dagegen immer wieder zum Schleifenanfang zurück; er muss kein erreichbares Ende haben.
So liest du das Flussdiagramm
In dem Bild erkennst du die typischen Bausteine eines Flussdiagramms:
  • abgerundete Rechtecke für Start und Ende,
  • Rechtecke für konkrete Prozessschritte,
  • Rauten für Entscheidungen wie "Ja oder Nein?",
  • Parallelogramme für Ein- und Ausgaben, zum Beispiel einen Zeitstempel,
  • Pfeile für die Richtung des Ablaufs.
Manche Darstellungen enthalten außerdem Dokumente oder ausgelagerte Teilprozesse. So sieht man auf einen Blick, wie aus einem Input Schritt für Schritt ein Output wird.
Wofür Flussdiagramme gut sind
Flussdiagramme sind ein einfaches Werkzeug, um Prozesse zu planen, zu erklären oder Fehler zu finden.

Vorteile:
  • schnell gezeichnet und schnell verändert,
  • übersichtlich bei linearen Abläufen,
  • gut geeignet, um einzelne Teilschritte zu untersuchen.
Bei sehr großen oder verzweigten Prozessen kann ein Flussdiagramm aber schnell unübersichtlich werden.
Flussdiagramme selbst erstellen

Werkstatt 13: Vom Ablaufplan zum Test

13.1 Ein Flussdiagramm übersetzen

Setze diesen Plan in einem neuen Sketch um: Start → x = 10 → solange x < 100: x ausgeben, x um 2 erhöhen → Ende. Nutze Serial.begin(9600) und schreibe den einmaligen Ablauf in setup(); loop() bleibt leer. Die vollständige Grundstruktur zum Ausführen und Erweitern ist:

void setup() {
  Serial.begin(9600);
  int x = 10;
  while (x < 100) {
    Serial.println(x);
    x = x + 2;
  }
}
void loop() {}

Vorhersage und Test: Bestimme erste Zahl, letzte Zahl, Anzahl der Ausgaben und Endwert von x, bevor du hochlädst. Vergleiche im Monitor bei 9600 Baud. Ändere nur < in <= und sage die neue letzte Zahl und Anzahl voraus. Erkläre, warum die ursprüngliche Folge nicht bei 100 ausgegeben endet.

Vom Flussdiagramm zum Arduino-Code

Die kurzen Codeabschnitte in den vier Vergleichen zeigen einzelne Bausteine. Lade sie nicht allein hoch. Der vollständige Versuch folgt unter „Übung – Vom Plan zum Code“.

Warum diese Brücke wichtig ist
Ein Flussdiagramm ist ein Plan, kein fertiges Programm.
Ziel ist es, diesen Plan systematisch in Code zu übersetzen, ohne etwas zu vergessen oder durcheinanderzubringen.

Jeder Schritt im Flussdiagramm entspricht später einem bestimmten Teil im Code.
Grundregel der Übersetzung
Flussdiagramm Schritt für Schritt lesen
und jeden Schritt nacheinander in Code umsetzen.

Merksatz:
Ein Schritt = eine Idee = ein Code-Abschnitt
1. Sequenz - normaler Code
Flussdiagramm (gedanklich): 
LED an
warten
LED aus
Arduino-Code: 
digitalWrite(13, HIGH);
delay(500);
digitalWrite(13, LOW);
Jede Anweisung wird genau einmal und in derselben Reihenfolge ausgeführt.
2. Auswahl - if / else
Flussdiagramm (gedanklich): 
Ist der Taster gedrückt?
  Ja - LED an
  Nein - LED aus
Arduino-Code: 
if (digitalRead(BTN) == LOW) {
  digitalWrite(LED, HIGH);
} else {
  digitalWrite(LED, LOW);
}
Die Entscheidung im Flussdiagramm wird zu if und else.
3. Wiederholung (fest) - for-Schleife
Flussdiagramm (gedanklich): 
Wiederhole 3-mal:
  LED an
  warten
  LED aus
Arduino-Code: 
for (int i = 0; i < 3; i++) {
  digitalWrite(13, HIGH);
  delay(300);
  digitalWrite(13, LOW);
  delay(300);
}
Die Anzahl der Wiederholungen steht direkt in der Schleife.
4. Wiederholung (Bedingung) - while-Schleife
Flussdiagramm (gedanklich): 
Solange der Taster nicht gedrückt ist:
  LED blinkt
Arduino-Code: 
while (digitalRead(BTN) == HIGH) {
  digitalWrite(LED, HIGH);
  delay(200);
  digitalWrite(LED, LOW);
  delay(200);
}
"Solange" im Flussdiagramm bedeutet fast immer while.
Übersetzungs-Strategie (sehr wichtig)
Gehe immer in dieser Reihenfolge vor:
  1. Flussdiagramm vollständig verstehen
  2. Sequenzen umsetzen
  3. Dann Entscheidungen (if / else)
  4. Zum Schluss Wiederholungen (for / while)
So vermeidest du typische Anfängerfehler.

Aufbau und eindeutiges Ziel: Taster D4/GND, eingebaute LED. Der Ablauf startet nach einem Tastendruck genau einmal pro Reset, blinkt fünfmal für jeweils 300 ms an und 300 ms aus und bleibt anschließend aus. Setze den Ablauf in setup(), lasse loop() leer.

IDE-Auftrag: Lade den vollständigen Sketch hoch. Halte den Taster beim Start frei, drücke dann einmal und zähle die Impulse. Teste anschließend einen weiteren Druck, einen langen Druck und Reset. Ändere als Transfer auf drei Impulse und vergleiche mit deinem Plan aus Kapitel 13.

const int BTN = 4;
void setup() {
  pinMode(BTN, INPUT_PULLUP);
  pinMode(LED_BUILTIN, OUTPUT);
  digitalWrite(LED_BUILTIN, LOW);
  while (digitalRead(BTN) == HIGH) {}
  for (int i = 0; i < 5; i++) {
    digitalWrite(LED_BUILTIN, HIGH);
    delay(300);
    digitalWrite(LED_BUILTIN, LOW);
    delay(300);
  }
}

14. LCD-Displays - Texte anzeigen

Wozu ein Display?
Ein Display macht ein Arduino-Projekt "sichtbar": Du kannst Werte, Zustände, Menüs oder Hinweise anzeigen (z. B. Temperatur, Punktestand, Ampelmodus, Fehlermeldungen).
Es gibt verschiedene Display-Typen
Nicht jedes Display funktioniert gleich. Häufige Typen:
  • Zeichen-LCD (z. B. 16x2, 20x4; meist HD44780-kompatibel)
  • Zeichen-LCD mit I2C-Adapter (weniger Kabel)
  • OLED (oft I2C oder SPI; sehr kontrastreich)
  • TFT (Farbdisplay; oft SPI; komplexer, mehr Speicherbedarf)
In diesem Baustein geht es vor allem um das Zeichen-LCD.
Zeichen-LCD (16x2 / 20x4) - was bedeutet das?
Ein 16x2-Display kann 16 Zeichen pro Zeile und hat 2 Zeilen. Ein 20x4-Display kann 20 Zeichen pro Zeile und hat 4 Zeilen.

Es zeigt vor allem Text (Zeichen) an - keine frei zeichnbaren Bilder wie ein TFT.
Parallel vs. I2C
Es gibt zwei sehr verbreitete Anschlussarten:
  • Parallel (viele Kabel): mehrere Datenpins + Steuerpins
  • I2C (wenige Kabel): meist nur VCC, GND, SDA, SCL
Für Anfänger ist ein I2C-LCD oft einfacher, weil man weniger verdrahten muss.
Wichtig: Spannung, Kontrast, Hintergrundbeleuchtung
Häufige Stolpersteine:
  • Kontrast: Viele LCDs haben ein kleines Potentiometer - wenn der Kontrast falsch ist, siehst du "nichts".
  • 5 V oder 3,3 V: Versorgung und Datenpegel müssen zum Modul passen. Verwende hier nur das ausdrücklich für 5 V vorgesehene I²C-LCD am Uno R3; 5-V-I²C-Pullups passen nicht direkt zu jedem 3,3-V-Board.
  • Backlight: Hintergrundbeleuchtung kann an/aus sein - bei falscher Verdrahtung wirkt das Display "tot".
Grundbefehle (Zeichen-LCD)
Typische Funktionen (je nach Library):
  • begin() - Display starten
  • clear() - Bildschirm leeren
  • setCursor(spalte, zeile) - Schreibposition setzen
  • print("Text") - Text ausgeben
Alternative: 16×2 LCD parallel

Dieser alternative Aufbau braucht keinen I²C-Adapter. Führe ihn nur mit einem passenden 16-poligen HD44780-LCD aus, nachdem du die anderen Bauteile entfernt hast: VSS→GND, VDD→5 V, VO→Schleifer eines 10-kΩ-Potentiometers (äußere Anschlüsse 5 V/GND), RS→D12, R/W→GND, E→D11, D4→D5, D5→D4, D6→D3, D7→D2. D0–D3 am LCD bleiben frei. LED+/LED− benötigen die Versorgung und den Vorwiderstand aus dem LCD-Datenblatt. Verwechsle die LCD-Datenleitungen D4–D7 nicht mit den Arduino-Pinnamen.

#include <LiquidCrystal.h>

// RS, E, LCD-D4, LCD-D5, LCD-D6, LCD-D7
LiquidCrystal lcd(12, 11, 5, 4, 3, 2);

void setup() {
  lcd.begin(16, 2);
  lcd.print("Hallo!");
  lcd.setCursor(0, 1);
  lcd.print("Arduino LCD");
}

void loop() {
}
Die folgenden Werkstattaufgaben verwenden stattdessen das I²C-LCD mit vier Anschlüssen.
Beispiel: LCD mit I2C (weniger Kabel) 
#include <Wire.h>
#include <LiquidCrystal_I2C.h>

// 0x27 erst nach dem I2C-Scan unten verwenden oder anpassen.
LiquidCrystal_I2C lcd(0x27, 16, 2);

void setup() {
  lcd.init();
  lcd.backlight();
  lcd.setCursor(0, 0);
  lcd.print("I2C LCD ready");
}

}
Wenn nichts erscheint: Kontrast prüfen und ggf. I2C-Adresse testen.

Werkstatt 14: LCD selbst in Betrieb nehmen

14.1–14.2 Bibliothek, Anschluss und Adresse

  1. Öffne in der IDE Sketch → Bibliothek einbinden → Bibliotheken verwalten beziehungsweise den Bibliotheksverwalter. Suche LiquidCrystal I2C. Die Beispiele hier verwenden die API mit LiquidCrystal_I2C(adresse, spalten, zeilen), init(), backlight() und noBacklight(), wie sie im verlinkten Quellcode dokumentiert ist. Eine gleichnamige Bibliothek kann eine andere API haben. Notiere Name, Autor und installierte Version und prüfe deren mitgeliefertes Beispiel.
  2. Trenne USB. Verbinde am 5-V-I²C-LCD GND→GND, VCC→5 V, SDA→SDA (Uno R3: auch A4) und SCL→SCL (auch A5). Der parallel angeschlossene Taster darf D4/GND verwenden, nicht A4. Verlasse dich auf die Beschriftung und nicht die Reihenfolge der vier Stifte.
  3. Verbinde USB und lade zuerst den Scanner unten hoch. Öffne den Monitor bei 9600 Baud und notiere die gefundene Hex-Adresse. Bei keinem Fund: Versorgung und SDA/SCL prüfen. Ersetze anschließend in den LCD-Sketches 0x27 durch deine tatsächlich gefundene Adresse.
  4. Lade das vollständige I²C-Beispiel oben hoch. Erwartet ist I2C LCD ready in der ersten Zeile. Drehe den kleinen Kontrastregler vorsichtig, falls nur Licht oder Blöcke sichtbar sind. Bei init-Kompilierfehlern prüfst du die Bibliothek; bei erfolgreichem Upload, aber leerem LCD zuerst Adresse, Anschluss und Kontrast.
#include <Wire.h>
void setup() {
  Serial.begin(9600);
  Wire.begin();
  Serial.println("I2C-Scan");
  int gefunden = 0;
  for (int adresse = 1; adresse < 127; adresse++) {
    Wire.beginTransmission(adresse);
    if (Wire.endTransmission() == 0) {
      Serial.print("Gefunden: 0x");
      if (adresse < 16) Serial.print('0');
      Serial.println(adresse, HEX);
      gefunden++;
    }
  }
  if (gefunden == 0) Serial.println("Kein I2C-Geraet gefunden");
}
void loop() {}

Der Scanner zeigt erreichbare I²C-Adressen, nicht den Displaytyp. Lasse für diesen Test nur das LCD am Bus angeschlossen. Ein Fund allein bestätigt noch nicht, dass die Bibliothek zur Adapterbelegung passt.

15. Motoren steuern

Was ist ein Motor?
Ein Motor wandelt elektrische Energie in Bewegung um.
Mit Motoren können z. B. Räder angetrieben, Arme bewegt oder Lüfter betrieben werden.

Motoren sind damit eine wichtige Verbindung zwischen Programm und realer Bewegung.
Es gibt verschiedene Motorarten
Je nach Aufgabe nutzt man unterschiedliche Motoren:
  • Gleichstrommotor (DC) - dreht sich kontinuierlich
  • Servomotor - führt gezielt eine Position an
  • Schrittmotor - bewegt sich in festen Schritten
In diesem Lernbaustein steht vor allem der DC-Motor im Fokus.
Warum darf man Motoren nicht direkt anschließen?
Motoren benötigen meist:
  • mehr Strom als ein Arduino-Pin liefern kann
  • eine Schutzbeschaltung gegen Spannungsspitzen

Deshalb steuert der Arduino den Motor nicht direkt, sondern über ein Hilfsbauteil (z. B. Transistor oder Motortreiber).
Transistor oder Motortreiber
Häufige Lösungen:
  • Transistor: Ein/aus, evtl. mit PWM für Geschwindigkeit
  • Motortreiber-Modul (z. B. L298N): Richtung + Geschwindigkeit
Der Arduino gibt nur Steuersignale, die eigentliche Motorleistung kommt aus einer separaten Versorgung.
Wichtiger Schutz: Freilaufdiode
DC-Motoren enthalten induktive Wicklungen. Beim Abschalten können Spannungsspitzen entstehen, die den Arduino zerstören können.

Beim Schalten in nur einer Richtung kann eine passend angeschlossene Freilaufdiode den Strom weiterführen. Eine umpolbare H-Brücke benötigt passende Freilaufpfade für beide Richtungen; bei der verwendeten L298N-Platine müssen die Schutzdioden bereits vorhanden sein. Eine einzelne Diode direkt quer zum Motor wäre für den Richtungswechsel ungeeignet.
Motor ein- und ausschalten (Prinzip)
Der Arduino steuert den Motor ähnlich wie eine LED - aber indirekt: 
digitalWrite(ENA, HIGH); // Treiber freigeben
digitalWrite(ENA, LOW);  // Bruecke abschalten
ENA bezeichnet den Freigabeeingang des Treibers, nicht einen Motoranschluss. Bei passender Richtungsvorgabe schaltet der Treiber den Motorstrom aus der externen Versorgung.
Geschwindigkeit steuern
Die Drehzahl eines DC-Motors kann mit Pulsweitenmodulation (PWM) verändert werden: 
analogWrite(ENA, 120);
Der Wert 0–255 bestimmt beim Uno das Tastverhältnis am PWM-Steuereingang des Treibers. Bei gleicher Last führt ein größerer Wert häufig zu höherer Drehzahl, aber nicht proportional. Ein kleiner Wert kann zum Anlaufen zu wenig sein. PWM allein ist keine geregelte Strombegrenzung und ersetzt keinen Überstromschutz.

Werkstatt 15: Mit einer L298N-H-Brücke steuern

Diese beiden Materialaufgaben gehören weiter zu diesem Modul. Du brauchst eine beschriftete L298N-Treiberplatine mit Schutzdioden, kleine dazu passende DC-Motoren und eine dafür ausgelegte externe Motorversorgung. Lies die Anleitung deiner Platine: Die mit „12 V“ oder „VS“ markierte Motorklemme bekommt die für Motor und Modul zulässige Spannung, nicht automatisch 12 V. Der L298 hat einen Spannungsabfall; Motorspannung und Netzteilspannung sind deshalb nicht gleich. Der Motor wird weder aus einem GPIO noch aus dem Uno-5-V-Anschluss gespeist.

Anschlussliste für diese Versuche

  1. Trenne USB und Motorversorgung. Entferne die bisherigen LED-, Lautsprecher-/Piezo- und Tasterleitungen von den neu belegten Pins. Verbinde Motor links mit OUT1/OUT2 (Brücke A), Motor rechts später mit OUT3/OUT4 (Brücke B).
  2. Arduino D3→IN1, D4→IN2; für den zweiten Motor D7→IN3, D8→IN4. Verbinde GND des Uno mit GND des Treibers und Minus der Motorversorgung.
  3. Entferne die ENA-/ENB-Steckbrücken für dauerhaftes Einschalten. D5→ENA, später D6→ENB. Verwechsle diese Jumper nicht mit dem 5V-EN-Reglerjumper. Dessen Stellung und die 5-V-Logikversorgung legst du ausschließlich nach der Modul-Anleitung fest; eine 5-V-Klemme kann je nach Stellung Ein- oder Ausgang sein. Verbinde keine zwei 5-V-Ausgänge miteinander.
  4. Verbinde Plus und Minus der noch ausgeschalteten Motorversorgung mit den dafür markierten Motorklemmen. Sichere die Motoren und lasse Räder frei laufen. Prüfe zulässigen Anlauf-/Blockierstrom und die Schutzdioden anhand von Motor- und Modulunterlagen; blockiere die Motorwelle nicht zum Testen.
  5. Verbinde USB, lade den passenden Sketch mit noch ausgeschalteter Motorversorgung hoch und schalte erst dann die Motorversorgung ein. Vor jedem Umbau oder erneutem Upload schaltest du die Motorversorgung aus. Bei Erwärmung oder Stillstand trotz Ansteuerung schaltest du sie ebenfalls aus und prüfst Aufbau, Versorgung und Belastung.

15.1 Zwei Sekunden antreiben, zwei Sekunden bremsen

Verwende zunächst nur Motor A. Lade diesen Sketch hoch. Er bildet den Materialauftrag D3 HIGH/D4 LOW und danach beide HIGH ab; zusätzlich wird ENA ausdrücklich gesteuert.

const int IN1 = 3, IN2 = 4, ENA = 5;
void setup() {
  pinMode(ENA, OUTPUT);
  digitalWrite(ENA, LOW);
  pinMode(IN1, OUTPUT);
  pinMode(IN2, OUTPUT);
}
void loop() {
  digitalWrite(IN1, HIGH);
  digitalWrite(IN2, LOW);
  analogWrite(ENA, 255);
  delay(2000);
  digitalWrite(IN1, HIGH);
  digitalWrite(IN2, HIGH);
  delay(2000);
}

Erwartung und Test: Sage die Bewegung in beiden Phasen voraus und beobachte drei Zyklen. Bei aktivem ENA bedeuten gleiche Eingänge elektrisches Bremsen, nicht Freilauf. Ersetze für einen Vergleich im zweiten Abschnitt nach digitalWrite(IN2, HIGH); die Bremsphase durch analogWrite(ENA, 0); mit unverändertem delay(2000). Nun ist die Brücke abgeschaltet und der Motor kann auslaufen. Ob du den Unterschied gut erkennst, hängt von Trägheit und Last ab. Dokumentiere die tatsächliche Beobachtung.

15.2 Zwei Motoren mit Unterprogrammen steuern

Erweitere bei abgezogener Versorgung auf Motor B und ENB. Dieser Sketch enthält die fünf geforderten Funktionen: beide vorwärts, beide rückwärts, nur links vorwärts, nur rechts vorwärts und Stopp. „Vorwärts“ ist zunächst eine Annahme über Einbaurichtung und Motorpolung.

Wie im Motorenmodul ist A links (IN1 D3, IN2 D4, ENA D5) und B rechts (IN3 D7, IN4 D8, ENB D6). Damit weicht die Belegung des zweiten Motors vom ursprünglichen Material ab. stopp() bremst in diesem Versuch ausdrücklich beide Motoren bei aktivierten Enable-Eingängen. Das Motorenmodul verwendet dagegen einen auslaufenden Stopp mit abgeschalteten Enable-Eingängen.

const int ENA = 5, ENB = 6;
void setzen(int a, int b, int c, int d) {
  digitalWrite(3, a); digitalWrite(4, b);
  digitalWrite(7, c); digitalWrite(8, d);
}
void vorwaerts() { setzen(HIGH, LOW, HIGH, LOW); }
void rueckwaerts() { setzen(LOW, HIGH, LOW, HIGH); }
void linksVor() { setzen(HIGH, LOW, HIGH, HIGH); }
void rechtsVor() { setzen(HIGH, HIGH, HIGH, LOW); }
void stopp() { setzen(HIGH, HIGH, HIGH, HIGH); }
void setup() {
  pinMode(ENA, OUTPUT); pinMode(ENB, OUTPUT);
  digitalWrite(ENA, LOW); digitalWrite(ENB, LOW);
  pinMode(3, OUTPUT); pinMode(4, OUTPUT);
  pinMode(7, OUTPUT); pinMode(8, OUTPUT);
  stopp();
  analogWrite(ENA, 255); analogWrite(ENB, 255);
}
void loop() {
  vorwaerts(); delay(2000);
  stopp(); delay(1000);
  rueckwaerts(); delay(2000);
  stopp(); delay(1000);
  linksVor(); delay(1000);
  stopp(); delay(1000);
  rechtsVor(); delay(1000);
  stopp(); delay(1000);
}

Test und Auswertung: Lade hoch, schalte die Motorversorgung ein und prüfe jede Funktion bei frei laufenden Rädern. Falls ein eingebauter Motor bei vorwaerts() falsch dreht, vertausche bei abgezogener Versorgung seine beiden Motorleitungen oder korrigiere konsequent seine Signalzuordnung. „Nur links vorwärts“ bezeichnet das linke Rad und führt bei einem Fahrzeug typischerweise zu einer Rechtskurve. Erkläre, welcher Motor jeweils fährt und welcher bremst.

Mini-Challenge - Ventilator steuern
Challenge
Ziel: Ein Motor soll:
  • nur während eines gedrückten Tasters angesteuert werden
  • sein PWM-Tastverhältnis beim Halten schrittweise erhöhen
Nutze if, analogWrite() und eine Variable für die Geschwindigkeit.

Aufbau: Motor A mit IN1→D3, IN2→D4 und ENA→D5 wie in 15.1; Taster für diese Aufgabe D2/GND, weil D4 jetzt den Motor steuert. Motor B bleibt unversorgt. Entferne den ENA-Jumper; die externe Motorversorgung und gemeinsame Masse bleiben erforderlich.

const int BTN = 2, IN1 = 3, IN2 = 4, ENA = 5;
int pwm = 0;
unsigned long zuletzt = 0;
void setup() {
  pinMode(BTN, INPUT_PULLUP);
  pinMode(ENA, OUTPUT);
  digitalWrite(ENA, LOW);
  pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);
}
void loop() {
  if (digitalRead(BTN) == LOW) {
    if (millis() - zuletzt >= 20) {
      zuletzt = millis();
      if (pwm < 255) pwm += 5;
    }
  } else {
    pwm = 0;
    zuletzt = millis();
  }
  analogWrite(ENA, pwm);
}

Test und Reflexion: Lade bei ausgeschalteter Motorversorgung hoch. Schalte ein, teste frei, mindestens zwei Sekunden halten und loslassen. Dokumentiere Code und reale Beobachtung. Der PWM-Wert steigt bis 255; der Motor kann wegen Reibung erst ab einem Mindestwert anlaufen. Nach dem Loslassen wird die Brücke deaktiviert, der Motor kann auslaufen. Begründe, weshalb die Rampe weder einen sicheren Sanftanlauf noch eine Strombegrenzung garantiert und warum ein gespeicherter Ein-/Aus-Umschalter zusätzlichen Zustand und Entprellung bräuchte.

Lösungsidee:
Taster mit if abfragen.
Bei gedrücktem Taster: Geschwindigkeit langsam erhöhen (Variable + PWM).
Bei losgelassenem Taster: Motor ausschalten.
