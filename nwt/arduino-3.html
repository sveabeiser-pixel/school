Dein Start am Arbeitsplatz

Leitfrage: Wie steuerst du mit gespeicherten Werten, Wiederholungen und Entscheidungen gezielt Licht und Ton? Du sagst zuerst das Verhalten voraus, lädst den Sketch hoch und vergleichst deine Beobachtung mit der Vorhersage.

  1. Arbeite mit einem Arduino Uno R3 / ATmega328P, USB-Datenkabel, Breadboard und Steckleitungen. Die Zahlenbereiche und Pinangaben dieser Seite beziehen sich auf dieses Board.
  2. Öffne die Arduino-IDE. Wähle im Boardwähler bzw. unter Werkzeuge → Board den Uno und den zugehörigen Port. Ziehe bei unklarer Zuordnung USB kurz ab: Der verschwindende Port gehört zum Board.
  3. Lege für jede Aufgabe einen eigenen Sketch an und speichere ihn unter der Aufgabennummer. Ersetze den Inhalt vollständig durch die jeweilige Vorlage: Ein Sketch enthält genau ein setup() und ein loop().
  4. Klicke zuerst Überprüfen (Haken), dann Hochladen (Pfeil). Warte auf die Erfolgsmeldung. Das Prüfen allein überträgt keinen Code. Prüfe bei Uploadfehlern Board, Port und Datenkabel.
  5. Trenne USB vor jedem Umbau. Schließe anschließend wieder an und lade den passenden Sketch hoch. Für reine LED13-Aufgaben reicht die eingebaute LED L; du brauchst dafür keine externe LED.

Tonaufbau für alle Aufgaben mit Pin 11

Verwende wie in Modul 2 einen kleinen passiven Lautsprecher oder einen passiven Piezo-Schallwandler. Prüfe das Bauteil vor dem Anschluss anhand der Set-Unterlagen, des Datenblatts oder gemeinsam mit deiner Lehrkraft. Ein unbeschriftetes Teil wird nicht probeweise direkt am Pin angeschlossen; ein aktiver Summer mit eigener Tonerzeugung eignet sich nicht für die Tonhöhenversuche.

Trenne USB und verbinde D11 → 330-Ω-Serienwiderstand → Lautsprecheranschluss 1; Anschluss 2 → GND. Bei einem gepolten Piezo liegt + auf der Pinseite und − an GND. Auch ein niederohmiger kleiner passiver Lautsprecher wird hier nur mit diesem Serienwiderstand leise betrieben; der Widerstand begrenzt den Pin-Strom. Mit 1 kΩ in Reihe wird er noch leiser. Für höhere Lautstärke brauchst du eine geeignete Treiberstufe. Halte den Schallwandler beim Test vom Ohr fern und entferne den Tonaufbau später vor Lauflicht und LED-Versuchen.

Was ist eine Variable?
Eine Variable ist ein Speicherplatz im Arduino, in dem ein Wert abgelegt werden kann. Dieser Wert kann sich während des Programms ändern.
Beispiel aus dem Alltag
Stell dir eine Variable wie eine beschriftete Kiste vor:
Der Name der Kiste ist der Variablenname, der Inhalt der Kiste ist der Wert.

Der Inhalt kann jederzeit ausgetauscht werden – der Name der Kiste bleibt gleich.
Datentypen (aus dem Heft)
Variablen haben unterschiedliche Datentypen, je nachdem, was gespeichert wird:
  • int – beim Uno R3 ganze Zahlen von −32768 bis 32767
  • long – ganze Zahlen von −2147483648 bis 2147483647
  • float – Kommazahlen (z. B. 2.5)
Variablen im Programm
Eine Variable wird zuerst angelegt: 
int a;
Danach kann ihr ein Wert zugewiesen werden: 
a = 10;
Später kann der Wert wieder geändert werden: 
a = a + 5;
Ablaufspur: Was steht wann in der Variable?
Eine Zuweisung wird immer von rechts nach links verstanden: Erst wird rechts gerechnet, dann wird das Ergebnis links gespeichert. Die folgenden drei Zeilen stehen innerhalb einer Funktion. Die lokale Variable int a; hat dort ohne Initialisierung keinen bestimmten Anfangswert. Eine globale Variable außerhalb der Funktionen würde dagegen vor setup() mit 0 initialisiert. Setze beim Programmieren den gewünschten Startwert ausdrücklich.
Wichtiger Hinweis
Der Arduino merkt sich immer nur den aktuellen Wert einer Variable. Alte Werte gehen verloren, sobald ein neuer Wert zugewiesen wird.
Warum sind Variablen so wichtig?
Ohne Variablen wären Programme:
  • unflexibel
  • lang
  • schwer veränderbar
Mit Variablen kann man z. B. Tonhöhen, Wartezeiten oder Helligkeiten einfach anpassen.

6.1 Werte verfolgen und hören

Nutze den Tonaufbau an D11. Berechne nach jeder Zeile in setup() die aktuellen Werte von a, n und m. Notiere dann Tonhöhe, Tondauer und Pause eines Durchlaufs. Erkläre, ob die letzte Änderung von a auch m verändert.

int a;
long n, m;
void setup() {
  a = 10;
  n = 100 - 8;
  m = 2 * a + 15 - 3;
  a = 200 + 20;
}
void loop() {
  tone(11, a);
  delay(n);
  noTone(11);
  delay(m);
}

Teste: Lade hoch und höre kurz zu. Verdopple anschließend nur n. Sage vor dem Upload voraus, was sich zeitlich ändert und was gleich bleibt. Im Material fehlt bei noTone() der Pin; die Vorlage korrigiert das.

6.2 Dein Musikstück mit Notenlängen

Öffne eine Kopie deines Musikstücks aus Aufgabe 5.2. Lege vor setup() drei Variablen int a = 125;, int v = 250;, int h = 500; für Achtel-, Viertel- und halbe Noten an. Ersetze die passenden Zahlen in den delay()-Befehlen durch diese Namen. Wenn du den Sketch nicht zur Hand hast, beginne mit dieser spielbaren Kurzfolge und erweitere sie um weitere Noten:

int a = 125;
int v = 250;
int h = 500;
void setup() {}
void loop() {
  tone(11, 262); delay(a); noTone(11); delay(30);
  tone(11, 294); delay(v); noTone(11); delay(30);
  tone(11, 330); delay(h); noTone(11); delay(1000);
}

Teste: Verdopple alle drei Notenlängen und lade erneut hoch. Vergleiche Tempo und Tonhöhe. Begründe, weshalb du für ein einheitlich schnelleres Stück auch die fest eingetragenen Pausen proportional ändern müsstest.

6.3 Ein Ton wird höher

int f;
void setup() { f = 100; }
void loop() {
  tone(11, f);
  delay(100);
  f = f + 1;
}

Notiere die ersten fünf Frequenzwerte. Lade den Sketch am Tonaufbau hoch, höre etwa zehn Sekunden zu und trenne dann USB. Erkläre, welche Zeile die Frequenz ändert und weshalb der Ton zwischen den Änderungen nicht verstummt. Stopp & check: Ein int wächst nicht unbegrenzt. Beschreibe für einen späteren Umbau mit if, wie du oberhalb von 1000 Hz wieder bei 100 Hz beginnen würdest.

7. Serielle Ausgabe – Mit dem Arduino kommunizieren

Was ist die serielle Ausgabe?
Mit der seriellen Ausgabe kann der Arduino Text und Zahlen an den Computer senden.
Diese Informationen erscheinen im seriellen Monitor der Arduino-IDE.
Wozu braucht man das?
Die serielle Ausgabe wird vor allem genutzt, um:
  • zu prüfen, ob ein Programm richtig läuft
  • Werte von Variablen anzuzeigen
  • Fehler im Programm zu finden
Sie ist eine wichtige Hilfe beim Programmieren.
Serial.begin(9600)
Bevor der Arduino Daten senden kann, muss die serielle Verbindung gestartet werden: 
Serial.begin(9600);
Die Zahl 9600 gibt die Übertragungsgeschwindigkeit an (Baudrate).
Serial.println()
Mit Serial.println() gibt der Arduino einen Wert oder Text aus und beginnt danach eine neue Zeile. 
Serial.println(x);
So kann man verfolgen, wie sich der Wert von x im Laufe des Programms ändert.

Debugging – Wenn das Programm nicht so läuft wie gedacht

Was bedeutet Debugging?
Debugging bedeutet, Fehler im Programm zu finden und zu beheben. Fehler sind dabei normal und gehören zum Programmieren dazu.
Gute Programmierer unterscheiden sich nicht dadurch, dass sie keine Fehler machen – sondern dadurch, dass sie systematisch nach ihnen suchen.
Die wichtigste Regel
Merke: Erst denken, dann ändern.
Wildes Ausprobieren führt selten zum Ziel. Debugging heißt: Schritt für Schritt prüfen.

Typische Fehlerquellen

Programm startet nicht
Häufige Ursachen:
  • falsches Board ausgewählt
  • falscher Port ausgewählt
  • USB-Kabel nur zum Laden geeignet
LED blinkt nicht
Mögliche Ursachen:
  • falscher Pin im Code
  • LED falsch herum eingebaut
  • Widerstand fehlt oder falsch gesteckt
Serieller Monitor zeigt nichts
Prüfe:
  • Serial.begin() vorhanden?
  • richtige Baudrate eingestellt?
  • serieller Monitor geöffnet?
Fehlermeldung auf Englisch
Die Arduino-IDE meldet Fehler meist auf Englisch. Das ist kein Problem:
Wichtig sind Schlüsselwörter wie expected, not declared, before.
Systematische Debug-Strategie
Gehe immer in dieser Reihenfolge vor:
  1. Was soll passieren?
  2. Was passiert tatsächlich?
  3. Wo im Code wird das entschieden?
  4. Welche Variable oder welcher Pin ist beteiligt?

8. for-Schleifen – Wiederholungen elegant lösen

Was ist eine for-Schleife?
Eine for-Schleife wird verwendet, wenn ein Programmteil mehrmals hintereinander ausgeführt werden soll.
Statt denselben Code immer wieder zu schreiben, nutzt man eine Schleife.
Zwar könnte man da ja auch im loop() machen, aber da wird es solange gemacht, bis das Programm gestoppt wird. Mit einer for-Schleife kann man genau festlegen, wie oft etwas passieren soll. Vielleicht nur 5 mal, oder bis eine Bedingung erfüllt ist.
Warum braucht man Schleifen?
Schleifen machen Programme:
  • kürzer
  • übersichtlicher
  • leichter veränderbar
Eine Zahl zu ändern reicht aus – der Code passt sich an.
Aufbau einer for-Schleife
Eine for-Schleife besteht aus drei Teilen: 
for (int i = 0; i < 5; i++) {
  // Code
}
Bedeutung:
  • Startwert: int i = 0
  • Bedingung: i < 5
  • Schritt: i++ (i wird um 1 erhöht)

Lies die Schleife in vier Schritten

  1. Startwert einmal setzen.
  2. Bedingung prüfen.
  3. Block ausführen.
  4. Zählvariable verändern und erneut prüfen.

Trage danach die einzelnen Durchgänge in die Ablaufspur ein.

Beispiel aus dem Heft
Eine LED soll fünfmal blinken: 
void setup() {
  pinMode(13, OUTPUT);
  for (int i = 0; i < 5; i++) {
    digitalWrite(13, HIGH);
    delay(300);
    digitalWrite(13, LOW);
    delay(300);
  }
}
void loop() {}
Lade den Sketch hoch und zähle an LED L mit. Drücke Reset: Der Code im Block wird erneut genau 5-mal ausgeführt. Die Schleife steht bewusst in setup(); innerhalb von loop() würden die Fünfergruppen immer wieder starten.
Einzelne Schleifendurchgänge sichtbar machen
Bei for (int i = 0; i < 5; i++) startet i bei 0. Vor jedem Durchgang wird geprüft, ob i < 5 noch wahr ist. Erst nach dem Block wird i um 1 erhöht.
Typischer Fehler
Wenn die Bedingung nie falsch wird, läuft die Schleife endlos.
Deshalb immer prüfen: Wird die Schleifenvariable wirklich verändert?

8.1 Start, Grenze und Schritt verändern

Nutze nur das USB-Board und den Monitor mit 9600 Baud. Bestimme vor jedem Upload ersten Wert, letzten Wert und Anzahl der Durchläufe. Drücke bei geöffnetem Monitor Reset und prüfe deine Vorhersage. Ändere nacheinander: Start 0 → 5; dann Grenze 30 → 50; schließlich Schritt n = n + 1 → n = n + 3. Behalte jeweils die vorigen Änderungen bei.

void setup() {
  Serial.begin(9600);
  for (int n = 0; n < 30; n = n + 1) {
    Serial.println("Hallo");
    Serial.println(n);
  }
}
void loop() {}

Erkläre, weshalb bei n < 50 die Zahl 50 nicht ausgegeben wird und warum der letzte Wert bei Schritten von 3 trotzdem nicht 49 sein muss.

8.2 Eine Tonfolge vorhersagen

Baue den Tonaufbau an D11 auf. Bestimme erste und letzte Frequenz, Schrittweite und Anzahl der Tonstufen. Berechne die Summe der Wartezeiten. Lade hoch und höre zu: Was passiert nach dem letzten Schleifendurchlauf?

void setup() {
  for (int f = 100; f < 1001; f = f + 3) {
    tone(11, f);
    delay(60);
  }
}
void loop() {}

Ergänze anschließend noTone(11); direkt nach der Schleife in setup(). Teste erneut und erkläre den Unterschied. Trenne USB nach dem Versuch.

8.3 Auf- und abschwellende Sirene

Programmiere am selben Tonaufbau eine wiederholte Folge von 100 bis 1000 Hz und zurück. Übernimm die Schleife aus 8.2 in loop(), ändere die Wartezeit auf 5 ms und ergänze danach eine zweite Schleife mit Start 1000, Bedingung f >= 100 und Schritt f = f - 3. setup() bleibt leer. Du kannst dieses lauffähige Grundgerüst erweitern:

void setup() {}
void loop() {
  for (int f = 100; f <= 1000; f += 3) {
    tone(11, f);
    delay(5);
  }
  // Fuege hier die absteigende Schleife ein.
}

Teste: Höre nur wenige Zyklen. Vergleiche danach 5 ms und 10 ms je Stufe. Begründe, ob sich die Frequenzgrenzen oder nur die Geschwindigkeit des Auf- und Abschwellens ändern.

8.4 Fünf LEDs als Lauflicht

Trenne USB und entferne den Tonaufbau. Du brauchst fünf LEDs und fünf Widerstände mit je 330 Ω. Verbinde für jeden Pin D9, D10, D11, D12 und D13 einen eigenen Zweig: Pin → Widerstand → LED-Anode; LED-Kathode → GND. Die Kathode ist bei ungekürzten LEDs meist das kürzere Bein; beachte auch die flache Gehäuseseite. Stecke Anode und Kathode in getrennte Kontaktreihen. Verbinde die benutzte GND-Schiene mit GND des Boards.

void setup() {
  for (int pin = 9; pin <= 13; pin++) {
    pinMode(pin, OUTPUT);
  }
}
void loop() {
  for (int pin = 9; pin <= 13; pin++) {
    digitalWrite(pin, HIGH);
    delay(200);
    digitalWrite(pin, LOW);
  }
}

Prüfe: Nach dem Upload leuchtet jeweils nur eine externe LED, von D9 bis D13, dann wieder D9. Die eingebaute LED L kann bei D13 mit aufleuchten. Falls eine LED fehlt: Trenne USB, kontrolliere Polung, Kontaktreihe und den zugehörigen Pin.

Geschachtelte for-Schleifen – Schleifen in Schleifen

Was bedeutet „geschachtelt“?
Eine geschachtelte for-Schleife ist eine Schleife, die innerhalb einer anderen Schleife steht.
Die innere Schleife wird bei jedem Durchlauf der äußeren Schleife komplett ausgeführt.
Warum braucht man das?
Geschachtelte Schleifen werden genutzt, wenn:
  • Muster erzeugt werden sollen
  • Abläufe mehrfach wiederholt werden
  • zwei Dinge gleichzeitig gezählt werden müssen
Sie sind typisch für Licht- und Tonfolgen.
Grundaufbau 
for (int i = 0; i < 3; i++) {
  for (int j = 0; j < 5; j++) {
    // Code
  }
}
Bedeutung:
  • Die äußere Schleife läuft 3-mal
  • Bei jedem Durchlauf läuft die innere Schleife 5-mal
  • Der Code im Inneren läuft also 15-mal
Ablaufspur: außen und innen
Lies geschachtelte Schleifen von außen nach innen. Die äußere Schleife startet eine Runde. In dieser Runde läuft die innere Schleife komplett. Erst dann geht die äußere Schleife weiter.
Beispiel mit LED
Die LED soll in mehreren Durchgängen blinken: 
void setup() {
  pinMode(13, OUTPUT);
  for (int r = 0; r < 3; r++) {
    for (int i = 0; i < 4; i++) {
      digitalWrite(13, HIGH);
      delay(200);
      digitalWrite(13, LOW);
      delay(200);
    }
    delay(1000);
  }
}
void loop() {}
Lade hoch und zähle an LED L mit: 3 Runden mit jeweils 4 Blinkimpulsen. Nach jeder Runde folgt zusätzlich eine Sekunde Pause. Ändere nur die äußere Grenze auf 2 und prüfe deine neue Vorhersage nach einem Upload.
Typischer Denkfehler
Viele denken, die innere Schleife laufe „nebenbei“.
Tatsächlich gilt:
Merke: Die innere Schleife läuft vollständig, bevor die äußere weitergeht.

9. LEDs dimmen – Helligkeit in feinen Stufen steuern

Aufbau: eine externe LED an D3

Trenne USB und entferne Lauflicht und Tonaufbau. Verbinde D3 → 330 Ω → LED-Anode; LED-Kathode → GND. Die eingebaute LED an D13 eignet sich beim Uno R3 nicht für diesen PWM-Versuch. Lade für jeden Versuch einen eigenen LED-Sketch hoch: tone() benutzt beim Uno R3 denselben Timer wie PWM an D3/D11 und darf in diesen Versuchen nicht gleichzeitig laufen.

Digital vs. Analog
Bisher hast du LEDs digital geschaltet:
Merke: HIGH = an, LOW = aus.

Beim Dimmen geht es darum, die Helligkeit in 256 feinen Stufen zu verändern – nicht nur an oder aus.
analogWrite()
Zum Dimmen benutzt man die Anweisung: 
analogWrite(pin, wert);
Der Wert bestimmt die Helligkeit:
  • 0 -> LED aus
  • 127 -> ungefähr halbe Einschaltdauer, nicht zwingend subjektiv halb hell
  • 255 -> volle Helligkeit
Wie funktioniert das technisch?
Der Arduino erzeugt kein echtes Analogsignal, sondern nutzt Pulsweitenmodulation (PWM).

Dabei wird die LED sehr schnell ein- und ausgeschaltet. Je länger sie eingeschaltet ist, desto heller erscheint sie für das Auge.
Beispiel: LED dimmen 
void setup() {
  pinMode(3, OUTPUT);
}

void loop() {
  analogWrite(3, 127);
  delay(1000);
}
Die LED an Pin 3 erhält ungefähr halbe Einschaltdauer. Lade hoch und vergleiche mit den Werten 0 und 255. Eine subjektiv halb so helle LED musst du durch Vergleich bestimmen.
Wichtiger Hinweis
analogWrite() funktioniert nur an PWM-Pins (z. B. 3, 5, 6, 9, 10, 11 beim Arduino Uno).

10. RGB-LEDs – Farben mischen mit Licht

Was ist eine RGB-LED?
Eine RGB-LED enthält drei LEDs in einem Gehäuse: Rot, Grün und Blau.

Durch das Mischen dieser drei Farben können viele verschiedene Farben erzeugt werden.
Das RGB-Prinzip
Jede Farbe setzt sich aus Anteilen von Rot, Grün und Blau zusammen:
  • Rot + Grün -> Gelb
  • Rot + Blau -> Magenta
  • Grün + Blau -> Cyan
  • Rot + Grün + Blau -> bei passender Abstimmung ungefähr Weiß

Materialschaltung mit D9/D10/D11. Hier nutzt du D3/D5/D6 und je 330 Ω; den 110-Ω-Wert aus dem Bild übernimmst du nicht.

Ein Farbrezept besteht aus drei Werten

Ansteuerung mit dem Arduino
Jede Farbe der RGB-LED wird an einen eigenen Pin angeschlossen.

analogWrite(gruenPin, 0);
analogWrite(blauPin, 0);

Wertebereich

  • 0 -> Farbe aus
  • 255 -> maximale Helligkeit

Gemeinsame Anode / gemeinsame Kathode
RGB-LEDs gibt es in zwei Varianten:
  • Gemeinsame Kathode: gemeinsamer Minuspol
  • Gemeinsame Anode: gemeinsamer Pluspol
Die Vorlagen hier gelten für die gemeinsame Kathode. Bei gemeinsamer Anode kommt der gemeinsame Anschluss beim Uno R3 an 5 V und jeder Ausgabewert wird zu 255 - farbwert invertiert. Kläre den Typ vor dem Anschluss und passe alle drei Kanäle einschließlich des Ausschaltzustands an.

11. if / else – Entscheidungen im Programm

Was bedeutet if?
Mit if kann ein Programm eine Entscheidung treffen.
Es prüft eine Bedingung und führt Code nur dann aus, wenn diese Bedingung erfüllt ist.
Alltagsbeispiel
Stell dir vor:
Wenn es regnet, dann nimmst du einen Regenschirm.
Sonst brauchst du keinen.

Genau so arbeitet if / else im Programm.
Grundaufbau von if / else 
if (Bedingung) {
  // wird ausgeführt, wenn die Bedingung wahr ist
} else {
  // wird ausgeführt, wenn die Bedingung falsch ist
}
Vergleichsoperatoren
Bedingungen vergleichen Werte:
  • == gleich
  • < kleiner als
  • > größer als
  • <= kleiner oder gleich
  • >= größer oder gleich
Wichtig: == ist ein Vergleich, = ist eine Zuweisung.
