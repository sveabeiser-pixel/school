Sicherung: Wie funktionieren Arrays?

Ein Array ist eine geordnete Liste von Werten. Jeder Eintrag wird über einen Index angesprochen. Der erste Listenplatz hat die Nummer 0 . Im Melodie-Beispiel berechnet man die Tondauer aus dem Notenwert.

Wahr oder falsch?

Falsch. Das erste Element eines Arrays hat normalerweise den Index 1.

Falsch. Das erste Element einer Liste bekommt immer Index 0.

Mini-Check zu 6.1 bis 6.4

Warum muss die Schleife in Aufgabe 6.1 länger laufen als im ersten kurzen Beispiel?

Weil die erweiterte Melodie mehr als 6 Töne enthält.

Die erweiterte Melodie enthält deutlich mehr Töne. Deshalb muss auch die Schleife mehr Elemente durchlaufen.

Was ist der entscheidende Unterschied zwischen einem char-Array und einem Array mit Wörtern?

Ein char-Array speichert einzelne Zeichen, für Wörter braucht man Zeichenketten mit Pointer.

Genau das gilt hier: einzelne Zeichen mit char, ganze Wörter als Zeichenketten mit Pointer.

Transfer: Entwickle deinen eigenen Array-Einsatz

Eine mögliche Antwort

Ich würde einen Melodiespieler bauen. Ein Array speichert die Frequenzen, zum Beispiel 262, 294 und 330 Hz. Ein zweites Array enthält die zugehörigen Tondauern. Über denselben Index wähle ich Frequenz und Dauer eines Tons aus. Eine for-Schleife spielt die Liste nacheinander ab. Mit dieser Struktur kann ich die Melodie durch Änderung der Listen erweitern, ohne jeden Ton als eigenen Codeblock zu schreiben.

1. Melodie erweitern

int melodie[] = {196,196,220,196,262,247,196,196,220,196,294,262,196,196,392,330,262,247,220,349,349,330,262,294,262};
int notenWert[] = {8,8,4,4,4,2,8,8,4,4,4,2,8,8,4,4,4,4,8,8,4,4,4,4,2};
void setup() {}
void loop() {
  for (int i = 0; i < 25; i++) {
    int dauer = 1000 / notenWert[i];
    tone(11, melodie[i], dauer);
    delay(dauer * 1.3);
    noTone(11);
  }
  delay(1000);
}

Beide Arrays enthalten die 25 Werte aus dem Material. Der Index läuft von 0 bis 24; für jeden Eintrag werden Frequenz und Notenwert gemeinsam verwendet.

2. Tafeldienst auslosen

const char* namen[] = {"Martin", "Volker", "Frank", "Kolja", "Alexander", "Mario", "Peter", "Rainer"};
void setup() {
  Serial.begin(9600);
  randomSeed(analogRead(A0));
  int index = random(8);
  Serial.println(namen[index]);
}
void loop() {}

random(8) liefert einen Index von 0 bis 7. Das Beispiel lost einmal beim Start aus. Der Seed über einen freien Analogeingang ist für eine einfache Unterrichtsdemonstration gedacht, nicht für eine garantierte zufällige oder faire Zuteilung über längere Zeit.

3. Literaturautomat

const char* x[] = {"Nacht", "Regen", "Nebel"};
const char* y[] = {"Wind", "Sturm", "Schnee"};
void setup() {
  Serial.begin(9600);

  Serial.print("Wer reitet so spaet durch " );
  Serial.print(x[random(3)]);
  Serial.print(" und " );
  Serial.print(y[random(3)]);
  Serial.println("?");

void loop() {}

Eine mögliche Ausgabe ist: Wer reitet so spaet durch Nebel und Wind? Jeder Begriff wird über einen gültigen Index ausgewählt.

4. Hausarbeiten verteilen

const char* namen[] = {"Alex", "Robin", "Sam"};
const char* dienste[] = {"abwaschen", "aufräumen", "Staub wischen"};
int reihenfolge[] = {0, 1, 2};
void setup() {
  Serial.begin(9600);
  randomSeed(analogRead(A0));
  for (int i = 2; i > 0; i--) {
    int j = random(i + 1);
    int temp = reihenfolge[i];
    reihenfolge[i] = reihenfolge[j];
    reihenfolge[j] = temp;
  }
  for (int i = 0; i < 3; i++) {
    Serial.print(namen[reihenfolge[i]]);
    Serial.print(" darf " );
    Serial.println(dienste[i]);
  }
}
void loop() {}

Die Indexliste wird mit dem Fisher-Yates-Verfahren gemischt. Jeder ursprüngliche Index bleibt genau einmal enthalten; niemand bekommt im Beispiel zwei Dienste.

Interrupt: Auf Ereignisse sofort reagieren

Ablaufspur: Vom Tastendruck zur Reaktion

Ereignisaktiver Bereichzustandnächster Schritt
Normalbetriebloop()0Hauptprogramm läuft weiter
Signal wechselt von HIGH zu LOWISR1ISR wird beendet
ISR ist beendetloop()1Aktion ausführen
Aktion ist abgeschlossenloop()0Hauptprogramm fortsetzen

Ordne den Interrupt-Ablauf

  1. Am Taster ändert sich das Signal am Pin.
  2. Der Interrupt erkennt die Signaländerung.
  3. Das Hauptprogramm wird kurz unterbrochen.
  4. Die Interrupt Service Routine wird ausgeführt.
  5. Nach der ISR läuft das Hauptprogramm an der unterbrochenen Stelle weiter.

Was gehört in eine ISR, was nicht?

KategorieBegriff
In einer ISR sinnvollNur kurz einen Zustand merken
In einer ISR sinnvollEine Variable auf 1 setzen
In einer ISR vermeidendelay() benutzen
In einer ISR vermeidenSeriellen Monitor umfangreich benutzen
In einer ISR vermeidenLC-Display ansteuern
In einer ISR vermeidenAufwändige Berechnungen machen

Warum volatile?

Weil sich ihr Wert außerhalb des normalen Programmflusses ändern kann. Variablen im Interrupt müssen als volatile deklariert werden, damit der Compiler sie nicht falsch optimiert.

Wahr oder falsch?

Falsch. Während einer ISR sind delay(), serieller Monitor und aufwändige Berechnungen gute Ideen, weil der Interrupt dann besonders viel erledigt.

Falsch. Eine ISR muss kurz gehalten werden. delay(), serieller Monitor, LC-Display und aufwändige Berechnungen sollen dort nicht benutzt werden.

Transfer: Interrupt sinnvoll beschreiben

Eine mögliche Antwort

Beim Polling wird ein Eingang nur an bestimmten Stellen des Hauptprogramms gelesen, sodass ein kurzes Signal zwischen zwei Abfragen übersehen werden kann. Ein Interrupt kann auf eine passende Signalflanke reagieren und kurz die ISR ausführen. Die ISR setzt nur eine als volatile deklarierte Ereignisvariable. Die eigentliche Aktion folgt in loop(), damit die ISR kurz bleibt. Wenn das Ereignis übernommen und gelöscht wird, schütze ich diesen gemeinsamen Zugriff vor einer gleichzeitig eintreffenden ISR; volatile allein verhindert keinen solchen Konflikt. Ein einzelnes Flag speichert nur, dass mindestens ein Ereignis aufgetreten ist, und zählt keine beliebig vielen Ereignisse.

Aufgabe: Lauflicht mit Interrupt

const byte leds[] = {4,5,6,7,8,9,10,11};
const byte rot = 12;
volatile byte ereignis = 0;
void tasteISR() { ereignis = 1; }
void setup() {
  for (byte i = 0; i < 8; i++) pinMode(leds[i], OUTPUT);
  pinMode(rot, OUTPUT);
  pinMode(2, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(2), tasteISR, FALLING);
}
void loop() {
  for (byte i = 0; i < 8; i++) {
    digitalWrite(leds[i], HIGH); delay(100);
    digitalWrite(leds[i], LOW);
    noInterrupts();
    byte merken = ereignis; ereignis = 0;
    interrupts();
    if (merken) digitalWrite(rot, HIGH);
  }
}

Ein Tasterdruck nach GND löst eine FALLING-Flanke aus. Die ISR merkt das Ereignis; die rote LED wird spätestens nach dem nächsten 100-ms-Lauflichtschritt eingeschaltet. Jede LED benötigt einen passenden eigenen Vorwiderstand.

Aufgabe: Ereignis merken

volatile byte zustand = 0;
void tasteISR() { zustand = 1; }
void machIrgendwas() { digitalWrite(13, HIGH); }
void setup() {
  pinMode(13, OUTPUT); pinMode(2, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(2), tasteISR, FALLING);
}
void loop() {
  noInterrupts();
  byte ausloesen = zustand; zustand = 0;
  interrupts();
  if (ausloesen) machIrgendwas();
}

Die Übernahme und das Löschen des Flags erfolgen gemeinsam bei kurz gesperrten Interrupts. Ein später eintreffendes Ereignis bleibt damit für den nächsten Durchlauf erhalten.

Mini-Check: Troubleshooting

Was prüfst du zuerst, wenn ein Sketch gar nicht kompiliert?

Die Fehlermeldung verstehen und auf setup(), loop() oder fehlende Bibliotheken achten.

Das ist der erste Schritt: Compilerfehler lesen und die eigentliche Ursache finden.

Welcher Fehler führt oft dazu, dass ein Block gar nicht ausgeführt wird?

Ein zusätzliches Semikolon direkt nach if(), while() oder for().

Genau dieser Fehler ist besonders tückisch: Dann wird der Block in den geschweiften Klammern übersprungen.

Fehlermeldung einordnen

Dann liegt das Problem häufig nicht mehr im Quelltext, sondern bei den Einstellungen oder der Verbindung: falsches Board, falscher COM-Port, Treiberproblem oder ein verstellter Programmer.

Dein Fehlersuchplan

Eine mögliche Antwort

Zuerst kompiliere ich und korrigiere Syntaxfehler anhand der ersten Fehlermeldung. Danach prüfe ich den Upload mit Board-Typ, Port und USB-Verbindung. Bei erfolgreichem Upload prüfe ich Versorgung, gemeinsamen GND, Polung und Stromweg. Ich vergleiche die verwendeten Pins mit dem Sketch. Anschließend lasse ich einen einfachen Teiltest laufen, zum Beispiel nur eine LED. Mit serieller Ausgabe untersuche ich Messwerte und Entscheidungen. Nach jeder einzelnen Änderung wiederhole ich denselben Test und notiere, ob die Beobachtung nun zur Vorhersage passt.
